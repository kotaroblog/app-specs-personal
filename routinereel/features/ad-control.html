広告制御機能

Unity LevelPlay（バナー + インタースティシャル）／配信は App Store 版のみ

v1.0機能ID: RR-FEAT-AD

現状: 広告は一切配信されていない。

AdMob アカウントが「無効なトラフィック」により恒久的に無効化（2026-07-30）され、再審査請求も却下された。 その後 AppLovin MAX へ移行したが publisher アカウントの承認が下りなかったため断念し、 2026-08-20 に Unity LevelPlay へ再移行した。

RoutineReel は App Key と広告ユニットIDが未設定（空）のため、広告のリクエスト自体が発生しない。

概要

無料ユーザー向けにバナー広告と、書き出し完了後のインタースティシャル広告を配信する。 プレミアム会員には表示しない。広告ネットワークは Unity LevelPlay（Unity Ads をメディエーション経由の bidder として利用）。 リワード広告は実装済みだが、現バージョンでは表示導線を持たない。

関連画面

  • ホーム（バナー。中央＋ボタンとの誤タップを防ぐため直下に 24pt の非インタラクティブ離隔スペーサーを置く）
  • プレビュー / 書き出し（書き出し完了後のインタースティシャル）
  • Paywall（プレミアム訴求）

広告を出してよい環境の判定（再発防止の中枢）

AdMob 停止の原因は、開発中・TestFlight 検証中に本番の広告IDでインプレッションが発生していたことだった。 ネットワークを変えても同じ規約（自己クリック・他者への視聴依頼の禁止）が適用されるため、同じ事故を構造的に防ぐ。

AdEnvironment.isAdDeliveryAvailable = !appKey.isEmpty && isProduction （App Key が設定済み かつ App Store 配信版）

環境広告のロード・表示
DEBUG ビルド / シミュレーター / TestFlight一切リクエストしない
App Store 配信版（App Key 設定済み）配信する
  • 判定は App Store レシートの種別（sandboxReceipt かどうか）で行う。ビルド構成の設定ミスでは破れない
  • LevelPlay には AdMob のような「テスト広告ID」の概念がないため、開発中は広告を出さない方式を採る
  • SDK 初期化自体も配信可能な環境でのみ実行する
  • SDK の初期化完了前は広告をロードしない（LevelPlay は初期化前の loadAd() が失敗するため）。初期化完了は @Observable な AdReadiness で SwiftUI に伝播する
  • ATT ダイアログも同じゲートの内側。広告を配信しない間はトラッキング許可を求めない

インタースティシャルの表示条件（移行後も維持）

条件内容理由
タイミング書き出し「完了」でホームに戻る瞬間シェア画面（ExportCompleteView）表示前に出すと、TikTok / Reels 投稿ボタン（バイラルループの発火点）を遅らせてしまうため
頻度1日1回まで制作ツールとしての作業導線を阻害しない

プレミアム表示しない課金特典

※ 広告が配信できない期間は「初回書き出し済み」フラグも消費しない（App Key 設定後の最初の書き出しをクリーンに保つため）。

広告が配信されない間の挙動

対象挙動

ATT ダイアログ表示しない

ビジネスルール

  • 広告のロード・表示は App Store 配信版のみ。DEBUG・シミュレーター・TestFlight では一切リクエストしない
  • App Key または広告ユニットIDが未設定の間は広告に関わる処理を一切実行しない（安全側の既定）。RoutineReel は現在この状態
  • SDK の初期化完了前は広告をロードしない
  • プレミアム会員にはバナー・インタースティシャルを表示しない
  • 全画面広告は書き出しの完了後にのみ出し、投稿導線（シェア）を遅延させない
  • バナーはタップ導線に隣接させない（中央＋ボタンとの離隔 24pt を確保する）
  • 広告のロード・表示に失敗しても UX を止めない（バナーは非表示、全画面はサイレントでスキップ）

技術仕様

項目内容
SDKLevelPlay 9.6.0（SPM: LevelPlay-Swift-Package / プロダクト名 UnityMediationSDK）
アダプタLevelPlayUnityAdsAdapter 5.10.0（プロダクト名 UnityAdsAdapter）。SDK とは別のバージョン体系のため 9.x を指定すると依存解決に失敗する
初期化LPMInitRequestBuilder(appKey:) → LevelPlay.initWith(_:completion:)
表示LevelPlay の showAd は viewController を必須で要求するため、最前面の ViewController を解決して渡す
状態管理日次カウント・初回書き出し済みフラグは UserDefaults に保持（interstitialDailyCount / interstitialDailyDate / interstitialFirstExportDone）
再試行ロード失敗時は指数バックオフ（上限64秒）。再試行タスクは1本に束ねて多重実行を防ぐ
ビルド設定OTHER_LDFLAGS に -ObjC が必須

※ App Key・広告ユニットIDの実値は本仕様書には記載しない（コード側で管理する）。

エラー処理

発生条件対応
バナーのロード失敗枠ごと非表示（空白を残さない）
インタースティシャルのロード失敗サイレントでスキップ。指数バックオフで再ロード
SDK 初期化の失敗広告以外の機能は動き続ける。原因調査のため Logger に記録する
App Key 未設定広告を一切ロードしない（安全側の既定）

実装メモ

  • LevelPlay 9.6.0 + UnityAds アダプタ 5.10.0 を SPM で導入。OTHER_LDFLAGS に -ObjC を追加
  • AdEnvironment.isAdDeliveryAvailable で全広告処理を分岐
  • App Store レシートの種別で本番配信版を判定
  • 全画面広告のロードは SDK 初期化完了後にのみ行う（初期化完了時にもロードを呼び直して取りこぼしを防ぐ）
  • 書き出し完了後の表示条件（1日1回・初回スキップ・プレミアム除外）を維持
  • バナー直下に 24pt の非インタラクティブ離隔スペーサーを配置（v1.1.0 で追加）
  • Unity ダッシュボード（LevelPlay）で App Key と広告ユニットIDを発行して設定する（未設定のため現在は広告なし）
  • リワードの表示導線を作るかは、配信開始後の収益を見てから判断する
