計測イベント（AnalyticsManager）

計測は AnalyticsManager（BlockPuzzle/Services/AnalyticsManager.swift）に一元化し、登録された送信先すべてに送る。 送信先は常に Logger（カテゴリ Analytics）で、GoogleService-Info.plist がある場合だけ Firebase Analytics も加わる（AnalyticsFirebaseBridge）。 個人情報は送らず、スコアや回数などの匿名の数値だけを送る。イベント名は英小文字とアンダースコア（Firebase の制約）。

イベントパラメータ送るとき
app_openなしアプリ起動
game_startなしゲーム開始
game_overscore / max_combo / duration_secondsゲームオーバー
score_resultscore / is_new_high_scoreゲームオーバー
tutorial_start / tutorial_completeなしチュートリアルの開始・完了
tutorial_skipstep_reachedチュートリアルを飛ばした
theme_selectedtheme / source（onboarding / settings）テーマを選んだ
undo_usedused_adアンドゥを使った
ad_interstitial_shown / ad_rewarded_shownなし全画面広告・リワード広告の表示
iap_paywall_view / iap_purchase_startなし購入画面の表示・購入の開始
iap_purchase_successproduct_id購入の完了
bonus_start ★ v1.5.3time_limit_seconds（制限時間の秒数）ボーナスタイムに入った（入る演出が始まったとき）
bonus_end ★ v1.5.3perfect_count（全消しした枚数）／boards（置き終えた盤面の数）／score（ボーナスタイムで得た点）ボーナスタイムが時間切れで終わった（まとめの表示に移ったとき）

ボーナスタイムの計測（v1.5.3〜）

  • 送信は GameView.handleBonusPhaseChange で、ボーナスタイムの段階（BonusPhase）が「入る演出」になったら bonus_start、「終了」になったら bonus_end を送る。VoiceOver の読み上げも同じ場所で出す
  • 目的は、ボーナスタイムの試作の良し悪し（何枚全消しできているか・どれだけ点が入っているか）を数字で見ること
  • 撮影モード（ストア用スクリーンショットの自動撮影）では送らない（AppEnvironment.isUISnapshot。ゲーム開始の計測と同じ扱い）
  • 既知の穴: ボーナスタイムの途中で画面を離れると bonus_end が送られず、bonus_start と件数が揃わない（ISSUES.md BP-018 に記載・未対応）。件数を比べるときは差があることを前提にする
