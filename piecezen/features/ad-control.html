広告制御機能

Unity LevelPlay による広告配信と、配信環境を App Store 配信版のみに限定する安全機構

v3.0機能ID: PZ-FEAT-AD

2026-08-20 広告基盤を AppLovin MAX から Unity LevelPlay へ移行

AdMob アカウントが「無効なトラフィック」により恒久的に無効化（2026-07-30）され、再審査請求も却下された。 その後 AppLovin MAX へ移行したが、publisher アカウントの承認が下りなかったため断念し、Unity LevelPlay へ再移行した。

再発防止の中枢: AdEnvironment.isAdDeliveryAvailable = !appKey.isEmpty && isProduction （App Key が設定済み かつ App Store 配信版）。 停止の原因が開発・TestFlight 検証中の自己インプレッションだったため、広告のロード・表示は App Store 配信版のみに限定し、 DEBUG・シミュレーター・TestFlight では一切リクエストしない。判定は App Store レシートの種別で行い、ビルド構成の設定ミスでは破れない。 ATT ダイアログも同じゲートの内側にあり、広告を配信しない間は表示しない。

App Key と広告ユニットID（バナー / インタースティシャル / リワード）は設定済みだが、 ironSource Ads アカウントが承認待ちのため現時点ではまだ広告は配信されていない。 その間、バナーは枠ごと非表示にし、リワードで与えていた報酬は広告なしで即付与する（1ゲームあたりの上限は維持）。

広告基盤の変遷

時期基盤結果
〜2026-07-30Google AdMobアカウントが恒久的に無効化。AdSense / AdMob は今後一切利用できない
2026-07-30 〜 2026-08-20AppLovin MAX移行完了したが publisher アカウントの承認が下りず断念
2026-08-20 〜Unity LevelPlay移行完了。ironSource Ads アカウント承認待ち

Unity Ads は 2026-04-01 以降、直接統合だと配信性能が落ちるため、LevelPlay（メディエーション）経由の bidder として利用する。直接統合は使わない。

技術構成

項目内容
SDKLevelPlay 9.6.0（SPM: LevelPlay-Swift-Package / プロダクト名 UnityMediationSDK）
アダプタLevelPlayUnityAdsAdapter 5.10.0（プロダクト名 UnityAdsAdapter）。SDK とは別のバージョン体系のため 9.x を指定すると依存解決に失敗する
対応フォーマットバナー（アダプティブ）・インタースティシャル・リワードの3種
初期化LPMInitRequestBuilder(appKey:) → LevelPlay.initWith(_:completion:)。完了は @Observable な AdReadiness で SwiftUI に伝播する
ロード開始条件広告配信が有効 かつ SDK 初期化完了後。LevelPlay は初期化前の loadAd() が失敗するため
クラスバナー LPMBannerAdView（LPMAdSize.createAdaptive() / 破棄時に destroy() 必須）、全画面 LPMInterstitialAd / LPMRewardedAd
再試行ロード失敗時は指数バックオフ（上限64秒）。再試行タスクは1本に束ねて多重実行を防ぐ
ビルド設定OTHER_LDFLAGS に -ObjC が必須
呼び出し側 APIloadInterstitial / showInterstitial / loadRewarded / showRewarded / isRewardedAdReady / shouldShowInterstitial は AdMob 時代から変えていない

広告環境の判定（AdEnvironment）

判定内容
isAdDeliveryAvailable !appKey.isEmpty && isProduction。広告に関わる全挙動の単一スイッチとして機能する。App Key 未設定の間は自動的に無効
isProduction 広告を配信してよい環境か。App Store 配信版のみ true。DEBUG ビルド・シミュレーター・TestFlight はすべて false。判定は App Store レシートが sandboxReceipt かどうかで行う
isInitialized LevelPlay SDK の初期化が完了したか。広告のロードはこれが true になってから行う

本番広告を開発者自身が表示・タップすることがアカウント無効化の直接原因になり得るため、広告は App Store 配信版でのみ配信する。 LevelPlay には AdMob のような「テスト広告ID」の概念がないため、開発中はテスト広告を出すのではなく広告そのものを出さない方式を採る。 レイアウト確認は広告枠のプレースホルダで行う。

具体的な広告ユニットIDおよびパブリッシャー識別子は本仕様書には記載しない（コード側で管理する）。

広告構成と停止中の挙動

種類表示タイミング（変更なし）広告が配信されない間の挙動
バナー ゲーム画面下部に常時（未購入時のみ）
LPMBannerAdView（アダプティブ）		 枠ごと非表示。高さ0ではなくビュー自体を配置しないため、盤面下に余白が残らない
インタースティシャル 3ゲームに1回、最低90秒間隔（未購入時のみ）
LPMInterstitialAd		 呼び出さない。広告リクエストも発生しない
リワード（もう1手 / アンドゥ追加） ゲーム終了時の救済（復活）・アンドゥ2回目以降
LPMRewardedAd		 広告を挟まず報酬を即付与。1ゲームあたりの上限回数は維持

付随して停止するもの

対象停止中の挙動理由
トラッキング許可（ATT）ダイアログ 表示しない トラッキング許可は広告目的でしか求めていない。広告がない状態で許可を求めると「求める理由がない」状態になり審査リスクにもなる
広告SDKの初期化 行わない 広告リクエストを一切発生させないため。起動コストと不要な通信も避ける

アプリ起動時の計測ログは、広告の有無とは独立して従来どおり実行する。

UI 文言への影響

箇所広告配信中の表記配信停止中の表記（現状）
ゲーム終了画面のリワードボタン広告を見てもう1手無料でもう1手（アイコンも gift.fill に変化）
アンドゥボタン（無料回数を使い切った後）戻す (広告)戻す

いずれも isAdDeliveryAvailable による分岐で、広告を再開すれば元の表記に戻る設計にしている。

ビジネスルール

  • 広告配信が停止している間は、広告枠を一切表示せず、広告リクエストも発生させない
  • リワードで与えていた報酬は広告なしで即付与する。ただし1ゲームあたりの上限回数は維持する
  • プレミアム購入者には広告を表示しない。将来別の広告ネットワークを導入した場合も表示しない（購入時の保証）
  • プレミアム購入者にはアンドゥの広告視聴を一切要求しない（アンドゥ無制限が特典のため）
  • 広告をロード・表示するのは App Store 配信版のみ。それ以外の環境では広告を一切リクエストしない
  • SDK の初期化完了前は広告をロードしない（LevelPlay は初期化前の loadAd() が失敗するため）
  • 撮影モード（スクリーンショット自動撮影）では広告・ATT・計測をすべて抑止する
