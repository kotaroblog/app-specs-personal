効果音システム

打撃音・足音・環境音の鳴らし分け、素材差し替え、ピッチ・音量の揃え方、中断からの復帰

機能ID: CF-F05

概要

ブロックを壊す・置く、歩く、ジャンプする、クラフトが完了する、といった操作に音を返す。あわせて雨・夜・風・洞窟のループ環境音を鳴らす。

音源は 音声ファイル（差し替え素材）とコード生成の合成音の二段構えで、素材が無いものは合成音で鳴る。素材の音色・音量・ピッチは、素材ごとの録音差がそのままゲーム内の差にならないよう、読み込み時と再生時に揃える。

関連画面

  • ゲームメイン（CF-S01） — 採掘・設置・移動・クラフトなど、効果音の発生源はすべてこの画面にある

1. 音源の決定（合成音と差し替え素材の二段構え）

従来はすべてコードで波形を生成していた（サイン波・ホワイトノイズ・1極ローパス3段）。現在は音声ファイルが置かれていればそれを優先し、無ければ従来の合成音へ倒れる。

なぜ二段構えにするか：素材が揃ったものから順に差し替えられる。全部そろうまで差し替えを待つ必要がなく、途中の状態でも音が欠けない。

2. 素材別の音色（ImpactMaterial）

打撃音（壊す・置く・足音）を6カテゴリで鳴らし分ける。

カテゴリ対象ブロック明るさ（合成音の tone）
ガラスガラス0.24（最も明るい）
石石・レンガ・鉱石・石材加工物・かまど0.18
木原木・板材・作業台・チェスト・ベッド・松明0.14
砂砂0.11
土・草土・草・耕地・キノコ0.10
葉・雪葉・雪・花・草・小麦0.07（最もこもる）

tone は合成音の3段ローパスの係数で、小さいほどこもる。差し替え素材を使う場合は素材そのものの音色が使われる。

この順序は「硬い素材ほど明るい」という直感に沿わせたもので、硬い順に単調でなければならない（逆転すると葉がガラスより明るい、といった破綻になる）。単調性はテストで固定している。

音量は素材で変えない。柔らかい素材ほど音を小さくすると、「音色が違う」ではなく単に「聞こえない」になる。素材の違いは音色（明るさ）だけで表現する。
ブロック → カテゴリの対応表には default を置かない。全ケースを列挙しておくと、ブロックを追加したときにコンパイルエラーで気づける。default があると、対応を書き忘れたブロックが黙って石の音で鳴り続ける。

足音の素材

現在入っている足音の素材は 土（汎用）・草・石・木・砂・水中 の6種。素材が無いカテゴリは合成音で鳴る。

3. 再生ピッチの微ランダム化

同じ音が続いたときの単調さを消すため、鳴らすたびに再生レートをわずかにずらす。

音レート範囲
足音±6%
壊す・置く±5%
ジャンプ・着水・水中移動±3%
クラフト完了・目標達成・精錬・就寝1.0 固定
モブの鳴き声1.0 固定
音程が意味を持つ音は固定する。クラフト完了や目標達成のような「知らせる音」は音程そのものがサインなので、揺らすと音痴な楽器になる。
ピッチ変更器はプレイヤ1本につき専用に持つ（効果音プレイヤ4本それぞれに挿入）。共有すると、鳴っている途中の音のピッチまで次の再生で書き換わる。

幅の決め方：鳴る回数の多さで決める。連打されるものほど広く振らないと単調さが残り、逆に広げすぎると素材ごとの音色の差が埋もれる。

4. 音量の正規化

差し替え素材は録音レベルがばらつくため、読み込み時に用途ごとの基準 RMS へ揃える。

対象基準 RMS
壊す0.0340
置く0.0262
足音・水中移動0.0087
モブの鳴き声0.045
ジャンプ0.0197
完了・達成を知らせる音0.0443
ループ環境音揃えない（素材ごとの厚みに意味があるため手で合わせる）
ピークが 1.0 を超える手前で頭打ちにする。超えるとクリップして歪む。「音量を揃えたら割れた」は、原因が正規化処理側にあるため後から気づきにくく直しにくい壊れ方になる。
モブの音量は種類で変えない。遠近は距離減衰（max(0.15, 1 − 距離 / 16)・16m 超は鳴らさない）が表現している。そこへ素材ごとの録音レベルの違いが乗ると「牛だけいつもうるさい」になる。

5. 環境音（ループ）

種類ON 条件
雨天候が雨のとき
夜太陽高度 sunFactor < 0.15。1日10分のうち約5.5分（55%）が夜にあたる
昼の風夜と対で切り替える（昼 ON / 夜 OFF）
洞窟プレイヤーの y < 24
ON/OFF の状態は音の管理側が保持する。中断から復帰したとき、呼び出し元（描画ループ）から見ると状態は変わっていないので鳴らし直しの指示が来ない。音の管理側が「いま何が ON だったか」を覚えていないと、効果音は戻るのに環境音だけ戻らない状態になる。
ループ素材は先頭と末尾がつながるものを使う。末尾を先頭へクロスフェードして継ぎ目を消す。

6. 中断からの復帰

オーディオエンジンは一度止まると自力では戻らない。再生系はすべて「エンジンが動いていること」を前提に始まるので、止まったあとは例外も出さずに無音のままになり、音が出ていないことに気づけない。電話・アラーム・他アプリの再生・イヤホンの抜き差しで実際に起きる。

きっかけ処理

出力先の変更（イヤホンの抜き差しなど）
メディアサービスのリセット
フォアグラウンド復帰同上（同じ復旧処理を通す）
フォアグラウンド復帰の通知は View 層で受けて、音の管理側を呼ぶ。音の管理は画面を知らない層なので、そこへ UIApplication（UIKit）を持ち込まない。依存は View → Service の一方向を保つ。

8. 音の検証方法

耳が最も敏感な 2〜4kHz のエネルギーを、同じ音量に揃えてから比較する。揃えずに比べると「良くなった」のか「音量が上がっただけ」なのかを区別できない。
音量（RMS）は全チャンネルで測る。左右で波形の違うステレオ素材をモノラル化してから測ると打ち消しが起きて小さく出る。実際にこれで、環境音を +2.2dB 大きいまま入れてしまったことがある。
モノラル化してよいのは周波数の偏りを見るときだけ。

測定スクリプトはアプリのリポジトリ側 tools/ に置いている（measure_impact_sound.py / measure_ambient_sound.py / measure_sound_assets.py）。

ビジネスルール

  • 素材が無い音は必ず合成音で鳴る。音が欠ける状態を作らない
  • 素材の違いは音色で表現する。音量では表現しない
  • 遠近は距離減衰のみで表現する。素材ごとの録音レベル差を遠近の表現に混ぜない
  • 知らせる音（完了・達成）はピッチを固定する
  • 音の良し悪しは、音量を揃えた状態で 2〜4kHz のエネルギーを比べて判定する

エラー処理

発生条件対応
差し替え素材が見つからない探索順に従って番号なし → 汎用 → 合成音へ倒す。エラー表示はしない
素材の読み込み・形式変換に失敗したその音は合成音で鳴らす。ゲーム進行は止めない
正規化でピークが 1.0 を超える1.0 手前で頭打ちにしてクリップを防ぐ
割り込み・出力先変更・メディアサービスリセットでエンジンが停止した通知を受けて再起動し、ループ環境音を元の ON/OFF 状態へ戻す
フォアグラウンド復帰時にエンジンが停止していた同上（View 層が通知を受けて音の管理側へ委譲する）

実装メモ

  • ブロック → 素材カテゴリの対応に default を書かない（追加漏れをコンパイルエラーで検出するため）
  • ピッチ変更器はプレイヤごとに専用に持つ（共有すると再生中の音のピッチが書き換わる）
  • ループ環境音の ON/OFF 状態は音の管理側で保持する（復帰時に呼び出し元からは再指示が来ない）
  • 音の管理側に UIKit を import しない。ライフサイクル通知は View 層で受けて委譲する
  • RMS 測定は全チャンネルで行う。モノラル化は周波数分析のときだけ
  • 素材の入手元・ライセンスはアプリのリポジトリ側で管理する（本仕様書には記載しない）
