メモ編集（MemoEditorView）

1ページ分を自分の言葉で残す画面。写真ありでもなしでも同じ画面を使い、アクションには必ず期限を付ける。

実装済 画面ID: BS-S05

目的・役割

アプリの中核の入力画面。要点（最大3）・アクション（最大3・期限つき）・フレーズ（任意）を本人が書く。 写真は任意で、撮った場合も OCR の結果は「読み取ったテキスト」として参考に出すだけ（要点やアクションへ自動では入れない）。

入口（2通り）

入口経路画面の違い
書くだけ本の詳細 → メモを追加 →「書くだけ」／オンボの最初の1冊の直後写真・参考欄・「撮り直す」なし
撮影して書く本の詳細 → メモを追加 →「撮影して書く」→ カメラ（CameraView）→ 撮影プレビュー（PhotoPreviewView）→「この写真で書く」写真帯・参考欄（読めた場合）・「撮り直す」あり

カメラと撮影プレビュー

  • カメラは UIImagePickerController（標準コントロール）。左上の × と標準の「キャンセル」のどちらでも閉じる。カメラの無い端末ではフォトライブラリ選択になる
  • 撮影プレビューは写真を全画面表示し、「撮り直す」／「この写真で書く」の2択。ブレ・ピンボケの確認用
  • 「この写真で書く」を押すとOCR の完了を待たずにメモ編集を開き、OCR はバックグラウンドで走る。読めた時点で参考欄が現れる

状態

状態表示内容
初期表示空の要点1行・空のアクション1行（期限は3日後）を用意し、0.35 秒後に要点1行目へフォーカス
保存できない要点・アクションのどちらにも文字が無い。「保存する」をグレーで無効化し「要点かアクションを1つ書くと保存できます」
保存できる要点かアクションに1文字以上。フレーズだけでは保存できない
保存中「保存する」を無効化（二重保存防止）
保存失敗（空と判定）暖色で「要点かアクションを1つ以上書いてください」
書きかけで閉じる確認「書きかけを破棄しますか？」（破棄する／書き続ける）。要点・アクション・フレーズのどれかに文字があるとき

遷移

操作遷移先

期限チップ →「日付を指定」期限を選ぶシート

保存処理

  1. 通知許可が未決定のときだけここで許可を求める（期限つきのアクションを作る直前が最も文脈のある場面のため）
  2. 写真を JPEG（品質 0.7）に変換
  3. MemoEditorViewModel.save: 要点とアクションを正規化（前後の空白を削る・空行を落とす・同じ文言の重複を落とす・3件で打ち切る）。フレーズは空なら nil。Memo と Action を作って context.save()
  4. ActionService.scheduleAll(for: memo) で配下の全アクションの期限通知を登録（BS-F01）
  5. カバーを閉じる

使用するデータモデル

@Observable @MainActor final class MemoEditorViewModel {
    static let maxSummaryCount = 3
    static let maxActionCount = 3
    var summary: [SummaryDraft]    // id + text
    var actions: [ActionDraft]     // id + text + dueDate（非 Optional）
    var phrase: String
    var canSave: Bool              // 要点かアクションに1つでも文字があれば true
}
// 保存先: Memo(book:photoData:ocrText:) / Action(memo:text:dueDate:)

実装メモ

  • 入力本文は 15pt（MemoEditorFont.body）。小さいと書く気が失せるため
  • 行は Identifiable な Draft で持ち、id で削除する（index バインディングで削除するとクラッシュしうる経路を除去済み）
  • OCR は Vision の VNRecognizeTextRequest（日本語・英語・accurate）。OCRService.validate（30文字以上・平均信頼度 0.3 以上）は定義はあるが呼ばれていない。読めたものはそのまま参考欄に出す
  • OCR 失敗は画面に出さずログのみ（category OCR・info）
  • 保存後のメモを開き直して編集する画面は無い
  • スクリーンショット撮影モード（-uiTestSnapshot）では初期フォーカスを当てない
