データモデル

SwiftData @Model 3種（Book / Memo / Action）の構造・リレーション・導出プロパティ

ER 図

erDiagram Book ||--o{ Memo : "memos (cascade)" Memo ||--o{ Action : "actions (cascade)" Book { UUID id String title String author String isbn "optional" Data coverImageData "externalStorage / optional" String statusRawValue "reading / done" Date createdAt } Memo { UUID id Data photoData "externalStorage / optional" String ocrText StringArray summary "最大3" String phrase "optional" Date createdAt } Action { UUID id String text Bool isDone Date dueDate "optional / 作成経路では必ず入る" Date completedAt "optional" String calendarEventID "optional" Date reminderDate "optional" Date createdAt }

コンテナ

  • BookSparkApp で .modelContainer(for: [Book.self, Memo.self, Action.self])。スキーマのバージョン管理（VersionedSchema）は持たない
  • スクリーンショット撮影モード（起動引数 -uiTestSnapshot）では inMemory: true にし、SnapshotSeeder がサンプルの本4冊を投入する。本番データには触れない
  • SwiftData 以外の永続値は UserDefaults の hasCompletedOnboarding（@AppStorage）のみ。Pro 状態は保存せず、起動時に StoreKit から判定し直す（BS-F02）

Book

enum BookStatus: String, Codable {
    case reading
    case done
}

@Model
class Book {
    var id: UUID = UUID()
    var title: String = ""
    var author: String = ""
    var isbn: String?

    // 表紙画像はローカルに保存（Google Books API の URL 変更リスク回避）
    @Attribute(.externalStorage)
    var coverImageData: Data?

    var statusRawValue: String = BookStatus.reading.rawValue
    var createdAt: Date = Date()

    @Relationship(deleteRule: .cascade, inverse: \Memo.book)
    var memos: [Memo] = []
}
導出プロパティ定義使う場所
statusstatusRawValue を BookStatus に変換。不正値は .reading全般
allActions全メモのアクションを平らにしたもの件数・並べ替え・削除時の通知解除
openActionCountstate == .open の件数本棚ヘッダー「期限内 N」
overdueActionCountstate == .overdue の件数本棚ヘッダー・本カード「流れた N」
achievementRate完了 ÷ 全アクション（0.0〜1.0）。アクションが無ければ 0本カードの進捗バーのみ。週次レビューの「達成率」とは定義が違う（用語集）
lastMemoDateメモの createdAt の最大値。メモが無ければ本の createdAt本棚の並び順
sortedActions下記の並び規則で並べた全アクション本の詳細のアクション一覧

sortedActions の並び規則

  1. 流れた（.overdue）— 期限の昇順（古い期限ほど上）
  2. 期限内（.open）— 期限の昇順（近い期限ほど上）
  3. 完了（.done）— 完了時刻の降順（最近終えたものほど上）

期限が nil のものは distantFuture、完了時刻が nil のものは distantPast として扱う。 同着は id.uuidString の昇順で安定させる（描画のたびに順番が入れ替わらないように）。基準時刻を渡せる sortedActions(at:) がテスト用に公開されている。

Memo

@Model
class Memo {
    var id: UUID = UUID()
    var book: Book?

    // 撮影画像（externalStorage でファイルシステムに自動保存）
    @Attribute(.externalStorage)
    var photoData: Data?

    // Vision OCR の結果テキスト（参考表示用・写真なしメモでは空）
    var ocrText: String = ""

    // 要点（最大3行）
    var summary: [String] = []

    // 印象的なフレーズ
    var phrase: String?

    var createdAt: Date = Date()

    @Relationship(deleteRule: .cascade, inverse: \Action.memo)
    var actions: [Action] = []
}
  • 写真は jpegData(compressionQuality: 0.7) で保存する。写真なしメモ（「書くだけ」）は photoData == nil・ocrText == ""
  • summary と actions の上限3件は保存時の正規化で担保する（モデル側に制約は無い）。空行・前後空白・重複は落とす
  • 保存後のメモを編集する画面は無い。変更できるのはアクション（文言・期限・完了・削除）と、メモごとの削除のみ

Action

enum ActionState: Sendable {
    case open     // 期限内（未完了・期限前）
    case done     // 完了
    case overdue  // 流れた（未完了のまま期限を過ぎた）
}

@Model
class Action {
    var id: UUID = UUID()
    var memo: Memo?
    var text: String = ""
    var isDone: Bool = false

    // EventKit のイベントID
    var calendarEventID: String?

    var reminderDate: Date?
    var createdAt: Date = Date()

    /// 期限。新規作成時は既定で「3日後の 23:59」（ローカル時刻）
    var dueDate: Date?

    /// isDone を true にした時刻。false に戻したら nil
    var completedAt: Date?
}
導出・操作定義
isOverdue(at:)!isDone && dueDate != nil && dueDate < now。期限は「その日の 23:59:00」なので、期限日の 23:59 を過ぎた瞬間から流れた扱い
state(at:)isDone なら .done、そうでなければ isOverdue で .overdue / .open。保存された列ではなく毎回計算するので、時間が経つだけで open → overdue に変わる
setDone(_:at:)isDone と completedAt を同時に更新（true で時刻を入れ、false で nil）。View からは直接呼ばず ActionService.setDone を通す
calendarEventID / reminderDateカレンダー登録に成功したときだけ入る（イベントID と予定の日時）。reminderDate は通知には使っていない。calendarEventID があると一覧のアイコンが「登録済み」になる

状態遷移と通知の規則は BS-F01 期限つきアクション を参照。

削除と通知の関係

Book → Memo → Action は .cascade で連鎖削除されるが、SwiftData の連鎖削除は保留中のローカル通知を消さない。 そのため削除は必ず ActionService.delete / deleteMemo / deleteBook を通し、配下の全アクションの通知を解除してから context.delete する。

モデル外の値型（画面・集計用）

型置き場所役割
SummaryDraft / ActionDraftMemoEditorViewModel編集中の要点／アクション1行。Identifiable にして行削除時の index ずれクラッシュを防ぐ。ActionDraft.dueDate は非 Optional（期限必須）
WeeklyStatsWeeklyReviewViewModel今週のメモ数・達成・流れた・期限内。達成率は Int?（分母0で nil）
WeeklyBucket / ActionOutcomeWeeklyHistory8週推移の1週分と、集計に必要な値だけを抜いた入力。SwiftData を使わずにテストできる

マイグレーション方針

SwiftData の @Model は全プロパティにデフォルト値必須。新規プロパティ追加時は必ずデフォルト値を設定する。
  • v1.0 は未リリースのため既存ユーザーデータは無い。AI 前提期のモデル（AI 回数記録など）は撤去済みで、移行処理は持たない
  • Action.dueDate は Optional のまま残しているが、v1.0 のアクション作成経路（メモ編集の保存）では必ず値が入る。表示・並べ替え・集計は nil を想定した分岐を持つ
