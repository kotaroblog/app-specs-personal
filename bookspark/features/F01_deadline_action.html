期限つきアクション

アクションに期限を持たせ、過ぎたら「流れた」にする。状態変更と期限通知2通の登録／解除を ActionService に集約する。

実装済 機能ID: BS-F01

概要

記録するだけのアプリは失敗しえないので続かない、という反省から v1.0 に入れた中核機能。 アクションは作成時に必ず期限（既定3日後）を持ち、未完了のまま期限を過ぎると流れたになる。 流れたは週次レビューで数えられ、本棚のヘッダーにも常に出る。 状態を変える操作はすべて ActionService を通し、通知の登録・解除が状態とずれないようにする。

関連画面

  • メモ編集（BS-S05） — 作成と期限の初期値
  • 本の詳細（BS-S04） — 完了・文言変更・期限変更・カレンダー登録・削除
  • 本棚（BS-S02） — 期限内／流れたの件数
  • 週次レビュー（BS-S06） — 達成／流れたの集計

期限の規則（DueDateRules）

項目値
期限の実体選んだ日の 23:59:00（ローカル時刻）。endOfDay(offsetDays:from:)
既定3日後の 23:59（defaultOffsetDays = 3）。メモ編集で行を追加した時刻が基準
プリセット今日（0）／明日（1）／3日後（3）／1週間（7）＋「日付を指定」
過去日選べない（DatePicker の範囲が今日以降）。流れた期限を引き直すときは初期値を今日に寄せる
期限なし選べない。作成経路では必ず期限が入る

状態遷移

stateDiagram-v2 [*] --> open : メモ保存で作成 open --> overdue : 期限日の23時59分を過ぎる（時間経過のみ） open --> done : チェック overdue --> done : チェック overdue --> open : 期限を今日以降に付け替え done --> open : チェックを外す（期限前） done --> overdue : チェックを外す（期限後） open --> [*] : 削除 overdue --> [*] : 削除 done --> [*] : 削除

状態は保存しない。isDone と dueDate と現在時刻から毎回計算する（Action.state(at:)）。

ActionService の操作と通知の扱い

操作データの変化通知
scheduleAll(for: memo)—（メモ保存直後に呼ぶ）配下の未完了・期限ありアクションすべてに2通を登録
setDone(action, true)isDone = true・completedAt = now2通とも解除
setDone(action, false)isDone = false・completedAt = nil解除してから再登録（まだ間に合う分だけ）
updateText(action, text)前後の空白を削った文言に変更。空・同一なら何もしない未完了なら解除 → 再登録（本文に文言が入るため）
changeDueDate(action, date)dueDate を変更未完了なら解除 → 再登録
delete(action)アクションを削除2通とも解除
deleteMemo(memo)メモと配下のアクションを削除（cascade）配下の全アクションの2通を解除
deleteBook(book)本・メモ・アクションを削除（cascade）配下の全アクションの2通を解除

通知2通のトリガー時刻

通知ID本文時刻の決め方
期限当日action-{UUID}「{アクション}」は今日までです期限日の 9:00。それが既に過ぎていたらいまから1時間後。それも期限（23:59）を越えるなら登録しない
流れたaction-{UUID}-overdue「{アクション}」は流れました。期限を引き直しますか？期限翌日の 9:00。既に過ぎていたら登録しない

例: 22:30 に期限「今日」のアクションを作る → 当日通知は 23:30、流れた通知は翌 9:00。23:10 に作る → 当日通知なし（0:10 は期限超え）、流れた通知のみ。

通知の許可・週次通知・タップ時の挙動は BS-F03。

処理フロー

sequenceDiagram participant U as User participant E as MemoEditorView participant VM as MemoEditorViewModel participant AS as ActionService participant NS as NotificationService U->>E: 保存する E->>NS: requestPermissionIfNeeded()（未決定のときだけ） E->>VM: save(book, photoData, ocrText, context) VM-->>E: Memo（Action は期限つきで作成済み） E->>AS: scheduleAll(for: memo) AS->>NS: scheduleDueReminder(id, text, dueDate) × 件数 NS->>NS: 拒否なら登録しない／当日・翌日の2通を登録 E-->>U: 閉じて本の詳細へ U->>AS: チェック（本の詳細） AS->>AS: action.setDone(true, now) AS->>NS: cancelActionReminder(id)

ビジネスルール

  • 1メモにつきアクションは最大3件。空の行と同じ文言の重複は保存時に落とす
  • 流れたの判定は dueDate < now。期限は 23:59:00 なので、期限日の 23:59 以降は流れた
  • 流れたは終端ではない。後から完了にすれば「達成」（完了した週に数える）、期限を引き直せば「期限内」に戻る
  • 本の詳細での並びは 流れた（期限昇順）→ 期限内（期限昇順）→ 完了（完了時刻降順）（データモデル）
  • カレンダーに登録すると、予定の日がそのままアクションの期限になる（changeDueDate を通す）。カレンダー側の予定を消してもアプリ側は変わらない
  • View から action.isDone.toggle() や NotificationService を直接呼ばない

外部連携

連携先用途備考
UserNotifications期限当日・流れた の通知UNCalendarNotificationTrigger（年月日時分・繰り返しなし）。登録前に同じ ID の保留分を消す
EventKitアクションをカレンダーの予定にする書き込みのみの権限（requestWriteOnlyAccessToEvents）。予定は30分・既定カレンダー・タイトル「[BookSpark] {アクション}」

エラー処理

発生条件対応
通知が拒否されている登録しない（info ログ）。状態変更自体は行う
通知の登録に失敗error ログのみ
カレンダー登録に失敗・権限拒否シート内に「カレンダーへの登録に失敗しました」。期限は変えない

実装メモ

  • 通知の登録先は ActionReminderScheduling protocol で差し替え可能（テストでモックを注入するため）。本番は NotificationReminderScheduler
  • 純粋関数 DueDateRules（期限・通知時刻）と Action.state(at:)・Book.sortedActions(at:) は基準時刻を引数で渡せ、ユニットテストで検証済み（DueDateRulesTests / ActionStateTests / ActionServiceTests / BookSortedActionsTests）
  • 保留中のローカル通知には iOS の件数上限（64件）があるが、アプリ側で件数を管理していない（未完了アクション1件につき最大2件＋週次1件）
  • Action.reminderDate はカレンダー予定の日時を記録するだけで、通知時刻には使っていない
