通知

ローカル通知3種（期限当日・流れた・週次）の登録規則、許可の求め方、タップ時の遷移。

実装済 機能ID: BS-F03

概要

期限つきアクションは、期限が来たことを知らせないと「知らないうちに流れた」だけになる。 そのため期限当日の朝に1通、流れた翌朝に1通を出し、週末に振り返りを促す週次通知を1通繰り返す。 すべて端末内のローカル通知（UNUserNotificationCenter）で、サーバーは使わない。

関連画面

  • メモ編集（BS-S05） — 許可を求める場面（保存直前）
  • 本の詳細（BS-S04） — 完了・期限変更・カレンダー登録で再登録／解除
  • 週次レビュー（BS-S06） — 週次通知のタップ先
  • 設定（BS-S08） — 許可状態の表示と設定アプリへの導線

通知の種類

種類ID本文（タイトルは常に「BookSpark」）時刻繰り返し
期限当日action-{UUID}「{アクション}」は今日までです期限日の 9:00。過ぎていたら今から1時間後、それも期限を越えるなら出さないなし
流れたaction-{UUID}-overdue「{アクション}」は流れました。期限を引き直しますか？期限翌日の 9:00。過ぎていたら出さないなし
週次weekly-review今週の振り返りができますよ毎週日曜 20:00あり

いずれもサウンドは既定。アプリ前面にいるときもバナー＋サウンドで出す（willPresent で [.banner, .sound]）。

登録・解除のタイミング

契機処理
アプリ起動（毎回）週次通知を登録し直す（同じ ID の保留分を消してから追加）
メモ保存配下の未完了アクションに期限当日・流れた の2通を登録
完了にする／削除（アクション・メモ・本）該当アクションの2通を解除
完了を外す／文言変更／期限変更（カレンダー登録を含む）解除してから、未完了なら再登録

アクションの規則の全体は BS-F01。

許可の求め方

  • 起動時・オンボーディングでは求めない
  • メモの「保存する」を押した直後（保存処理の前）と、カレンダー登録に成功した直後に、許可状態が .notDetermined のときだけ OS のダイアログを出す（要求する種類は alert / sound / badge）
  • 拒否されたら以後は求めない。期限通知の登録時に .denied を見て登録をやめ、info ログを残す
  • 利用者が状態を確認・変更する場所は設定画面の「通知」行（設定アプリへ移動）

タップ時の遷移（コールド起動を含む）

sequenceDiagram participant U as User participant OS as iOS participant AD as AppDelegate participant ND as NotificationDelegate participant R as AppRouter participant BS as BookShelfView U->>OS: 週次通知をタップ OS->>AD: didFinishLaunching（コールド起動時） AD->>OS: UNUserNotificationCenter.delegate = ND OS->>ND: didReceive(response) ND->>ND: ID が weekly-review か確認 ND->>R: pendingWeeklyReview = true BS->>R: onAppear または onChange で確認 BS->>BS: activeSheet = .weeklyReview BS->>R: pendingWeeklyReview = false BS-->>U: 週次レビューを表示
  • デリゲートは画面を直接開かず、AppRouter（@Observable の共有オブジェクト）にフラグを立てるだけ。本棚が出現していなければ、出現した時点で拾う
  • 期限当日・流れた の通知はタップしてもアプリが開くだけで、特定の本・アクションへは遷移しない

ビジネスルール

  • 通知の時刻は「期限日の朝9時」に揃える。当日作成で9時を過ぎていても、期限までに1時間以上あれば1時間後に知らせる
  • 流れた通知は、期限を引き直すきっかけとして翌朝に1回だけ出す
  • 週は月曜始まりなので、週次通知（日曜 20:00）はその週の最後の夜に来る

外部連携

連携先用途備考
UserNotificationsローカル通知の許可・登録・解除・受信UNCalendarNotificationTrigger。期限系は年月日時分・1回、週次は曜日時分・繰り返し

エラー処理

発生条件対応
許可リクエストの例外未許可として扱う。error ログ（category Notification）
通知が拒否されている期限通知を登録しない。info ログ
登録の例外error ログ（通知 ID を .public で出す）

実装メモ

  • 週次通知は許可状態を確認せずに登録を試みる（期限通知は .denied なら登録しない）
  • スクリーンショット撮影モードでは起動時の週次通知の登録と StoreKit の確認を行わない
  • 通知 ID をアクションの UUID から作るので、同じアクションを登録し直しても重複しない
  • 設定画面のフッター文言は期限系2通のみを説明している
