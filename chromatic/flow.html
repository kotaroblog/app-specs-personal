初回の流れと ATT のタイミング（1.4.3・未公開）

1.4.3 から、初回は説明1枚（「光った順にタップ」）の「はじめる」で 4パネル×NORMAL の1ゲームがすぐ始まる。トラッキング許可（ATT）は、新しく入れた人では初回の結果画面を閉じた後（待機画面に戻してから）に出し、応答までは待機画面を押せない。応答を待ってから広告 SDK を初期化する。
flowchart TD Launch([起動]) --> Seen{オンボーディング済み?} Seen -- いいえ（新規） --> Onb[説明1枚
光った順にタップ] Onb -- はじめる --> Play[4パネル×NORMAL の
1ゲーム] Play --> Result[結果画面] Result -- 閉じる（初回の結果） --> Idle1[待機画面
応答まで操作を止める] Idle1 --> ATT1{{ATT のダイアログ}} ATT1 --> SDK1[広告 SDK の初期化] Seen -- はい（2回目以降の起動・旧版から使っている人） --> ATT2{{起動時に ATT
未回答のときだけ}} ATT2 --> SDK2[広告 SDK の初期化]

遊ばずに閉じた人にいつまでも出ない状態を作らないため、起動の時点でオンボーディングを済ませていれば、初回の結果を閉じていなくても起動時に出す。旧版でオンボーディング済みの人は「初回の結果を閉じた」扱い（新しいキー chromatic_has_closed_first_result で区別。既存のキーは変えない）。ATT を出してよいかの判定は従来どおり shouldRequestTracking。1.4.2 までは、オンボーディングを終えた後の起動時に出していた。
