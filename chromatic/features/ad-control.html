広告制御機能

Unity LevelPlay（バナー + インタースティシャル）／配信は App Store 版のみ

v3.0機能ID: CR-FEAT-AD2026-08-20 更新
現状: 広告は一切配信されていない。 2026-07-30 に AdMob アカウントが「無効なトラフィック」を理由に恒久的に無効化され、再審査請求も却下された。 その後 AppLovin MAX へ移行したが publisher アカウントの承認が下りなかったため、 2026-08-20 に Unity LevelPlay へ再移行した。 CHROMATIC は App Key と広告ユニットIDが未設定（空）のため、現時点では広告のリクエスト自体が発生しない。

広告基盤

項目内容
ネットワークUnity LevelPlay（Unity Ads をメディエーション経由の bidder として利用）
SDKLevelPlay 9.6.0（SPM: LevelPlay-Swift-Package / プロダクト名 UnityMediationSDK）
アダプタLevelPlayUnityAdsAdapter 5.10.0（プロダクト名 UnityAdsAdapter）。SDK とは別のバージョン体系のため 9.x を指定すると依存解決に失敗する
メディエーションアダプタも SPM で追加できるため CocoaPods は導入しない
対応フォーマットバナー・インタースティシャル・リワードの3種（CHROMATIC はバナーとインタースティシャルのみ使用）
使用クラスLPMBannerAdView（LPMAdSize.createAdaptive() / 破棄時に destroy() 必須） / LPMInterstitialAd
初期化LPMInitRequestBuilder(appKey:) → LevelPlay.initWith(_:completion:)。完了は @Observable な AdReadiness で SwiftUI に伝播
ロード開始条件広告配信が有効 かつ SDK 初期化完了後。LevelPlay は初期化前の loadAd() が失敗するため
ビルド設定OTHER_LDFLAGS に -ObjC が必須（Objective-C カテゴリを正しくリンクするため）
ロード失敗時指数バックオフで再試行（上限64秒）。リトライ Task は1本に束ねて並走させない

再発防止の設計（最重要）

アカウント無効化の原因は、開発・TestFlight での検証中に本番の広告でインプレッションが発生していたことにある。 ネットワークを変えても自己クリック・視聴依頼の禁止という規約は同じであるため、 広告をロード・表示するのは App Store 配信版のみに限定した。

判定内容
AdEnvironment.isProduction App Store 配信版か。判定はApp Store レシートの種別（sandboxReceipt かどうか）で行う。TestFlight・Xcode から実機へ直接インストールした場合のレシートは sandboxReceipt になるため、ビルド構成の設定ミスでは判定が破れない
AdEnvironment.isAdDeliveryAvailable !appKey.isEmpty && isProduction（App Key が設定済み かつ App Store 配信版）のときだけ true。バナーの表示可否・全画面広告の呼び出し・ATT ダイアログ・SDK 初期化のすべてがこの値で分岐する単一スイッチ
LevelPlay にも AdMob のような「テスト広告ID」の概念がない。 そのため開発中は「広告を出さない」方式を採用し、レイアウト確認は広告枠のプレースホルダで行う。 本番広告での目視確認は行わない。
具体的な App Key・広告ユニットIDは本仕様書には記載しない（コード側で管理する）。

広告構成

種類表示条件プレミアム購入者
バナー LPMBannerAdView。ゲーム画面の最下部に固定（safeAreaInset）。広告フォーマット本来の高さをそのまま使い、固定値でクリップしない 非表示
インタースティシャル LPMInterstitialAd。ゲーム終了後の「もう一度」「モード選択へ」タップ時。4ゲームに1回かつ前回表示から最低90秒空ける 非表示
リワード CHROMATIC では未導入（報酬型の導線を持たない）

広告配信が無効な期間の挙動

対象挙動理由
バナー枠ごと非表示。ビュー自体を配置しないため盤面下に余白が残らない広告リクエストを発生させない
インタースティシャル呼び出さない。ロードもしない同上
SDK 初期化行わない起動コストと不要な通信を避ける
ATT（トラッキング許可）ダイアログ表示しないトラッキング許可は広告目的でしか求めていない。広告がない状態で許可を求めると「求める理由がない」状態になり審査リスクになる
撮影モード（スクリーンショット自動撮影）広告・ATT・通知ダイアログをすべて抑止提出用スクショを覆わないため

ATT（トラッキング許可）の要求タイミング

  • 広告配信が有効（isAdDeliveryAvailable == true）であること
  • 3ゲーム完了後のゲームオーバー時（初回ゲームオーバーからの変更）
  • ステータスが notDetermined であること
  • 撮影モードでないこと

許可・非許可いずれでも広告配信は可能で、非許可時は非パーソナライズ広告になる。

ビジネスルール

  • 広告のロード・表示は App Store 配信版でのみ行う。DEBUG・シミュレーター・TestFlight では一切リクエストしない
  • App Key または広告ユニットIDが未設定の間は、広告に関わる処理を一切実行しない（安全側の既定）。CHROMATIC は現在この状態
  • SDK の初期化完了前は広告をロードしない（LevelPlay は初期化前の loadAd() が失敗するため）
  • プレミアム購入者には広告を表示しない。今後広告を再開した場合も表示しない（購入時の保証）
  • 全画面広告には必ず表示間隔（4ゲームに1回・最低90秒）を設ける
  • バナーはアダプティブサイズの高さをそのまま使い、固定値でクリップしない（広告の一部が隠れるとポリシー違反）
  • 広告をボタンやタップ導線に隣接させない（誤クリック誘発の禁止）
