設定（SettingsView）

人生タブ右上の歯車から開く設定画面。プロフィール編集・通知・表示切替・アプリ情報・全データ削除を集約する。

実装済 画面ID: LR-SETTINGS-01

目的・役割

アプリの前提（生年月日・目標年齢）と、体験の強度（残り時間と人生の週を出すかどうか）、 通知、法務まわりの外部リンク、そして全データ削除を一箇所に集めた画面。 テーマはダーク固定のため配色の切替は持たない（将来プレミアムで検討）。

この画面の位置づけ: 人生タブ（LR-S04）の NavigationStack に push される。 子として リマインダー設定（LR-REMINDER-01） を持ち、 プロフィール編集は2つの .sheet（TargetAgeSheet / BirthDateSheet）で行う。
設定歯車は金ではなく月白: アプリ全体の tint を AppColors.moonWhite に統一している。 金をグローバル tint にすると歯車・トグル・ピッカーが軒並み金になり「1画面1点の金」が構造的に破れる （トグル ON 時は面塗りにもなり、金の面禁止にも反する）。

UI 構成（List・セクション順）

セクション項目説明
プロフィール目標年齢UserProfile が存在するときだけ出るセクション。値（「○歳」）＋シェブロン。タップで TargetAgeSheet を .sheet 表示。
プロフィール生年月日値（ymd）＋シェブロン。タップで BirthDateSheet を .sheet 表示。
通知リマインダーNavigationLink → ReminderSettingsView（LR-REMINDER-01）。右に現在のサマリー（reminderEnabled が false なら「オフ」、true なら「日 21:00」形式＝JapaneseWeekday.symbol ＋ %02d:%02d）。
表示残り時間と人生の週を表示Toggle（@AppStorage("showLifeCountdown")・既定 ON）。直下に説明文「気持ちが重く感じるときは、いつでも非表示にできます。」（caption・textMuted）。OFF にすると人生タブのカウントダウン・週グリッドと今日タブの残り時間ミニ（＋そこから開く「人生の週」全画面への導線）が同時に消える（両画面が同じキーを見ている）。
アプリ情報バージョンBundle.main.infoDictionary の CFBundleShortVersionString と CFBundleVersion から「1.0.0 (1)」形式で組み立てる。前者が取れなければ「—」、後者が空ならバージョンのみ。タップ不可（シェブロンなし）。
アプリ情報プライバシーポリシー / 利用規約 / サポート・お問い合わせLink → app-policies の各 URL（https://kotaroblog.github.io/app-policies/lifereview/…）。行の右端に外部遷移アイコン arrow.up.forward（caption semibold・textMuted）を置き、.accessibilityHint("Safariで開きます") を付ける。URL 生成は force unwrap せず if let で分岐し、作れなければ行自体を出さない。
危険操作全データを削除destructive ロールのボタン。確認アラート経由で実行（下記）。
2026-08-25 の変更（押せることが見えていなかった2箇所）
  • ポリシー3リンクに外部遷移アイコンを追加。 それまでは値なしの row(title, "") をそのまま Link で包んでいたため、 見た目が普通のテキスト行と区別できず、タップできること・Safari に出ることの手がかりがゼロだった。

プロフィール編集シート

シート内容
TargetAgeSheet（目標年齢）数値 TextField（44pt bold amber・numberPad・monospacedDigit・入力は 1〜120 にクランプ）＋ Stepper。Stepper の下限は min(現在年齢 + 1, 120)（現在年齢が 120 以上でも不正な Range を作らないため頭打ちにする）。キーボード上に「完了」。保存で UserProfile.targetAge を更新。
BirthDateSheet（生年月日）DatePicker .wheel（上限は今日）。オンボーディング・大切な人の編集シートと同じホイール（数十年さかのぼるのに月送り前提の .compact は使わない）。保存で UserProfile.birthDate を更新。
共通ツールバーは「閉じる」（cancellationAction）／「保存」（confirmationAction・不正時 disabled）。保存失敗時は modelContext.rollback() ＋「保存できませんでした。もう一度お試しください。」のアラート。
シートバリデーション不正時の文言
TargetAgeSheetUserProfile.isValidTargetAge(value, birthDate: profile.birthDate)「現在○歳より大きい年齢にしてください。」（amber の Label）
BirthDateSheetUserProfile.isValidTargetAge(profile.targetAge, birthDate: value)「この生年月日だと現在○歳になり、目標年齢（○歳）を超えてしまいます。先に目標年齢を上げてください。」
BirthDateSheet のバリデーションを後から足した理由（2026-07-26）: オンボーディングと目標年齢シートは「目標年齢 > 現在年齢」を既に拒否していたのに、生年月日シートだけ無検査だった。 そこからだけ生年月日を後ろにずらして目標年齢 ≦ 現在年齢（残り 0年0ヶ月・進捗 100% で固まる状態）を作れてしまう。 判定を UserProfile.isValidTargetAge(_:birthDate:now:) に集約し、3画面が同じ規則を共有するようにした。

全データを削除

確認アラート「全データを削除しますか？／記録・大切な人・やりたいことリスト・振り返り・添付写真・プロフィールと表示設定・通知予約まで、 すべてのデータが削除されます。この操作は取り消せません。」（削除 destructive ／ キャンセル）を必ず経由する。

  • SwiftData 5モデル（LogEntry / UserProfile / Relation / BucketItem / ReflectionSession）を種別ごとに try modelContext.delete(model:) → 最後に save()。
  • 添付画像ファイル（ImageStore.deleteAll()）。
  • 予約済みの週次通知（NotificationService.shared.cancelWeekly()）。
  • 未完了の振り返り下書き（全種別 ReflectionDraftStore.clear(type:)）。
  • @AppStorage（SettingsView.resettableDefaultsKeys: reminder 系4キー ＋ showLifeCountdown）。
  • 最後に onboardingCompleted = false → アプリのルートが RootTabView から OnboardingView に切り替わる。
  • ファイル・通知・下書きの掃除は save() 成功後に行う。 失敗時は rollback() ＋「データを削除できませんでした。もう一度お試しください。」のアラートで、データは元のまま残る。

状態

状態表示内容
UserProfile あり全セクションを表示（プロフィール／通知／表示／アプリ情報／全データ削除）。
UserProfile なし「プロフィール」セクション（目標年齢・生年月日）ごと表示しない。通知・表示・アプリ情報・全データ削除は常に出る。
リマインダー オフ「リマインダー」行の値は「オフ」。
リマインダー オン「リマインダー」行の値は「日 21:00」形式（曜日記号＋時刻）。
URL を生成できない該当のポリシー行を描画しない（force unwrap しない）。
編集シートの入力が不正「保存」を disabled にし、シート内に amber の警告 Label を表示。
保存・削除に失敗rollback() したうえでエラーアラートを表示。画面には留まる。

アクセシビリティ対応

  • ポリシー3リンクに .accessibilityHint("Safariで開きます")。アプリ外に出ることを操作前に伝える。
  • タップ可能行のシェブロン・外部遷移アイコンは textMuted（罫線色 outline は面上で 1.2:1 程度しかなく、手がかりとして機能しない）。
  • Dynamic Type: 行のラベル・値は scaledFont で追従する。例外は TargetAgeSheet の数値 TextField（44pt 固定）——TextField には minimumScaleFactor が効かず、追従させると最大文字サイズで3桁が横にはみ出す。値は Stepper でも変えられ 44pt は既に十分大きいため据え置く。
  • 破壊的操作（全データ削除）は destructive ロール ＋ 確認アラートの二段構え。
  • ナビタイトルは minchoNavigationTitle("設定")（principal に自前描画・accessibilityHidden(true)）。

実装メモ

  • List は .scrollContentBackground(.hidden) ＋ 各セクション .listRowBackground(AppColors.surface) ＋ screenBackground() で C案の面に揃える。
  • row(_:_:showChevron:enabled:) が行の共通レイアウト。ポリシー行だけは値を持たないため row を使わず、専用の policyLink(_:_:) で「タイトル ＋ Spacer ＋ 外部遷移アイコン」を組む。
  • プロフィール編集シートは UserProfile を直接更新して save()。失敗時は rollback() ＋ エラーアラート。
  • resetAppStorage(defaults:) は UserDefaults を引数で受けるので、テストから専用 suite を渡して検証できる。
  • この画面には広告・解析・課金がひとつも無い。外部通信はポリシー3リンク（Safari 遷移）だけで、アプリ自身は何も送信しない。
