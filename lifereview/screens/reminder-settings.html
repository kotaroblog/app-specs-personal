リマインダー設定

週次振り返りの曜日・時刻を指定する端末内ローカル通知の設定画面。

実装済 画面ID: LR-REMINDER-01

目的・役割

週次の振り返りを習慣にできるよう、毎週きまった曜日・時刻にローカル通知を出すための設定画面。 設定（人生タブ右上の歯車）→「通知」セクションの「リマインダー」行から NavigationLink で push する。 通知は端末内の UNUserNotificationCenter で完結し、サーバー送信・外部共有は行わない。 実装は ReminderSettingsView（UI・永続化）と NotificationService（許可・登録・解除）に分かれている。

実装されている通知は週次1本だけ（v1.0.0）: NotificationService が持つスケジュール API は scheduleWeekly / cancelWeekly の2つのみで、 識別子も "weekly_reflection" の1本だけ。月次・年次のリマインダーは未実装で、通知の種類を選ぶ UI も存在しない。 ふりかえりタブの月次・年次カードはユーザーが自分で開くもので、通知は出ない。
プライバシー: 通知の有効/無効・曜日・時刻は @AppStorage（UserDefaults）で端末内にのみ保持する。 通知許可ダイアログはシステム提供のもの（requestAuthorization）。通知関連の Info.plist キーは project.yml に定義していない（ローカル通知のみのため不要）。

UI 構成（ReminderSettingsView）

要素種類説明
ルートList.scrollContentBackground(.hidden) ＋ screenBackground()（地の藍＋粒）。タイトルは .minchoNavigationTitle("リマインダー")（明朝インライン）。
有効/無効トグルToggle「週次リマインダー」ON で許可リクエスト → 許可されたら有効化＋スケジュール登録。OFF で enabled = false ＋ cancelWeekly()。
トグル下の説明Section footer「毎週きまった曜日・時刻に、振り返りをそっとお知らせします。端末内だけで完結し、データは送信されません。」
タイミング SectionSection（header「タイミング」）トグル ON のときだけ List に現れる（if enabled）。
曜日ピッカーPicker「曜日」（スタイル未指定＝List 既定）ForEach(1...7)。ラベルは JapaneseWeekday.fullSymbol（「日曜日」〜「土曜日」）。タグは Calendar 準拠の 1=日〜7=土。変更で即再スケジュール。
時刻ピッカーDatePicker「時刻」（displayedComponents: .hourAndMinute）選択値から Calendar.current で hour / minute を取り出して保存し、即再スケジュール。表示用の Date は「今日の hour:minute」を都度組み立てている。
次回表示Section footer（footnote・textMuted）「次回：日曜日 21:00」の形式。保存済みの曜日・時刻をそのまま整形しているだけで、実際の日付計算はしていない。
許可なしアラートalertタイトル「通知が許可されていません」／本文「リマインダーを使うには、設定アプリで「人生アルバム」の通知を許可してください。」／ボタン「設定を開く」「閉じる」。

通知内容のプレビューカードや、画面内に常設される警告バナーは実装していない（許可がない場合はアラートで一度だけ伝える）。

通知内容（NotificationService.scheduleWeekly）

項目内容
タイトル「そろそろ、ふりかえりませんか」
本文「この一週間で、心が動いた瞬間は？」
サウンド.default
バッジ設定しない（許可 options には .badge を含むが、content.badge は未使用）
トリガーUNCalendarNotificationTrigger(dateMatching:repeats: true)。DateComponents は weekday / hour / minute / timeZone のみ。
タイムゾーンTimeZone(identifier: "Asia/Tokyo") 固定（下記の callout 参照）
識別子"weekly_reflection"（固定・private static）
登録手順removePendingNotificationRequests(withIdentifiers:) で同一識別子を消してから add(request)。失敗時は Logger にエラー出力するだけで UI 表示はしない。
タイムゾーンは Asia/Tokyo 固定（実装の事実）: 時刻ピッカーは Calendar.current（＝端末のタイムゾーン）で hour / minute を取り出して保存するが、 スケジュール時はその数値をそのまま Asia/Tokyo の時・分として DateComponents.timeZone に載せる。 したがって端末が JST 以外に設定されている場合、通知は「端末ローカルの 21:00」ではなく「JST の 21:00」に鳴り、 ピッカーの表示値と実際の発火時刻がずれる。「次回：」の文言も保存値の整形のみでタイムゾーン変換をしない。 日本国内向けアプリとして JST 固定を選んだ結果であり、v1.0.0 時点では端末タイムゾーン追従にしていない。

通知許可の扱い

場面実装の挙動
この画面を開いただけ許可リクエストは発行しない。.task で syncWithSystemAuthorization() を走らせるだけ。
トグルを ON にした瞬間turnOn() → requestAuthorization(options: [.alert, .badge, .sound])。許可されたら enabled = true にして scheduleWeekly。
許可が得られなかったenabled = false に戻し（トグルは OFF のまま）、アラート「通知が許可されていません」を表示。通知は登録しない。
すでに設定アプリで拒否済みシステムはダイアログを出さず即座に false を返すため、同じアラートに落ちる。「設定を開く」で UIApplication.openSettingsURLString を UIApplication.shared.open（URL 生成は guard let・force unwrap しない）。
許可リクエスト自体が throwLogger（subsystem: com.happyboy1002.LifeReview / category: Notification）にエラーを残し false を返す＝拒否と同じ扱い。
画面表示のたび（.task）enabled == true のときだけ notificationSettings().authorizationStatus を確認。.authorized / .provisional のどちらでもなければ enabled = false ＋ cancelWeekly()。アプリ外で通知を切られたまま「ON」が残るのを防ぐ。
この画面以外からの許可要求ふりかえりタブのリマインダー提案カード（F12）の「設定する」でも requestAuthorization を呼ぶ。アプリ起動時に許可を求める経路は存在しない。

状態

状態表示内容
初期表示（未設定）トグル OFF（reminderEnabled の既定値 false）。「タイミング」Section は非表示。曜日・時刻の既定値（1=日 / 21:00）は AppStorage の初期値として常に保持されている。
トグル ON・許可済み「タイミング」Section（曜日ピッカー・時刻ピッカー・「次回：〜」footer）を表示。
トグル ON 操作・未許可システムの許可ダイアログ。許可されればそのまま ON＋登録、されなければ OFF に戻ってアラート。
トグル ON 操作・拒否済みダイアログは出ず、トグルは OFF のままアラート（設定アプリへ誘導）。
トグル OFFcancelWeekly() で識別子 weekly_reflection の予約分のみを削除（配信済み通知は消さない）。
曜日・時刻を変更enabled == true のときだけ即座に再スケジュール（reschedule()）。OFF のときは値の保存だけ行う。
アプリ外で通知を拒否された後に再訪.task の突き合わせでトグルが自動的に OFF に戻り、予約も解除される。

使用するデータ

// 設定値は @AppStorage（UserDefaults）で端末内に永続化。SwiftData は使わない。
@AppStorage("reminderEnabled") private var enabled = false
@AppStorage("reminderWeekday") private var weekday = 1   // 1=日..7=土（Calendar 準拠）
@AppStorage("reminderHour")    private var hour = 21
@AppStorage("reminderMinute")  private var minute = 0

// NotificationService（@MainActor / static let shared）の公開 API はこの4つだけ
func requestAuthorization() async -> Bool
func authorizationStatus() async -> UNAuthorizationStatus
func scheduleWeekly(weekday: Int, hour: Int, minute: Int) async
func cancelWeekly()

// 曜日ラベルの単一情報源（Support/JapaneseWeekday.swift）
JapaneseWeekday.symbol(1)      // "日"     … 設定画面のサマリー行
JapaneseWeekday.fullSymbol(1)  // "日曜日" … この画面の曜日ピッカー・「次回：」
// 範囲外（1...7 以外）は "—" を返す

設定画面の「全データを削除」では、NotificationService.shared.cancelWeekly() で予約を解除したうえで reminderEnabled / reminderWeekday / reminderHour / reminderMinute を SettingsView.resetAppStorage() で消す（キー一覧は resettableDefaultsKeys・ユニットテストで担保）。

アクセシビリティ対応

  • 操作要素は Toggle / Picker / DatePicker の標準コントロールのみ。タップ領域と VoiceOver 読み上げはシステム標準に従う。
  • 「次回：〜」は .font(.footnote)＋AppColors.textMuted。Dynamic Type に追従する。
  • ナビタイトルは principal に明朝で自前描画し .accessibilityHidden(true)。読みは navigationTitle 側に寄せて二重読みを避ける（minchoNavigationTitle 共通実装）。
  • 許可されていないことはアラート（システム標準）で伝えるため、フォーカス移動とボタン読み上げも標準どおり。

実装メモ

  • 識別子を "weekly_reflection" に固定しているため、曜日・時刻を変えるたびに remove → add で確実に1本だけが残る。
  • cancelWeekly() は removePendingNotificationRequests のみ。配信済み通知の削除（removeDelivered…）はしていない。
  • トグルの見た目は enabledBinding（get/set カスタム Binding）で AppStorage に直結。ON のときは set が Task { await turnOn() } を起こすだけで、許可待ちの結果を受けて turnOn() 側が enabled = false に戻す（set 内で直接戻すわけではない）。
  • 時刻の Binding は「今日の日付＋保存済み hour/minute」で Date を組み立てる。時刻のみのピッカーでも年月日が欠けないようにするため。
  • ふりかえりタブの提案カード（F12）から有効化した場合は、その日の曜日 ＋ 21:00 固定で登録される（カード本文は「いまと同じ曜日・時刻に」と書いているが、実装が現在時刻を使うのは曜日だけ）。時刻を変えたい場合はこの画面で調整する。
  • C案デザイン規律: この画面に金（amber / goldDim）は使わない。地は screenBackground() で全画面共通。
  • 月次・年次通知、通知の一時停止（スヌーズ）、複数リマインダーは v1.0.0 のスコープ外。
