人生タブ（S04）

長期視点の集約画面。残り時間カウントダウン・人生の週グリッド・大切な人・バケットリスト・設定を提供する。

実装済 画面ID: LR-S04

目的・役割

「人生」タブは有限性を可視化し、長期的な視点でのアクション（バケットリスト・大切な人）への入口を提供する。 Your Life in Weeks の週グリッドと残り時間カウントダウンで、ユーザーが自分の人生の全体像を静かに俯瞰できる空間。 設定（歯車アイコン）は右上から開き、プロフィール編集（目標年齢・生年月日）・リマインダー・表示切替・アプリ情報・全データ削除を集約する。

C案規律: 週グリッドの「今週」だけが金の1点。経過セルは生成りの微光（weekPast）、未来は沈んだ藍（weekFuture）。カウントダウン数字は onSurface。金面は使わない。
設定歯車は金ではなく月白（2026-07-26）: アプリ全体の tint を AppColors.moonWhite に統一した（LifeReviewApp）。 金をグローバル tint にすると歯車・トグル・ピッカーが軒並み金になり「1画面1点」が構造的に破れる（トグル ON 時は面塗りにもなり、金の面禁止にも反する）。 この画面で金を使ってよいのは週グリッドの「今週」セル1点だけ。UIKit 層のナビ／タブバーも moonWhiteUI で揃えている。

CountdownView の詳細

要素説明
残り時間表示profile.remainingYearsMonths() から年数・ヶ月数を取得。365/30 の近似ではなく暦（DateComponents）で算出する（「0年12ヶ月」やうるう年ずれを避けるため）。
数字と単位のレイアウト数字は scaledFont(40, weight: .semibold) + lineLimit(1) + minimumScaleFactor(0.7)。単位「年」「ヶ月」は scaledFont(17)・lineLimit(1)・fixedSize で語中で折らない（大きな文字サイズで「ヶ／月」に割れるのを防ぐ）。幅の調整は数値側の縮小が受け持つ。
ThinProgressBarprofile.progress()（0.0〜1.0）を細線（高さ3）で表示。塗りは金ではなく textBody.opacity(0.5)・トラックは night3（ThinProgressBar の既定色。金は週グリッドの「今週」1点に取ってある）。
進捗テキスト「これまで ○% を歩いてきました」（○ = Int((progress * 100).rounded())・四捨五入）。
アクセシビリティ.accessibilityElement(children: .combine)・accessibilityLabel「これからの時間」・accessibilityValue「○年○ヶ月。これまで○パーセントを歩いてきました」。

WeekGridBody / WeekGridCanvas の詳細

要素説明
サマリーカード現在（○歳・onSurface）・経過（○週・onSurface）・残り（○週・onSurfaceVariant）・合計（○週「合計(○歳)」・textMuted）の4カラム統計を AppCard（padding 16）内に表示。値は scaledFont(14, weight: .bold) monospacedDigit、ラベルは scaledFont(10)。縦セパレーター（cardBorder 1px・高さ32）で区切る。Dynamic Type が accessibility1 以上のときは 2×2 に折り返す（区切りは横罫に変わる）。
凡例「経過した週」（weekPast #706D66）・「今週」（amber #C2894B）・「残りの週」（weekFuture #1B2333）の3種。10×10 の角丸ドット＋ scaledFont(11) のラベル。
WeekGridCanvas52列 × targetAge 行の週グリッドを Canvas で描画。cellW=(width-gutter-gap*52)/52・cellH=5px・rowGap=2px・gap=1px・gutter=24px・セル角丸1px。cellW が 0 以下になる幅では描画しない。10年毎（year % 10 == 0）に年齢ラベル（8pt・textMuted）を左端に表示。今週セル（idx == elapsedWeeks）= amber（金の節目1点）／経過 = weekPast／未来 = weekFuture。
アクセシビリティCanvas 全体に「人生の週グリッド」accessibilityLabel・「経過○週、残り○週」accessibilityValue。サマリーの各セルは .accessibilityElement(children: .combine)。
全画面表示（LifeTimelineScreen）同じ WeekGridBody を単独で表示する画面。今日タブの残り時間ミニ（RemainingTimeMiniView）からの push 先で、人生タブからは遷移しない。UserProfile が無い場合は「プロフィールを設定してください」を表示。screenBackground() ＋ minchoNavigationTitle("人生の週")。
グリッド配色の修正（2026-07-26）: 経過セルは以前 textBody.opacity(0.28) の合成で作っていたが、未来セル（night3）に対する実効コントラストが 1.80:1 しかなく、 サムネイルサイズで境界が消えていた。さらに凡例ドットはカード面（night2）・グリッド本体は背景（night1）の上に描かれるため、 同じ opacity 指定でも凡例と本体で実効色がズレていた。不透明の専用トークン weekPast（L=.1727）/ weekFuture（L=.0167）に切り出して両方を解決（実測 3.05:1）。 weekFuture は値としては night3 と同じだが、押下面のトークンと用途を分離するために別名で持つ。「今週」だけが amber。

サブ画面（人生タブから遷移）

バケットリスト（BucketListView）

要素説明
List + BucketRowBucketItem を createdAt 降順で一覧表示。各行: チェックボタン（checkmark.circle.fill / circle・22pt）＋タイトル（subheadline）＋メモ（caption・2行まで）＋目標期日「目標 2026/7/26」（caption2）。行の背景は surface。
タップ領域の分離チェックボタン（minWidth/minHeight 44 + contentShape）で完了トグル、テキスト領域タップで編集シート。ひとつのボタンに両方の役割を持たせると誤爆するため Button を2つに割っている。
完了状態isCompleted=true のとき取り消し線＋textMuted 色＋チェックアイコン amber 色（未完了は outline）。トグル時に completedAt を Date()／nil で更新して save。
スワイプ削除.onDelete で pendingDeleteOffsets に退避し、確認ダイアログ「削除しますか？／メモや目標期日も一緒に削除されます。この操作は取り消せません。」（削除 destructive／キャンセル）を経由して実行（2026-07-26 追加）。
EmptyStateView未登録時: checklist アイコン＋「まだ何もありません」＋「やりたいことをまだ登録していません」＋「やりたいことを追加」CTA ボタン（minHeight 44）。
追加・編集（BucketEditSheet）ナビバー「+」または EmptyState CTA タップで .sheet 表示（既存を渡すと編集モード。ナビタイトルは「新しい項目」／「編集」）。タイトル（必須・空白のみは保存 disabled）・メモ（任意・複数行 1〜4行）・目標期日（Toggle + DatePicker .date）。編集時は既存インスタンスを上書きし、完了状態・作成日は保持する。

大切な人（RelationsListView）

要素説明
List + RelationRowRelation を createdAt 降順で一覧表示。各行: 名前（scaledFont(17, weight: .semibold)・onSurface）＋続柄（12.5pt・textMuted・任意）＋残り会える回数（1回以上のときだけ「あと○回」・onSurfaceVariant・13.5pt medium monospacedDigit／0回のときは「想定の年齢を迎えました」・12pt・textMuted・右寄せ2行）＋「年○回」（11pt・textMuted）。行全体が Button で、タップすると編集シート。行は .accessibilityElement(children: .combine) でひとまとめに読み上げる。
残り回数計算relation.remainingMeetings(from:) = max(0, targetAge - currentAge(from: now)) × meetingsPerYear。年齢は生年月日から毎回算出する（Relation+Life.swift。now: を注入できるのでテストが実行日に依存しない）。生年月日が未設定なら nil を返し「年○回」（12.5pt）のみ表示。
フッター（算出根拠）List の Section footer に「『あと○回』は、生年月日・想定年齢・会う頻度から算出した目安です。生年月日を登録すると、時間の経過に合わせて数が減っていきます。」（caption・textMuted）。
スワイプ削除.onDelete → 確認ダイアログ「削除しますか？／この操作は取り消せません。」（削除 destructive／キャンセル）を経由して実行。
EmptyStateView未登録時: person.2 アイコン＋「まだ登録がありません」＋「大切な人をまだ登録していません」＋「大切な人を追加」CTA ボタン。
追加・編集（RelationEditSheet）名前（必須）・続柄（任意）・生年月日（Toggle「生年月日を設定」＋ ホイール DatePicker・上限は今日）・想定年齢（数値入力 + Stepper・1〜120）・会う頻度（Stepper・年1〜365回）。生年月日 ON のときだけ「現在 ○歳」行と想定年齢行が現れる。新規追加時の初期値は 生年月日=およそ55歳前・想定年齢80歳・会う頻度 年2回。数値入力はキーボード上の「完了」でフォーカス解除できる。編集時は既存インスタンスを上書きし、作成日は保持する。
バリデーションRelation.isValidTargetAge(targetAge, birthDate:now:)（= targetAge > 現在年齢）。不正なら「想定年齢は、現在の年齢（○歳）より大きい値にしてください。」を amber の Label で表示し保存を無効化。名前が空白のみのときも保存不可。生年月日 OFF のときは常に有効。
免除規則（2026-08-25 追加）: 編集中の相手について想定年齢と生年月日をどちらも変更していない場合は、既に想定年齢に達していても保存を許す。片方でも変更したら通常の判定に戻す（想定年齢だけを同一性の条件にすると、生年月日を後ろへずらして「想定年齢 < 現在年齢」の不整合を保存できてしまう）。
Relation のスキーマ変更（2026-07-26）: currentAge: Int? を廃止し birthDate: Date? に変更した。 「現在の年齢」を保存していると登録した瞬間の年齢が固定され、1年経っても「あと○回」が減らない——この機能の価値そのものが時間とともに嘘になる。 生年月日ピッカーは .wheel（オンボーディング・設定の生年月日シートと統一。数十年さかのぼるのに月送り前提の .compact は使わない）。
想定年齢に達した相手の扱い（2026-08-25）
  • 「あと0回」と表示しない。 存命の相手に 0 という数字を出すのは、このアプリで最も強い断定になる。 数字をやめ「想定の年齢を迎えました」という静かな一文に置き換え、想定年齢の見直しへ促す。
  • その状態でも編集を保存できる。 従来はバリデーションに引っかかって保存自体ができず、 「会う頻度だけ直したい」ときに想定年齢の変更を強制されて詰む状態だった。 免除するのは「想定年齢も生年月日も触っていない」ときだけに限る。

設定（SettingsView）

右上の歯車から push する画面。詳細は単独仕様書 設定（LR-SETTINGS-01） に分離したため、 ここではタブから見た概要だけを置く（記述を二重に持たない）。

セクション概要
プロフィール目標年齢（TargetAgeSheet）・生年月日（BirthDateSheet）。UserProfile があるときだけ出る。
通知リマインダー → ReminderSettingsView（LR-REMINDER-01）。右に「オフ」/「日 21:00」のサマリー。
表示「残り時間と人生の週を表示」トグル（showLifeCountdown・既定 ON）。OFF にすると人生タブのカウントダウン・週グリッドと、今日タブの残り時間ミニが同時に消える（両画面が同じキーを見ている）。
アプリ情報バージョン表示と、app-policies へのリンク3本（プライバシーポリシー／利用規約／サポート・お問い合わせ・Safari で開く）。
危険操作全データを削除（確認アラート経由。SwiftData 5モデル＋画像＋通知予約＋下書き＋ @AppStorage を消し、オンボーディングへ戻る）。

アクセシビリティ対応

  • CountdownView: .accessibilityElement(children: .combine) + accessibilityLabel/Value でまとめて読み上げ。
  • WeekGridCanvas: .accessibilityLabel("人生の週グリッド") + .accessibilityValue("経過○週、残り○週")。
  • 設定ナビバー「gearshape」ボタン: .accessibilityLabel("設定を開く")。
  • RelationsListView「+」ボタン: .accessibilityLabel("大切な人を追加")。
  • BucketListView「+」ボタン: .accessibilityLabel("やりたいことを追加")。
  • BucketRow のチェックボタン: .accessibilityLabel(item.title) + .accessibilityValue(isCompleted ? "完了済み" : "未完了") + .accessibilityAddTraits(isCompleted ? .isSelected : [])。
  • WeekGridBody サマリーの各 stat セル / RelationRow: .accessibilityElement(children: .combine) でまとめる。
  • RelationEditSheet の生年月日ホイール: .labelsHidden() のため .accessibilityLabel("生年月日") を明示。
  • Dynamic Type: .font(.system(size:)) の直書きをやめ、本文・数値は scaledFont(_:relativeTo:weight:)、明朝見出しは AppFont.mincho(_:relativeTo:) で追従させる。カウントダウンの数字は minimumScaleFactor(0.7)、週サマリーの値は 0.75 で受ける。例外は TargetAgeSheet の数値 TextField（44pt 固定）——TextField には minimumScaleFactor が効かず、追従させると最大文字サイズで3桁が横にはみ出す。値は Stepper でも変えられ 44pt は既に十分大きいため据え置く。
  • 44pt: BucketRow のチェックボタンは minWidth/minHeight 44 + contentShape(Rectangle())。EmptyStateView の CTA も minHeight 44。
  • 破壊的操作の確認: バケットリスト・大切な人のスワイプ削除、全データ削除はいずれも確認アラートを挟む。
  • ナビタイトルは principal に自前描画するため .accessibilityHidden(true)。読みは navigationTitle 側に寄せ、二重読みを避ける。

実装メモ

  • LifeView は NavigationStack を持つ。SettingsView・RelationsListView・BucketListView は全て同一 NavigationStack 内に push される。
  • WeekGridCanvas は Canvas（SwiftUI）で描画するため非常に軽量。targetAge=80 では 80×52=4,160 セル分の描画をこなす。
  • WeekGridBody の totalWeeks / elapsedWeeks / currentAge は UserProfile の extension（UserProfile+Life.swift）で計算。ビューに計算ロジックは持たせない。
  • BucketItem・Relation の削除は SwiftData の modelContext.delete() → save()。失敗時は rollback + エラーアラート。
  • SettingsView の「全データを削除」は try modelContext.delete(model: LogEntry.self) 等を種別毎に実行し、最後に save()。失敗時は rollback。
  • SettingsView のプロフィール編集シート（TargetAgeSheet / BirthDateSheet）は UserProfile を直接更新し save() する。失敗時は rollback + エラーアラート。
  • 残り回数計算（RelationRow）は currentAge(from:) が nil（生年月日未設定）の場合に nil を返し、View 側で分岐する。計算は純粋な算術: max(0, targetAge - currentAge) × meetingsPerYear。
  • 背景・粒・ナビタイトルは共通部品に寄せる。 screenBackground() が背景色（night1）と grainOverlay() をまとめて敷く。粒は子ビューへ継承されないためタブのルートに敷いても push 先やシートには乗らず、画面ごとに2行書く運用では必ず漏れる（実際に導入時は8画面にしか乗っていなかった）。人生タブ配下は LifeView・RelationsListView・BucketListView・SettingsView・各シートまで全て screenBackground() を使う。
  • ナビタイトルは自前描画（minchoNavigationTitle(_:)）。 iOS 26 では UINavigationBarAppearance.largeTitleTextAttributes にカスタムフォントを指定すると大タイトルが一切描画されず全画面が無題になる。そのため大タイトルは引退させ、ToolbarItem(placement: .principal) に明朝17ptで置く。navigationTitle も併記して戻るボタンのラベルと VoiceOver の画面文脈を残す。UIKit 側の Appearance には色だけを残し、modifier の付け忘れがあってもゴシックで見えるフォールバックにしている。
  • List 系は .scrollContentBackground(.hidden) + 各行 .listRowBackground(AppColors.surface) で C案の面に揃える。
