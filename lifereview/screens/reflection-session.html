振り返りセッション

週/月/年の共通フロー（最大5ステップ）。完了画面で星がひとつ灯る。

実装済 画面ID: LR-SESSION-01

目的・役割

「立ち止まり、見返し、言葉にする」体験をひとつの儀式として提供する中核画面。 週次・月次・年次で共通のフローを使い、期間・問い文言・ラベルを ReflectionType で切り替える。 完了時に ReflectionSession を SwiftData へ保存する。 ハイライトは ReflectionSession.highlightLogIds の単一管理で、 LogEntry 側には印を持たない（旧 isHighlight は削除済み）。

C案規律: セッション中（STEP1〜最終STEP）は星・グロー・絵文字を一切出さない。 完了画面でのみ星が1つ灯る（アプリで唯一許可する発光演出）。金は主 CTA の面と細罫に限る。

ステップ構成

step 値View内容
0ReflectionStepReview見返す。対象期間のログを日付グループで一覧表示（記録0件でも進行可能）
1ReflectionStepChoose選ぶ。心に残ったログを複数選択（任意）。記録0件の期間ではこの step を通らない
2ReflectionStepPrompts問い。種別ごとの3問を1問ずつ表示し自由記述で答える（空欄可・1問500文字まで）
3ReflectionStepMood総括。LogMood 5種から1つ選ぶ（未選択でも進める）
4ReflectionStepNote気づき（任意）。自由メモ（1000文字まで）→ 完了ボタン

ステップ数は5固定ではない（記録0件の分岐）: activeSteps は記録0件の期間で [0, 2, 3, 4]（4ステップ）、それ以外は [0, 1, 2, 3, 4]（5ステップ）。 「選ぶ」に何も並ばない空画面を通過させないため。next() / back() は activeSteps 上の位置で前後する。
STEP 番号は進行位置から動的に採番する: アイブロウの「STEP n」は各ステップ側に固定せず、activeSteps.firstIndex(of: step) + 1 から生成した stepLabel を親（ReflectionSessionView）が各ステップへ渡す。 プログレス表示（n/m）も同じ progressStep / activeSteps.count から作るため、両者が食い違わない。 古い下書きが飛ばすべき step（記録0件時の 1）を指していた場合は onAppear で step = 2 に補正する。

step 0（見返す）の一覧

  • ログを startOfDay でグループ化し、日付の降順で並べる。見出しは weekdayWideMD（例: 金曜日 6/15）を明朝12.5で表示。
  • 各行は共通の LogCardView（カテゴリ記号＋ラベル・感情アイコン・日付・本文2行・写真サムネイル）。
  • 記録0件のとき: 「この期間の記録はまだありません。／記録がなくても、今の気持ちから振り返れます。」

step 1（選ぶ）の一覧

  • 期間内のログを日付降順でフラットに並べ、行タップで highlightIds（Set<UUID>）をトグルする。
  • 行の1行目は「〔曜日略 M/d〕 ・ 〔カテゴリ名〕」、2行目は本文（本文が無い記録は「（カテゴリのみ）」）。
  • 選択時: 枠線 goldDim ・本文 moonWhite ・チェック（amber）。未選択時: 枠線 warmShadow ・本文 textBody。

step 2（問い）の進行

  • 3問を1問ずつ表示する。問いは「“」「”」だけ amber、本文 moonWhite の明朝20（lineSpacing 19＝読む速度を落とす余白）。
  • 入力欄は TextEditor（minHeight 112・プレースホルダ「ことばにならなくても、断片で。」）。フォーカス時は枠が goldDim。
  • 1問あたり500文字で切り詰める（onChange で prefix）。切り詰めた場合は onChange がもう一度走るので、確定はそちらに任せる。
  • 下部に進行ドット（現在 amber・他 warmShadow）と「問い 〔n〕 / 3 ・ 答えたいものだけで」。
  • 入力のたびに（打鍵ごとに）answers[index] へ確定する（onChange → commitCurrent()）。 「次の問いへ／戻る」まで未確定にしておくと、×で閉じたときに入力中の1問分がまるごと消え、 下書きにも hasAnyInput（中断アラートを出すかの判定）にも乗らない。2026-08-25 に是正。
  • 「次の問いへ」でも確定してから次の問いへ移り、最終問の「次へ」で step 3 へ進む（移動時の確定は残してある）。
  • 戻るボタンは、2問目以降なら前の問いへ、1問目なら前のステップへ戻る。

step 3（総括）／ step 4（気づき）

  • step 3 は LogMood.allCases の5件を縦に並べる。選択済みの項目を再タップすると nil に戻る（選び直し・取り消しが可能）。
  • step 4 の TextEditor は minHeight 150・プレースホルダ「この期間から、自分について気づいたこと。」・1000文字で切り詰め。
  • キーボードは step 2 / step 4 とも .scrollDismissesKeyboard(.interactively)（下方向のドラッグ）で閉じる。 記録フォームのようなツールバーの「完了」ボタンは意図的に置かない（問いに集中させるためボタンを増やさない）。

期間計算ルール

種別periodStartperiodEnd
weekly今日から6日前の startOfDay今日の 23:59:59

期間は init(type:) で確定し、そのまま @Query の filter に渡す。開いてから日をまたいでも期間は変わらない。

下書き保存（ReflectionDraftStore）

項目仕様
保存先端末内の UserDefaults。キーは種別ごと（reflectionDraft.weekly / .monthly / .yearly）。外部送信はしない。
保存内容ReflectionDraft（periodStart / step / highlightIds / answers / moodRaw / note）を JSON エンコード。
保存タイミングstep / highlightIds / answers / mood / note のいずれかが変わるたび（onChange）。step 2 の回答は打鍵ごとに answers へ入るので、下書きも打鍵ごとに更新される。完了画面（isCompletion）では保存しない。
空の下書きhasContent（選択・回答・感情・ノートのいずれかがある）が false なら保存せずキーを削除する。
復元init で読み込み、各 @State の初期値に流し込む。
期限切れ判定ReflectionDraftStore.isReusable(draftStart:periodStart:type:) で判定する。 週次は「対象期間が重なる（開始日のずれが6日以内）」なら再開可。7日ずれると重なりが無くなるので別の週として破棄する。 月次・年次は従来どおり同日一致（periodStart が月初／年初で固定のため、ずれ＝別の月・年）。破棄時はキーごと削除する。
週次だけ許容幅を持つ理由週次の対象期間は「今日−6日 〜 今日」のローリングで毎日動く。同日一致で判定していた頃は、 夜に保存した下書きが翌朝には別の期間とみなされて消えていた。中断 → 翌日に再開はいちばん自然な使い方なので、7日ぶんのずれまでを同じ週の続きとして扱う。
保存する periodStart初回保存時の値を保持し続ける（draftPeriodStart）。保存のたびに「今日」基準へ書き換えると、 6日以内に開き続けるかぎり下書きが無期限に前へスライドし、何週間も前の回答やハイライトが「今週の下書き」として残り続けてしまう。
破棄振り返りの保存に成功した時点で clear(type:)。

保存ロジック（finish）

  • 二重実行を isSaving で抑止し、実行中は主 CTA が ProgressView に切り替わる。
  • answers: 各問いの回答をトリムし、空でないものだけ ReflectionAnswer(prompt:answer:) に変換する（問い文面ごと保存）。
  • note: トリム後が空なら nil で保存。
  • highlightLogIds: highlightIds を配列化して保存。LogEntry 側は一切更新しない。
  • 同一期間（typeRaw 一致 かつ periodStart の差が1秒未満）の既存セッションがあれば上書き（upsert）し、無ければ新規 insert する。
  • 新規時のみ starSeq = 既存の最大 + 1 を採番する。上書き時は starSeq に触れないため、星の位置が変わらない。
  • 採番用のフェッチに失敗した場合は -1（未採番）を入れ、ReflectionSession.starIndex の id 由来フォールバックに任せる（0 を返すと既存の星と衝突するため）。
  • modelContext.save() が失敗したら rollback() して保存エラーアラートを出し、isSaving を戻して最終ステップに留まる。
  • 保存成功後に fetchCount(FetchDescriptor<ReflectionSession>()) で累計件数を取得（失敗時は 1 とする）→ 下書きを破棄 → 完了画面へ → onCompleted を呼ぶ。
  • ログは Logger(subsystem: "com.happyboy1002.LifeReview", category: "Reflection") に .error で記録する（print は使わない）。
同じ期間を再度振り返っても星は増えない: 同一期間の再実行は「前回を推敲する」ものとして上書きになる。 星が重複増殖しないことで「星＝振り返りの数」という意味構造の信頼性を守る。 上書き時に更新されるのは内容（periodEnd / moodSummary / answers / highlightLogIds / note）と completedAt で、 id / createdAt / starSeq は保持される。completedAt が更新されるため、ふりかえりホームの「前回から ○日」は再実行時点にリセットされる。

完了画面（ReflectionCompletionView）

要素内容
星120×120 の中に淡い既存星5点（固定座標）と、新しい星1つ（微光ブラー＋芯）。新星のみフェード＋上方8pxで灯る（easeOut 0.6秒）。Reduce Motion 時は最初から灯った状態。
見出し「振り返りを、／ひとつ積みました。」（明朝22・moonWhite・中央）
サブテキスト週次は「〔期間ラベル〕 の週」、月次・年次は期間ラベルそのまま。総括感情があれば「 ・ 総括「〔ラベル〕」」を続ける。改行して「これで 〔N〕回目 の振り返りです。」（回数のみ textBody・monospacedDigit）。
主ボタン「軌跡を見る　›」（LineButton・幅220・goldDim の細罫）
副ボタン「閉じる」（テキストのみ・textMuted）
非表示プログレスバーは出さない。リマインダー提案もここでは行わない（ホームへ戻ってから提案する）。

状態

状態表示・挙動
通常（step が activeSteps 内）プログレスバー表示。各ステップをフェード＋8pxオフセットで切替。
下書きありinit で step・選択・回答・感情・ノート・periodStart を復元して途中から再開する。
週次を翌日に再開下書きの periodStart が1日ずれていても期間が重なるため復元する（6日以内）。7日以上ずれた下書きは破棄して step 0 から始まる。
下書きが無効な step を指す記録0件の期間で step 1 が復元された場合、onAppear で step 2 に補正する。
保存中（isSaving: true）主 CTA が ProgressView になり、再タップしても finish() が走らない。
保存成功累計件数を取得し、下書きを破棄して完了画面（step 5）へ。onCompleted 発火。
保存失敗rollback() ＋「保存エラー」アラート。最終ステップに留まり、再試行できる。
中断（入力あり）×タップで中断アラート。「下書きを保存して閉じる」で dismiss（内容は端末内に残る）。
中断（入力なし）hasAnyInput が false なのでアラートなしで即 dismiss。
完了画面プログレスバー非表示。星のフェード演出。「軌跡を見る」「閉じる」のみ。

遷移

操作遷移
主 CTA（最終ステップ以外）next() → activeSteps 上の次の step へ
戻る（先頭ステップ以外）back() → activeSteps 上の前の step へ（step 2 では前の問いが優先）
主 CTA（step 4）finish() → 保存 → 完了画面（step 5）
×ボタン（入力なし）そのまま dismiss
×ボタン（入力あり）中断アラート →「下書きを保存して閉じる」で dismiss ／「続ける」で留まる
「軌跡を見る」（完了画面）dismiss したうえで onViewTimeline を呼ぶ（親がタイムラインへ push）
「閉じる」（完了画面）dismiss。呼び出し元の画面に戻る。

呼び出し元は2箇所。ふりかえりタブのリズムカード（onViewTimeline / onCompleted 付き）と、 これまでの軌跡（コールバックなし）。いずれも fullScreenCover(item:)。 interactiveDismissDisabled(true) でスワイプダウンを禁止し、必ず×ボタンの経路を通す。

使用するデータモデル

// 期間述語は init で確定（開いた後に日をまたいでもズレない）
@Query private var entries: [LogEntry]
_entries = Query(
    filter: #Predicate<LogEntry> { $0.date >= start && $0.date <= end },
    sort: [SortDescriptor(\.date, order: .reverse)]
)

// 進行状態
@State private var step: Int              // 下書きから復元
@State private var highlightIds: Set<UUID>
@State private var answers: [Int: String] // 問い index → 回答
@State private var mood: LogMood?
@State private var note: String

// 記録0件の期間は「選ぶ」を通らない
private var activeSteps: [Int] { entries.isEmpty ? [0, 2, 3, 4] : [0, 1, 2, 3, 4] }
private var progressStep: Int { activeSteps.firstIndex(of: step) ?? 0 }
private var stepLabel: String { "STEP \(progressStep + 1)" }

// 完了時（同一期間があれば上書き、無ければ挿入）
let session = ReflectionSession(
    type: type,
    periodStart: periodStart,
    periodEnd: periodEnd,
    moodSummary: mood,
    answers: savedAnswers,          // 空回答は除外
    highlightLogIds: ids,           // ハイライトの唯一の真実源
    note: trimmedNote.isEmpty ? nil : trimmedNote
)
session.starSeq = nextStarSeq()     // 新規のみ採番。上書き時は触らない
modelContext.insert(session)

アクセシビリティ対応

  • 閉じる（×）は 44×44 で .accessibilityLabel("振り返りを閉じる")。戻るは 52×52 で .accessibilityLabel("前へ戻る")。主 CTA は minHeight 52。
  • 本文・ラベルは scaledFont、見出し・問いは AppFont.mincho(_:relativeTo:) で Dynamic Type に追従する。.font(.system(size:)) の直書きはアイコン（SF Symbol）のみ。
  • 入力欄は固定高ではなく minHeight（問い112 / 気づき150）。文字を大きくしても入力欄が潰れない。
  • ハイライト行は選択時に .isSelected トレイトを付与し、チェック丸には「選択中」／「未選択」のラベルを持たせる。
  • 総括感情の各行は .accessibilityLabel(mood.label) ＋ 選択時 .isSelected トレイト。
  • 完了画面の星（LightingStar）は .accessibilityHidden(true)（装飾のため読み上げない）。
  • Reduce Motion 時はステップ遷移のアニメーションを行わず即座に切り替え、完了画面の星も最初から灯った状態で出す。
  • 進捗はプログレスバー右端の「n/m」テキストで示す（Capsule セグメント自体にはラベルを付けていない）。

実装メモ

  • ReflectionType が Identifiable なため、fullScreenCover(item:) で種別ごとに新しいインスタンスが生成される。
  • ステップ遷移の演出語彙はフェード＋上方8pxのみ（easeOut 0.35秒）。横スライドは手続き感が出るため使わない。
  • グレインは .grainOverlay() をセッションのルートに直接適用する（grainOverlay は子ビューへ継承されないため）。
  • 完了演出の星は、このアプリで唯一グロー（微光ブラー）を許可した表現。
  • Logger は private static let logger で宣言し、既存セッション照合・保存・件数取得・星の採番の各失敗を .error で記録する。
  • 星図側は starSeq を Halton(2,3) 低差異列で正規化座標に写して配置するため、件数や並び順が変わっても既存の星は動かない。
