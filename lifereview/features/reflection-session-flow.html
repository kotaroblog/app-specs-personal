振り返りセッション機能

起動から完了までの状態遷移・下書きの保存/復元/破棄・保存（upsert）とデータの流れ。

実装済 機能ID: LR-FEAT-SESSION

概要

LifeReview の中核機能。「立ち止まり、見返し、言葉にする」儀式を最大5ステップで提供し、 完了時に ReflectionSession を SwiftData へ保存する。 週次・月次・年次を ReflectionType で統一フローとして扱い、 期間計算・問い文言・ラベル表示だけを type に応じて切り替える。

本ドキュメントはフローと状態遷移・データの流れを扱う。 各ステップの画面構成・文言・配色は LR-SESSION-01 を参照。

関連画面

  • ふりかえりタブ（LR-S03） — 主たるセッション起動ポイント
  • 振り返りセッション（LR-SESSION-01） — 各ステップの画面仕様
  • これまでの軌跡（LR-TIMELINE-01） — 完了後の確認先／空状態からの起動ポイント

ステップ進行モデル

内部の step は 0〜4 の固定 ID（0=見返す / 1=選ぶ / 2=問い / 3=総括 / 4=気づき）で、 step >= 5（ReflectionSessionView.stepCount）が完了画面を意味する。 ユーザーに見える「STEP n」と進捗（n/m）は、この固定 ID ではなく 実際に通るステップの並び activeSteps の中での位置から作る。

対象期間の記録activeStepsプログレスの分割数ユーザーに見える番号
0件[0, 2, 3, 4]4見返す=STEP 1 / 問い=STEP 2 / 総括=STEP 3 / 気づき=STEP 4
1件以上[0, 1, 2, 3, 4]5見返す=STEP 1 / 選ぶ=STEP 2 / 問い=STEP 3 / 総括=STEP 4 / 気づき=STEP 5
記録0件の期間は「選ぶ」を飛ばす。 next() / back() は activeSteps 上の前後へ移動するため、0件なら STEP1「見返す」の次は「問い」になる。 番号を各ステップ側に固定するとアイブロウの「STEP n」とプログレス（n/m）が食い違うので、 親（ReflectionSessionView）が stepLabel を作って各ステップに渡す。 古い下書きが飛ばすべき step = 1 を指していた場合は onAppear で step = 2 に補正し、空の「選ぶ」画面を出さない。
関数挙動
next()activeSteps 上の次へ。末尾なら stepCount(=5) に移り完了画面へ。
back()activeSteps 上の前へ。先頭では何もしない（STEP1 に「戻る」は無い）。
go(to:)遷移の実体。Reduce Motion がオンなら即時、オフなら .easeOut(duration: 0.35)。演出はフェード＋上方8pxのみ（横スライドは使わない）。

STEP3「問い」だけは内部にさらに問い単位のカーソル（index）を持ち、3問を1画面で送る。 最終問での「次へ」で STEP4 に進み、最初の問いでの「戻る」で STEP2（または STEP1）へ戻る。 回答は打鍵のたびに answers[index] へ確定し、問いの移動時にも確定する（移動まで未確定だと、×で閉じたときに入力中の1問分が消える）。

下書き（中断と再開）

中断は「破棄」ではなく「下書き保存」。ReflectionDraftStore が端末内（UserDefaults）に reflectionDraft.<type.rawValue> のキーで種別ごとに1件だけ保持する（週・月・年で最大3件）。外部送信はしない。

タイミング処理
保存step / highlightIds / answers / mood / note のいずれかが変わるたび saveDraft()。STEP3 の回答は打鍵ごとに answers へ入るため、下書きも打鍵ごとに更新される。完了画面に入った後（isCompletion）は保存しない。
空の下書きReflectionDraft.hasContent が false（選択・回答・感情・ノートがすべて空）なら保存せずキーを削除する。書いた内容を消してから閉じれば下書きも残らない。
復元init(type:) 内で load(type:periodStart:)。デコードできて isReusable(draftStart:periodStart:type:) が true なら、step と periodStart を含めて全項目を復元する。
再利用の判定週次は開始日のずれが6日以内（＝対象期間が重なる）なら再開可。7日ずれると重なりが無くなるので別の週として扱う。月次・年次は同日一致（periodStart が月初／年初で固定のため、ずれ＝別の月・年）。
期限切れ上の判定に外れた下書きは読み込まずキーごと削除する（古い期間の入力を新しい期間に持ち込まない）。
下書きの periodStart初回保存時の値を保持する（draftPeriodStart）。保存のたびに「今日」基準へ書き換えると、6日以内に開き続けるかぎり下書きが無期限に前へスライドし、何週間も前の入力が「今週の下書き」として生き残る。この固定値は下書き専用で、完了保存する ReflectionSession.periodStart にはセッション自身の（今日基準の）periodStart を使う。
破棄完了保存に成功した時のみ clear(type:)。保存失敗時は下書きを残す。
種別periodStart下書きが再開できる範囲
weekly今日−6日の 0:00中断から6日以内（期間が重なるあいだ。中断して翌日に再開できる）
monthly今月の 1日 0:00同じ月のあいだ
yearly今年の 1/1 0:00同じ年のあいだ

× を押したときの分岐は hasAnyInput（ハイライト選択あり／空白でない回答あり／感情選択あり／空白でないノートあり）で決まる。 true ならアラート「振り返りを中断しますか？」（選択肢は「続ける」／「下書きを保存して閉じる」）、false なら確認なしで閉じる。 下書きの書き込み自体はアラートより前に済んでいるため、アラートは同意の確認であって保存の実行契機ではない。

完了時の保存（upsert）

sequenceDiagram participant U as ユーザー participant S as ReflectionSessionView participant C as ModelContext participant D as ReflectionDraftStore U->>S: 最終ステップの CTA S->>S: isSaving を立てる（二重送信防止） S->>S: answers を trim して空を除外 → [ReflectionAnswer] S->>S: note を trim（空なら nil） S->>C: typeRaw 一致のセッションを fetch C-->>S: 同期間（periodStart の差 1秒未満）の1件 or なし alt 既存あり S->>C: periodEnd / moodSummary / answers / highlightLogIds / note / completedAt を更新 Note over S,C: starSeq は据え置き（星は動かず増えない） else 既存なし S->>S: nextStarSeq() で採番 S->>C: ReflectionSession を insert end S->>C: save() alt 成功 S->>C: fetchCount で累計件数を取得 S->>D: clear(type:) S->>S: step = 5（完了画面） S-->>U: 星がひとつ灯る（0.6s ease-out） S->>S: onCompleted?() else 失敗 S->>C: rollback() S-->>U: 「保存エラー」アラート Note over S: isSaving を戻し STEP5 に留まる（下書きは残る） end
同じ期間をもう一度振り返ったら「上書き」。 種別が同じ かつ periodStart の差が1秒未満のセッションが既にあれば、新規挿入せず内容を更新する。 「同じ週をもう一度振り返る＝前回を推敲する」であり、星が重複増殖すると「星＝振り返りの数」という意味が壊れるため。 completedAt は更新されるので、ホームの「前回から ○日」と軌跡の並び順は最新に追従する。
ケース結果
同じ日に週次を2回periodStart が同一 → 上書き（星は増えない）
翌日に週次をもう一度periodStart が1日ずれる → 新規（星がひとつ増える）
同じ月に月次を複数回periodStart が月初で同一 → 上書き
同じ年に年次を複数回periodStart が元日で同一 → 上書き

starSeq の採番

  • 新規挿入時に nextStarSeq() ＝ 既存 starSeq の最大値 + 1 を一度だけ与え、以後変えない。
  • 星図（StarMapView）は ReflectionSession.starIndex だけから座標を決める。index + 1 を Halton(2, 3) 低差異列に通し、Canvas サイズに対する正規化座標へ写す。件数・並び順・他の星の増減・Canvas 高さから独立しているため、振り返りを積んでも既存の星は動かない。
  • 採番のための fetch に失敗した場合は -1（未採番）を保存する。starIndex は id のバイト列由来の決定論的な値（先頭8バイト % 4096）にフォールバックする。0 を返さないのは、既存の星と位置が衝突するため。

ハイライト（highlightLogIds）の流れ

  • STEP2 の選択は Set<UUID> として保持し、完了時に Array にして ReflectionSession.highlightLogIds へ書き込む。これがハイライトの唯一の真実源で、LogEntry 側に印は持たない（旧 LogEntry.isHighlight は削除済み）。
  • 上書き（upsert）時は highlightLogIds を今回の選択で置き換える（マージしない）。
  • 表示側は resolvedHighlightLogs(from:) で現存ログとの照合を通す。存在しない id は無視され、クラッシュも空行も出ない。
  • 件数は survivingHighlightCount(in:) ／ TimelineTally(sessions:existingLogIds:) を通して実体ベースで数える。highlightLogIds.count を直接使うと、元の記録を削除したあとも数字が減らず詳細画面と食い違う。
  • 記録の削除時（LogDetailView）は、削除前に全セッションの highlightLogIds からその id を外す（cascade cleanup）。表示側でも生存照合しているため二重の備えだが、参照を残すと「消えた記録の id」が永久に溜まるので発生源で断つ。掃除に失敗しても削除自体は続行する。

完了後の遷移

操作・契機処理
onCompleted?()（保存成功時）ReflectHomeView が justCompleted = true を立てる。中断では呼ばれない。
完了画面「軌跡を見る」dismiss() してから onViewTimeline?()。親が navigateToTimeline = true にし、navigationDestination(isPresented:) で ReflectionTimelineView を push する（ネストした NavigationStack を避けるため）。
完了画面「閉じる」dismiss() のみ。
ホームへ戻った時（sessionType == nil）justCompleted が true なら false に戻し、hasOfferedReminder == false かつ reminderEnabled == false のときだけリマインダー提案カードを表示する。完了画面の上では提案しない。

期間計算ロジック

flowchart TD A["ReflectionType"] -->|weekly| B["periodStart = 今日−6日 の 0:00
periodEnd = 今日 23:59:59"] A -->|monthly| C["periodStart = 今月1日 0:00
periodEnd = 今日 23:59:59"] A -->|yearly| D["periodStart = 今年1月1日 0:00
periodEnd = 今日 23:59:59"]
  • 期間は init(type:) 時に確定する。セッションを開いたまま日付が変わっても期間は変わらない。
  • @Query の述語は date >= periodStart && date <= periodEnd、並びは date の降順。STEP1・STEP2 はこの同じ配列を共有する。
  • 年次でも periodEnd は「今日の 23:59:59」であり 12/31 ではない。まだ来ていない日を対象に含めない。

ビジネスルール

  • 周期は強制しない。「やりたい時に」できる設計。ホームは前回からの経過日数と「そろそろ」バッジ（最優先の1枚のみ）で静かに促すだけ。
  • 記録0件の期間でも振り返れる（「今週は記録が少なかった」も気づき）。0件のときは STEP1 の CTA が「問いから始める ›」になり、「選ぶ」を飛ばす。
  • 各入力（ハイライト選択・問い回答・感情・メモ）はすべて任意。ひとつも入力せず完了してもよい。CTA は入力状態に応じて「選ばずに進む ›」「このまま終える ✓」等に変わる。
  • 回答は前後の空白を除去し、空になったものは保存しない（answers に含めない）。
  • ノートは前後の空白を除去し、空なら nil で保存する。
  • 入力長は問いの回答が 500 文字、ノートが 1000 文字で頭打ち（超過分は入力時点で切り捨て）。
  • 保存は isSaving フラグで二重送信を防ぐ。処理中は主ボタンが ProgressView に変わる。
  • 感情はもう一度タップすると選択解除（nil）に戻せる。

エラー処理

発生条件対応
modelContext.save() が throwLogger.error → rollback() で挿入・更新を巻き戻す → 「振り返りを保存できませんでした。もう一度お試しください。」のアラート → isSaving を戻して STEP5 に留まる。下書きは消さないので再試行で失われない。
既存セッション照合の fetch が失敗Logger.error。existing = nil として新規挿入で続行する（振り返りを落とさないことを優先）。
nextStarSeq() の fetch が失敗Logger.error。-1（未採番）で保存し、星図では id 由来の決定論的な座標にフォールバックする。
累計件数の fetchCount が失敗Logger.error。completedCount = 1 にフォールバック。保存自体は成功しているので完了画面はそのまま出す。
下書きのデコードに失敗下書きなしとして扱い、step = 0 から開始する（例外は投げない）。
記録削除時のハイライト掃除に失敗Logger.error。記録の削除自体は続行する。件数表示は生存照合なので数字は狂わない。

実装メモ

  • ReflectionType: Identifiable（id = rawValue）。.fullScreenCover(item: $sessionType) で型安全に種別ごとのセッションを起動する。
  • 問い（prompts）は ReflectionPrompts.forType(type) で取得するコード定数テーブル。多言語化の余地を残して一箇所に集約している。
  • セッション中の answers は [Int: String]（prompts のインデックスをキー）で保持し、完了時に [ReflectionAnswer]（prompt 文字列＋回答）へ変換して保存する。問い文言を後から変えても、保存済みの振り返りには当時の問いが残る。
  • セッション画面はナビゲーションバーを持たないため、共通の screenBackground() ではなく自前の ZStack ＋ grainOverlay() を使う。ステップ切り替えは .id(step) ＋ .transition(.opacity.combined(with: .offset(y: 8)))。
  • キーボードは STEP3・STEP5 とも .scrollDismissesKeyboard(.interactively) の下方向ドラッグで閉じる。ツールバーの「完了」ボタンは意図的に置いていない（問いに集中させ、ボタンを増やさない）。
  • 本文・ラベルは scaledFont、見出しと問いは AppFont.mincho(_:relativeTo:) で Dynamic Type に追従。テキストエディタは固定高ではなく minHeight。
  • Reduce Motion がオンのときは、ステップ遷移も完了画面の星もアニメーションせず最終状態で表示する。
  • プログレスバーの × は 44×44、accessibilityLabel("振り返りを閉じる")。完了画面の星は装飾なので accessibilityHidden(true)。
