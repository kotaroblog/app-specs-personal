UserProfile

ユーザープロフィール（常に1件のみ存在）。生年月日と目標年齢から残り時間・週グリッドを計算する。

@Model
final class UserProfile {
    var id: UUID = UUID()
    /// 生年月日
    var birthDate: Date = Date()
    /// 目標年齢（人生の終端として扱う想定年齢）
    var targetAge: Int = 80
    var createdAt: Date = Date()
}

// 計算 extension（UserProfile+Life.swift）
extension UserProfile {
    var targetDate: Date                                  // 誕生日 + targetAge 年後の同月日
    func remaining(from:) -> TimeInterval                 // 残り秒数（過ぎていたらゼロ）
    func progress(from:) -> Double                        // 進捗率 0.0〜1.0
    func remainingYearsMonths(from:) -> (years: Int, months: Int)
    var totalWeeks: Int                                   // targetAge × 52
    func elapsedWeeks(from:) -> Int                       // 経過週数
    func currentAge(from:) -> Int                         // 現在年齢

    // ↓ 2026-07-26 追加
    static func age(of birthDate: Date, at now: Date = Date()) -> Int
    static func isValidTargetAge(_ targetAge: Int, birthDate: Date, now: Date = Date()) -> Bool
}
目標年齢バリデーションの集約（2026-07-26）: 「目標年齢は現在の年齢より大きい」という規則を、オンボーディング・目標年齢シート・生年月日シートの3画面が個別に書いていた。 生年月日シートだけ書き忘れがあり、そこからだけ「残り 0年0ヶ月・進捗100%」で固まる状態を作れた。 判定を UserProfile.isValidTargetAge(_:birthDate:now:) に集約し、画面が増えても同じ規則を共有できるようにした。 now: を注入できるため、テストが実行日に依存しない。
  • UserProfile は常に1件のみ。オンボーディング完了時に1件 insert し、以降は更新のみ。
  • 設定「全データを削除」で削除後、onboardingCompleted = false にしてオンボーディングへ戻す。

配色を「輝度の階段」へ再設計（2026-07-26）
旧仕様の原色パレット（experience #EA580C / relationship #DB2777 / creation #7C3AED / anxious #9333EA 等）は C案「ダーク天体」の禁止色（原色・紫・マゼンタ）に真っ向から反していたため和色系へ差し替え済みだったが、 そのとき彩度だけでなく明度まで揃えてしまい、8色が輝度 0.249〜0.395 の狭帯に密集していた。 全28ペアのどれもコントラスト比 1.5:1 に届かず、experience × creation は輝度差 0.0003 で実質同一色だった。
  • 識別は色相差＋OKLab 明度 0.80→0.52 の8段階段で行う（彩度を上げて買い戻さない）。
  • 彩度は金 #C2894B（OKLCH C=0.105）より必ず低く保つ。金がこのアプリで最も彩度の高い色という序列を崩さないため。
  • 低彩度の代償は二次符号が支払う: 円グラフの隙間・凡例・内訳リストの件数表示。
  • LogMood の tired は以前 #8E8B84 で LogCategory.other と16進が完全一致していた。積み上げ棒グラフは凡例が別置きで、帯の輝度差だけが対応付けの手がかりになるため青寄りの薄鈍に分けた。
  • チップ等の文字色にはカテゴリ色を使わない（焦香など暗い色が night2 の面で本文可読性に届かないため）。識別は色罫＋不透明度 0.14 の面が担い、文字は月白で読ませる。

ReflectionSession

完了した振り返りセッション（週次・月次・年次共通）。蓄積されたこれ自体がアプリ固有の価値資産になる。

@Model
final class ReflectionSession {
    var id: UUID = UUID()
    /// 種別（rawValue で保存）— weekly / monthly / yearly
    var typeRaw: String = ReflectionType.weekly.rawValue
    var periodStart: Date = Date()
    var periodEnd: Date = Date()
    /// 期間の総括感情（任意・rawValue で保存）
    var moodSummaryRaw: String?
    /// 静かな問いへの回答（[{prompt, answer}]）
    var answers: [ReflectionAnswer] = []
    /// ハイライトに選んだ LogEntry の id 集合（ハイライトの唯一の真実源）
    var highlightLogIds: [UUID] = []
    /// 気づき・自由記述（任意）
    var note: String?
    /// 星図での位置を決める採番（-1 = 未採番）
    var starSeq: Int = -1
    var completedAt: Date = Date()
    var createdAt: Date = Date()

    // 導出
    func resolvedHighlightLogs(from candidates: [LogEntry]) -> [LogEntry]
    var starIndex: Int
    func survivingHighlightCount(in existingLogIds: Set<UUID>) -> Int
}

starSeq / starIndex（2026-07-26 追加）

以前は配列インデックスから星の座標を決めていたため、振り返りを1件追加するだけで （並び順が繰り上がり）既存の星が全部動いていた。「振り返った夜の数だけ星が灯る」という約束を守るには、 星が自分の場所を持っている必要がある。
項目仕様
採番タイミング新規セッションの insert 時に一度だけ（既存 starSeq の最大 + 1）。以後変えない。
採番失敗時fetch 失敗時は -1 を返す（0 を返すと既存の星と衝突するため）。
starIndex採番済みならその値。未採番（-1）なら id のバイト列先頭8バイトから決定論的に導く（% 4096）。
UUID.hashValue を使わない理由プロセスごとにシードが変わるため、起動ごとに星が動いてしまう。
同一期間の再振り返り同じ種別＋同じ periodStart（1秒未満の差）の既存セッションがあれば上書きする。星が重複増殖せず「星＝振り返りの数」の意味構造が保たれる。上書き時は採番し直さない。

survivingHighlightCount（2026-07-26 追加）

件数表示に highlightLogIds.count を直接使うと、元の記録を削除したあとも数字が減らず、 詳細画面（resolvedHighlightLogs 経由）と食い違う。表示は必ずこちらを通す。 

func survivingHighlightCount(in existingLogIds: Set<UUID>) -> Int

削除済みログ参照の扱い（二段構え）

層担当内容
発生源で断つLogDetailView.delete()記録の削除時、その id を参照している全 ReflectionSession の highlightLogIds から取り除く（cascade cleanup）。掃除に失敗しても削除自体は続行し、Logger にのみ記録する。
表示側で照合survivingHighlightCount / resolvedHighlightLogs存在しない id は無視する。掃除が漏れてもクラッシュ・数字のズレを起こさない。

ReflectionDraft / ReflectionDraftStore（端末内下書き）

完了前の振り返りを退避する軽量な下書き。SwiftData ではなく UserDefaults（JSON エンコード）に保存する。

struct ReflectionDraft: Codable, Equatable {
    var periodStart: Date
    var step: Int
    var highlightIds: Set<UUID>
    var answers: [Int: String]
    var moodRaw: String?
    var note: String
}

@MainActor enum ReflectionDraftStore {
    static func load(type:periodStart:defaults:) -> ReflectionDraft?
    static func save(_:type:defaults:)
    static func clear(type:defaults:)

    // 下書きを再利用してよいかの判定（週次だけ 6 日のずれを許容）
    private static func isReusable(draftStart:periodStart:type:) -> Bool
}
// キー: "reflectionDraft.{weekly|monthly|yearly}"
  • 種別ごとに1件。再利用の可否は isReusable(draftStart:periodStart:type:) で決める。 週次は開始日のずれが6日以内（＝対象期間が重なる）なら再開可、月次・年次は同日一致。外れた下書きは読み込まずキーごと破棄する。
  • 週次だけ許容幅を持つ理由: 週次の periodStart は「今日−6日」で毎日動くローリング。同日一致で判定すると、 夜に保存した下書きが翌朝には消える（中断 → 翌日再開が壊れる）。
  • 保存する periodStart は初回保存時の値で固定する（ReflectionSessionView.draftPeriodStart）。 保存のたびに今日基準へ書き換えると、6日以内に開き続けるかぎり下書きが無期限に前へスライドしてしまう。 この固定値は下書き専用で、完了保存する ReflectionSession.periodStart にはセッション自身の periodStart を使う。
  • 内容が空（hasContent == false）なら保存せずクリアする。
  • セッション完了時と「全データを削除」時に全種別をクリアする。

Relation

大切な人（家族・友人など）。残り会える回数を見積もる対象。

@Model
final class Relation {
    var id: UUID = UUID()
    /// 名前（必須）
    var name: String = ""
    /// 続柄（父・母・親友など・任意）
    var relation: String?
    /// 生年月日（任意）
    var birthDate: Date?
    /// 想定の終端年齢（既定: 80）
    var targetAge: Int = 80
    /// 年あたりに会える回数（既定: 1・編集シートの初期値は 2）
    var meetingsPerYear: Int = 1
    var createdAt: Date = Date()
}

// 算出 extension（Relation+Life.swift）
extension Relation {
    func currentAge(from now: Date = Date()) -> Int?          // 生年月日未設定なら nil
    func remainingMeetings(from now: Date = Date()) -> Int?    // max(0, targetAge - age) × meetingsPerYear
    static func isValidTargetAge(_ targetAge: Int, birthDate: Date?, now: Date = Date()) -> Bool
}
破壊的変更: currentAge: Int? → birthDate: Date?（2026-07-26）
「現在の年齢」を Int で保存していたため、登録した瞬間の年齢が固定され、1年経っても「あと○回」が減らなかった—— この機能の価値そのものが時間とともに嘘になる。UserProfile と同じく生年月日を持ち、 年齢・残り回数は暦から毎回算出する方式に変更した。算出は Relation+Life.swift に分離（UserProfile / UserProfile+Life と同じ分け方）。
  • 生年月日が未設定なら残り回数は表示せず「年○回」のみ表示する（RelationRow）。
  • isValidTargetAge は生年月日が未設定なら常に true（検査対象が無いため）。
  • meetingsPerYear の範囲: 1〜365。想定年齢の範囲: 1〜120（数値入力 + Stepper 併用）。
  • 一覧のフッターに算出根拠を明記する: 「『あと○回』は、生年月日・想定年齢・会う頻度から算出した目安です。」

マイグレーション方針

SwiftData の @Model は全プロパティにデフォルト値必須。新規プロパティ追加時は必ずデフォルト値を設定する。
  • v1.0.0 は未リリースのため、2026-07-26 のスキーマ変更（LogEntry.isHighlight 削除・Relation.currentAge → birthDate・ReflectionSession.starSeq 追加）は MigrationPlan を用意せず破壊的変更として実施した。実機で旧データを持つのは開発端末のみ。
  • starSeq: Int = -1 のデフォルトは「未採番」を意味する。仮に採番されていないデータが混ざっても starIndex の id 由来フォールバックが位置を決めるため、星が消えたり原点に重なったりしない。
  • リリース以降にスキーマを変える場合は VersionedSchema + SchemaMigrationPlan を必ず実装する。
