オンボーディング

3頁で価値を伝えて、そのままホームへ送り出す

設計確定・実装未着手 画面ID: PD-15

目的・役割

初回起動時の3頁ウォークスルー。BB収支・弱点タグ・週次レビューという3つの核となる価値を順に伝え、最終頁の単一CTA「はじめる」でホームへ送り出す。オンボーディングでは通知許可を求めず、完了時にPaywallも自動提示しない。初回体験の目的を「価値の理解」だけに絞り、許可要求と課金訴求はどちらも後続の文脈（設定タブ・利用上限到達時）に委ねる。

初回体験から要求を外す。 通知許可ダイアログと source=onboarding のPaywall自動提示は、いずれもアプリの価値を体験する前にユーザーへ判断を求めるものだった。両方を廃止し、週次レビュー通知は設定タブのトグルから、Proの訴求は利用上限・分析ロック等の文脈付き導線からのみ提示する設計に変更した。

UI 構成

頁テーマ内容
①BB収支の価値訴求「アミュ帰りの10秒で、今夜の収支を」。チップIN/OUTからBB収支を自動換算・円のプラマイに縛られない
②弱点タグ＝負け筋の言語化「気になった1手が、負け筋の言葉になる」。弱点タグで記録するほど負けパターンが見える
③週次レビュー「日曜夜、5分の振り返り」。単一CTA「はじめる」＋補足文「日曜21:00の通知は、設定タブからいつでもONにできます。」（この画面では通知許可を求めない）
—共通ステップドット・スキップ（頁①②のみ表示）。各頁はスクロール可

状態

状態表示内容
頁①②「次へ」で進行。スキップを表示
頁③（最終）単一CTA「はじめる」＋通知の案内文のみ。スキップは非表示（2択を置かない）
完了hasCompletedOnboarding を保存し、そのままホームへ。Paywallも通知ダイアログも挟まない
大きな文字サイズ各頁がスクロール可のため、見出し・説明文が切れずに読める

遷移

操作遷移先
「次へ」タップ次頁
スキップ タップ（頁①②）オンボーディング完了処理へ
「はじめる」タップ（頁③）オンボーディング完了処理へ
完了ホーム（PD-01）。Paywallは経由しない
（後日）週次レビュー通知をON設定タブのトグル（PD-16）から許可を要求

使用するデータモデル

// SwiftDataモデルは持たない。初回起動フラグは UserDefaults（AppStorage）で管理
// hasCompletedOnboarding: Bool
// 通知許可（UNUserNotificationCenter）はこの画面では扱わない → 設定タブ（PD-16）

KPI イベント

イベントパラメータ目的
onboarding_completedなし初回体験の到達率。「はじめる」またはスキップで発火し、通知許可の有無に依存しない

実装メモ

  • この画面では通知許可を求めない。週次レビュー通知は設定タブのトグルからONにする（既存導線・変更なし）。既定は日曜21:00
  • 完了時にPaywallを自動提示しない（source=onboarding の自動提示は廃止）。hasCompletedOnboarding を保存してそのままホームへ遷移する
  • 最終頁は単一CTA「はじめる」のみ。2択（許可／あとで）を置かず、迷いを作らない
  • スキップは頁①②のみ表示。VoiceOverヒントで「オンボーディングを終了してホームへ移動します」旨を補う
  • 各頁は ScrollView 内に配置し、アクセシビリティ文字サイズでも見出し・説明文が切れない
  • 完了判定と永続化は OnboardingFlowModel（shouldPresentOnboarding / complete()）が担う。View側にフラグ操作を散らさない
