収支記録シート

リング／トナメ2モードの10秒収支入力（習慣の錨）

設計確定・実装未着手 画面ID: PD-02

目的・役割

アミュ帰りの10秒で「今夜の収支」を残すための中核入力シート。リング＝チップIN／OUTからBB収支をライブ換算、トナメ＝結果とプライズ内容を記録する。円は「支出（娯楽費）」のみを扱い、プラマイ収支・円換算・ROIは記録しない（2レイヤー収支・4+整合）。このシートは習慣の錨であり、どの経路でも永久無料でPaywallに阻まれない。

UI 構成

共通

要素種類説明
ナビバーNavigationタイトル（新規=「今夜を記録」／編集=「セッションを編集」）＋キャンセルのみ。日付ピッカーはナビバーに置かない（タイトルとの横並び競合を解消）
日付DatePicker（compact）フォーム最上部の行。カード内に配置し最小高44ptを確保する
モードセグメントSegmented Controlリング／トナメの切替。前回使用モードを記憶して初期選択する
店選択チップChip（横スクロール）店名サジェスト（使用頻度順）＋「＋新規」。選択済みはアクセント塗り。選択は任意
保存できない理由Inline Caption保存条件を満たさないとき、保存ボタン直上に1行表示（例: チップINを入力してください）
保存ボタンPrimary ButtonSession を保存し、成功時のみ記録完了画面（PD-03）へ。条件未満は無効化

リングモード

要素種類説明
ステークスチップChipその店の最新Sessionから前回値をクエリ導出して先頭表示（例: 2/5）。他候補も併置
チップINField + Keypad持ち込みチップ（点）。店の前回値をデフォルト
チップOUTField + Keypad終了時チップ（点）。アクティブ入力対象
BB収支ライブ換算Result Card（緑/テラコッタ）chipProfit / bbChips を即時換算表示（例: +200 BB）。補助表記「+1,000点 @2/5（1BB=5点）」
参加費（円）Field（任意）娯楽費として任意入力（例: ¥3,000）→ spentYen

トナメモード

要素種類説明
エントリー費（円）Field1エントリーあたりの費用（娯楽費）
エントリー数Stepperリエントリーを含むエントリー数（buyInCount）
結果Segmented Controlバスト／ITM／優勝の3択（resultRaw = busted / itm / won）
プライズ内容Text Field入賞時のみ表示。テキスト記録（例: リングチップ50,000点）→ prizeNote

保存条件（バリデーション）

形式最低条件意図
リングBB（bbChips）≧ 1 かつ チップIN ≧ 1BB収支の換算が成立する最小条件。チップOUT = 0 は正当な記録として許可する（全額失った夜を記録できないのは誤り）
トナメエントリー数 ≧ 1 かつ 参加費・支出合計・結果・プライズメモのいずれかに入力あり参加費0のフリーロールでも結果を選ぶだけで保存できるようにする。一方で完全な空レコードは作らせない
共通店の選択は任意店を思い出せない・登録していない夜でも記録を止めない
条件を満たさない間は保存ボタンを無効化する。 無効状態は背景 surfaceElevated＋枠線＋文字色 textSecondary＋警告アイコンで表現し（「押せそうなのに押せない」を避ける）、保存できない理由を1行だけボタン直上に表示する。同じ文をVoiceOverヒントにも設定し、視覚に頼らず理由が伝わるようにする。
編集モードの緩和は「その形式に限って」適用する。 既存データが現在の最低条件を満たしていない場合（旧バージョンで作られた記録など）、そのままでは編集画面から保存できなくなる。そこで編集時は元データの形式に限り条件を緩める。ユーザーがシート内で形式を切り替えた場合は、切り替え後の形式には通常条件を適用する（緩和を横に広げない）。

状態

状態表示内容
リング初期前回使用モードがリングなら初期表示。店・ステークス・チップINは前回値をプリセット
トナメ初期前回使用モードがトナメなら初期表示。結果未選択・プライズ欄は非表示
入賞（ITM/優勝）選択時プライズ内容テキスト欄を表示する
BB収支換算中（リング）チップIN/OUTとステークスが揃った時点で緑（勝ち）／テラコッタ（負け）カードにライブ換算を表示
新規店「＋新規」から店名を追加し Venue を作成
保存条件 未達保存ボタンを無効表示（surfaceElevated＋枠線＋textSecondary＋警告アイコン）。直上に理由を1行表示
保存失敗記録完了画面へ遷移せず、入力内容を保持したまま日本語Alert「保存できませんでした」を表示（詳細はエラー設計）
編集モード（旧データ）元データの形式に限り保存条件を緩め、過去の記録を保存不能にしない

遷移

操作遷移先
保存する タップ（保存成功時のみ）記録完了画面（PD-03）
保存する タップ（保存失敗時）遷移しない。記録シートにとどまり Alert を表示（入力は維持）
キャンセル タップホーム（PD-01）へ戻る
リング／トナメ セグメント切替同一シート内でモード切替

使用するデータモデル

Session   // gameTypeRaw（ring/tournament）
          // リング: chipIn / chipOut / sbChips / bbChips / durationMinutes(任意)
          //         computed chipProfit = chipOut - chipIn / bbProfit = chipProfit / bbChips
          // トナメ: buyInCount / resultRaw(busted/itm/won) / prizeNote
          // 共通: spentYen（娯楽費）/ venue / date
Venue     // name（店選択・前回値クエリの起点）

KPI イベント

イベントパラメータ目的
session_loggedgame_type, has_duration, venue_is_new錨行動の頻度（最重要リテンション指標）。金額・店名は含めない

実装メモ

  • 10秒入力が守るべき錨 — 入力ステップ数・タップ数を最小化し、前回値プリセットで実質「確認＋OUT入力」で完結させる
  • 収支入力はPaywallに阻まれない — このシートは永久無料。課金導線をこの画面のコア入力に挟まない
  • 店の「前回ステークス・前回チップIN」はその店の最新Sessionからクエリ導出（Venueに非正規化しない）
  • BB収支換算は bbChips > 0 のときのみ算出（0除算回避、bbProfitはOptional）
  • トナメの円換算・ROIは意図的に非実装。プライズは金銭換算せずテキストのみ（4+・賭博性の否定）
  • KPIのパラメータに金額・店名・自由記述を含めない（件数・真偽値・enum値のみ）
  • 日付はナビバーではなくフォーム最上部の行に置く（compact DatePicker・最小高44pt）。ナビバーはタイトル＋キャンセルのみとする
  • 保存できない理由はインライン表示とVoiceOverヒントの二重で伝える。ボタンを無効化するだけで理由を隠さない
  • 保存の成否で遷移を分ける — session_logged の発火と PD-03 への遷移は保存成功時のみ。失敗時は入力を維持して Alert 表示にとどめる
  • バリデーションは save() 内でも再検査し、条件未達なら SwiftData に触れる前に SessionEntrySaveError.invalidInput を throw する（空記録を作らない保証を View の disabled だけに依存させない）
