エラー設計・例外パターン一覧

例外の分類とユーザーへの提示方針。「記録したつもりが消えている」状態を作らないことが最優先

基本原則

保存が成功しない限り、次の画面へ進めない。 記録系シート（収支記録 PD-02 / ハンド簡易記録 PD-04 / クイックメモ PD-05）は保存成功時のみ遷移・シートを閉じる。 失敗時は入力値と画面をそのまま維持し、日本語のアラートで知らせる。

エラー分類の方針

  • 入力エラー（ビジネス）: 最低入力条件を満たさない。保存ボタンを無効化し、理由をインラインで提示する（アラートは出さない）
  • 永続化エラー（システム）: SwiftData の保存失敗。今回の変更のみを打ち消し、アラートで再試行を促す
  • 課金エラー: StoreKit の購入・復元失敗。アラートで結果を伝える（内部ロジックの詳細は本書では扱わない）
  • 権限エラー: 通知許可の拒否。設定タブのトグルを自動でOFFに戻し、強制も再要求もしない
  • 本アプリはローカル完結（SwiftData）のためネットワークエラーは課金・レンジデータ以外に存在しない

保存失敗時の巻き戻し方針

ModelContext.rollback() は使わない。 画面は共有の mainContext を使うため、rollback は今回の保存対象だけでなく 同じコンテキストにある無関係な未保存変更まで巻き戻してしまう。 そのため「今回の変更のみ」を個別に打ち消す。
経路失敗時の打ち消し方法
収支記録（新規）insert した Session を delete。今回新規作成した店（Venue）も delete（既存店を選択していた場合は何もしない）
収支記録（編集）書き換えるフィールドを事前にスナップショットし、失敗時にその値へ戻す（日付・形式・店・支出・チップIN/OUT・ステークス・エントリー数・結果・プライズ）
ハンド簡易記録（新規）insert した Hand を delete
ハンド簡易記録（編集・下書き昇格）スナップショットから復元（entryMode が quick に戻り、昇格しない）
クイックメモinsert した Hand を delete
  • KPIイベントは保存成功時のみ発火する（session_logged / hand_logged）。失敗時に記録数が過大計上されない（→ロギング方針）
  • 既知の制約: 本番の mainContext は autosave が有効なため、明示保存より前に autosave が走っていた場合「保存失敗＝何も永続していない」は厳密には保証されない

入力バリデーションの方針

  • 保存条件は ViewModel の canSave / validationMessage に集約し、保存ボタンの無効化と理由表示の両方に同じ値を使う
  • 無効状態は色だけで表さない。枠線・アイコン・ボタン直上の理由テキスト・VoiceOverヒントで伝える
  • save() 自体も SwiftData に触れる前に条件を検査して throw する。空記録を作らない保証を View の .disabled だけに依存させない
  • 編集モードの緩和: 過去に保存された不完全なデータを「保存できない記録」にしないため、元データが最低条件未満の場合はその形式に限って条件を緩める。形式を切り替えた場合は通常条件を適用する

Swift エラー型の方針

throws を統一して使用。コールバックでのエラー返却は禁止（CLAUDE.md準拠）。 ViewModel の save は成功時に対象モデルを返し、失敗時は throw する。 
/// 収支記録の保存を中断する理由
enum SessionEntrySaveError: LocalizedError, Equatable {
    /// 最低入力条件を満たしていない（メッセージはそのままユーザーに見せる日本語）
    case invalidInput(String)

    var errorDescription: String? {
        switch self {
        case .invalidInput(let message): return message
        }
    }
}

// 呼び出し側は成否で遷移を分岐する（失敗時は .stay ＝画面と入力を維持）
switch SessionEntryViewModel.nextStep(saveSucceeded: saved != nil, isEditing: isEditing) {
case .showDone: savedSession = saved   // 新規保存成功 → 記録完了画面
case .close:    dismiss()              // 編集保存成功 → シートを閉じる
case .stay:     break                  // 保存失敗 → とどまる
}

ロギングの原則

  • 失敗は Logger（os.log）の data / app カテゴリに error で記録する。print() は使わない
  • ログに金額・店名・メモ本文などのユーザーデータを載せない（記録するのは失敗の事実と localizedDescription のみ）
  • ユーザーに見せるアラートとログは別物として扱う（アラートは日本語の行動指示、ログは原因調査用）
