学習計画の進み具合と配り直し

学習計画を「計画」として保存し、進み具合・遅れを見せ、遅れたら残りを今日から終了日までに配り直す

v1.4.0（TestFlight・未提出） 機能ID: SS-FEAT-PLAN-01

概要

v1.3 までの学習計画は、学習計画シートが「計画名: 1日量（N日目/M日）」のやることを日数分作るだけで、 計画としてのまとまりが残らなかった。そのため計画の一覧・進み具合・遅れが見えず、1日休むと期限切れが溜まるだけで、残りを配り直す手段が無かった（SS-020）。 アプリの中心価値「試験日から逆算して今日やる分が決まる」の本体が欠けていた。

v1.4 で計画そのもの（StudyPlan）を保存し、日ごとのやること（StudyTask）に planID と割り当てた量（planAmount）を持たせた。 これで「どこまで進んだか」「何日分遅れているか」が計算でき、残りを配り直せる。データは足すだけで、既存のやることは消さない。

関連画面

  • 学習計画シート（SS-PLAN-01） — 計画の作成
  • カレンダー画面（SS-CAL-02） — 「学習計画」欄（進み具合・配り直し・一覧から外す）
  • 計測を終えたあとの画面（SS-AFTER-01） — 学習計画のやることは次の予定を聞かず、計画の次のやることを見せる
  • 週のふりかえり（SS-REVIEW-01） — 学習計画のやることは付け替えず、配り直しへ案内する

処理フロー

計画を作る

sequenceDiagram participant U as ユーザー participant V as StudyPlanSheet participant S as StudyPlanService participant DB as SwiftData U->>V: 計画名・科目・総量・単位・開始日・終了日・分割方法を入力 V->>S: targetDays / distribute（プレビュー「1日あたり 3〜4 ページ × N 日間」） U->>V: 作成 V->>S: createPlan(...) S->>DB: insert StudyPlan S->>DB: insert StudyTask × N（planID・planAmount・origin=plan・dueScope=day） V->>DB: save V-->>U: シートを閉じる（計測イベント plan_created）

進み具合を見て、配り直す

sequenceDiagram participant U as ユーザー participant V as PlanProgressSection（カレンダー） participant S as StudyPlanService participant DB as SwiftData V->>S: progress(plan, tasks, today) S-->>V: 終えた量・遅れの日数・残りの日数 V-->>U: 「計画どおり」／「N日分遅れ」＋「残りを配り直す」／「完了」＋「一覧から外す」 U->>V: 残りを配り直す V-->>U: 確認「残りの X ページを、今日から 10/31（土） までの N日に配り直します…」 U->>V: 配り直す V->>S: rebalance(plan, tasks, today) S->>DB: 未完了のやることを付け替え／足りなければ作成／余れば削除 V->>DB: save（計測イベント plan_rebalanced） V-->>U: 「『英単語帳』を配り直しました」

ビジネスルール

配る日と量

  • 配る日: 毎日＝開始日〜終了日の毎日／曜日を選ぶ＝その期間の選んだ曜日だけ／1タスク＝終了日の1日だけ
  • 量は合計ちょうどに配る: 1日あたり＝総量÷日数の商。割り切れない分は前の日から1ずつ多くする（例: 10ページを3日 → 4・3・3）。v1.3 までは切り上げた量を全日に入れていたため、合計が総量を超えていた
  • 量が0になる日はやることを作らない（総量が日数より少ないときは、前から総量の数の日だけ作る）。プレビューの「× N 日間」も実際に作る数で出す
  • 「1日あたり」は量に幅があれば「3〜4」のように出す
  • 題名は「計画名: 量単位（i日目/n日）」、1タスクのときは「計画名: 量単位」
  • 作ったやることは origin = plan。ホームなどでは「学習計画」と表示する

進み具合

項目計算
終えた量完了した計画のやることの planAmount の合計（総量を上限）。途中までのやることは完了するまで数えない
遅れの日数期限が今日より前で未完了の計画のやることの数
残りの日数今日（開始日より前なら開始日）から終了日までの、配る日の数。終了日を過ぎていれば0
状態残りの量が0、または未完了のやることが0なら「完了」／遅れがあれば「N日分遅れ」（オレンジ）／それ以外は「計画どおり」

表示は計画ごとに、科目の色の丸・計画名・状態・進捗バー・「done / total単位・終了日 M/d（E）」。「今日」は学習日の区切り（StudyDay.resetHour）で決める。

配り直し

  • 「残りを配り直す」は遅れているときだけ出す。押すと確認を出す（「配り直す／やめる」）
  • 残り（総量−終えた量）を、今日から終了日までの配る日に、作るときと同じ規則で配る
  • 未完了のやることを期限の早い順に新しい日程へ付け替える（題名・期限・量を書き換え、期限の種類は「その日」）。足りなければ新しく作り、余ったものは削除する
  • 完了したやることには触らない。題名の「i日目/n日」は、完了した数に続けて振り直す
  • 残りが無いときは「『計画名』は残りがありません」、終了日を過ぎている（または残りの配る日が0日）ときは「終了日を過ぎているため配り直せません」

一覧から外す

  • 「完了」の計画には「一覧から外す」を出す。押すと isArchived = true にして欄から消す。やることには触らない
  • 一覧に出す計画が0件のとき、カレンダーの「学習計画」欄そのものを出さない

他の画面での扱い

  • 計測を終えたあと: 学習計画のやることは「次はいつ・何を」を聞かず、同じ計画の次のやることを見せる。途中までなら同じやることを明日へ回す（詳細）
  • 週のふりかえり: 学習計画のやることは「来週へ／消す」の対象にしない（付け替えると進み具合が狂う）。件数だけ出して配り直しへ案内する
  • 科目を消したとき: その科目を指していた計画の科目を外す（計画そのものは残る。やることリスト機能参照）
1.4.0 より前に作った計画は、進み具合の欄に出ない。 v1.3 以前は計画の入れ物（StudyPlan）を作っていなかったため、まとめる手がかりが無い。 そのとき作ったやることはそのまま残り、ふつうのやることとして表示・完了できる（planID が無いので、週のふりかえりでは「来週へ／消す」の対象になる）。

外部連携

連携先用途備考
SwiftData（StudyPlan / StudyTask）計画と日ごとのやることの保存カレンダーの欄は isArchived == false の計画と planID != nil のやることだけを読む
Firebase Analyticsplan_created（作ったやることの数）／plan_rebalanced計画名などの内容は送らない

エラー処理

発生条件対応
配る日が0日・総量が0（作成時）計画を作らない（作成ボタンは入力が揃うまで押せない）
終了日を過ぎている・残りの配る日が0日（配り直し時）何も変えず「終了日を過ぎているため配り直せません」
残りの量が0（配り直し時）何も変えず「『計画名』は残りがありません」
SwiftData の保存失敗Logger でエラーを記録する。作成時はシートを閉じない（StudyPlanSheet）。配り直し時は TaskFlowService.save が記録する

実装メモ

  • 計算は StudyPlanService の純粋関数（targetDays / distribute / taskTitle / progress / rebalanceSchedule）に置き、単体テストで確かめている
  • 分割方法の enum は画面内の StudyPlanSheet.SplitMode から PlanSplitMode（daily / weekdayFilter / single）へ移し、計画に保存する
  • 曜日は weekdaysText に「1=日〜7=土」をカンマ区切りで保存する
  • カレンダーの欄は PlanProgressSection。表示中のビュー（日・週・月）によらず、試験日カードと表示切替タブの間に出す
