ホーム画面（HomeView）

タイマー実行の中心画面

v1.3画面ID: SS-HOME-01

目的・役割

科目を選んでタイマーを開始・停止する画面。タイマー実行中はLive Activityとも連動。

あわせてこのアプリの中心価値「試験日から逆算して今日やる分が決まる」を最初に提示する場所でもある（v1.3〜）。 起動直後に目に入る位置で試験日までの残り日数を見せ、未設定ならそこから設定・学習計画作成まで繋ぐ。

UI 構成（v1.3）

🔴 並び順を戻さないこと（v1.3・2026-09-05）
このアプリの中心価値は「試験日から逆算して今日やる分が決まる」こと。 v1.2.2 までは試験日カウントダウンが文脈カード群の中にあり、画面の6番目・スクロールしないと見えない位置だった。 機能としては実装済みなのに導線上ほぼ発見できず、結果として「カウントダウン付きのストップウォッチ」として使い始められる構造になっていた （Fable 5.1 のUI評価 2026-09-02 で最重要と判定。SS-001 / SS-002）。
そのため v1.3 でカウントダウンを ExamCountdownCard として切り出し、開始CTAより前・画面最上部に置いている。 「毎日使う開始CTAが最上部であるべき」という一般論でこの順序を戻すと、中心価値が再び埋没する。
v1.2.2 でカード順序を再設計。「大型開始CTA → 今日目標リング（主表示）→ 今週・今月（補助）→ ポモドーロ → 文脈カード」に整理。 科目一覧の各行を主導線（計測ボタン）と副導線（…メニュー）に整理し視認負荷を低減。
順序要素説明
1試験日カウントダウン（examCountdownSection / ExamCountdownCard）v1.3通常カードスタイル（softCardBorder）。試験日設定済みなら残り日数を大型数字（@ScaledMetric 40pt・relativeTo: .largeTitle）で表示。未設定・期限切れ時はカード全体がボタン（下記「タップ挙動」参照）
2大型計測開始CTA（startCTACard）重要カードスタイル（太い枠線＋底面シャドウ）。前回続き（直近セッションの科目）がある場合は「前回の続き: [科目名]」、フォーカス科目モード時は「今日の1科目: [科目名]」を表示。大きな「計測スタート」ボタン＋弱い「計測せず手動で記録」テキストリンク。v1.3 でカウントダウン1枚ぶん下がった（押せることと順序を UIテストで固定済み）
3今日目標カード（todayGoalCard）重要カードスタイル。大リングで当日達成率を主表示。基準は effectiveDailyGoalMinutes（日次StudyGoal優先→設定の1日の目標にフォールバック）。計測中リング・達成演出・ホーム表示すべて同一基準を使用
4科目候補リスト（subjectPickerList）「科目を選んで始める」。通常モードかつ科目が2件以上のときのみ表示。CTA科目を除いた候補を3件に絞り、showAllSubjects で全件展開。主導線は「計測」ボタン、「手動で記録」・「編集」・「削除」は各行末の「…」メニューへ集約
5今週・今月カード（2枚 / secondaryGoalsRow）通常カードスタイル（影なし・軽い境界線のみ）。compact 表示で横並び
6ポモドーロ設定トグル集中25分/休憩5分の自動切替。通常カードスタイル
7ダッシュボードカード（dashboardCard / DashboardCard）連続日数（🔥 N日連続）とモチベーション引用のみ。v1.3 でカウントダウンを最上部へ移設したため中身が2つに減った。どちらも無いときはカード自体を描画しない（hasContent が false なら EmptyView）— そうしないと当日まだ記録していない新規ユーザーにホーム最下部の空の枠線カードだけが残る
—科目未登録時primaryStudySection が ContentUnavailableView「科目が登録されていません／設定タブから科目を追加してください」に切り替わる
—タイマー実行中表示（timerRunningView）タイマー実行中のみ全面切替。HH:MM:SS 大字 + 一時停止/停止ボタン（スタイルはタイマー機能仕様参照）
—目標達成オーバーレイ日次目標達成時に「目標達成！」フルスクリーンオーバーレイ（タップで閉じる）
—ツールバー（右上）共有ボタン（accessibilityLabel: "学習記録を共有"）

試験日カウントダウンのタップ挙動（v1.3）

ExamCountdownCard は「設定を促している状態＝押せなければならない」という原則で作る。 押せない状態で「タップして設定しよう」と書くと、案内文が嘘になる。

状態判定（isTappable）表示タップ
試験日 未設定examDate == nil → true「試験日を設定しよう」＋ chevron.right ／ サブ「タップして登録すると、試験日までの残り日数と1日にやる分が出ます」可（カード全体がボタン）→ 試験日設定シート
試験日 設定済み（残り1日以上）daysLeft > 0 → false残り日数の大型数字＋試験名など不可（表示のみ）
試験日 期限切れ（残り0日以下）daysLeft <= 0 → true「お疲れ様でした！」＋「タップして次の試験日を設定しよう」可 → 試験日設定シート
🔴 期限切れ状態を条件から落とさないこと。 isTappable を examDate == nil だけで判定すると、期限切れ状態が抜ける。 そこも「タップして次の試験日を設定しよう」と促しているため、押せないと v1.2.2 と同じ欠陥（押せないカードで口頭指示だけする）を別の状態で作り直すことになる。 判定は必ず「未設定 または 残り0日以下」で行う。

ビジュアル階層方針（v1.2.2）

「重要カードスタイル」（太い枠線＋底面シャドウ）は主役カードにのみ適用し、画面全体の情報階層を明確化。 通常カードは軽い境界線のみ（影なし）。Dynamic Type 上限の不必要な制限は設けない。
スタイル適用対象
重要カードスタイル開始CTA・今日目標カード
通常カードスタイル試験日カウントダウン・科目候補リスト・今週・今月・ポモドーロ・ダッシュボードカード
試験日カウントダウンは位置（最上部）で優先度を示し、装飾は通常カードスタイルに留める。 重要カードスタイルを重ねると開始CTA・今日目標カードとの階層が崩れるため。 ただし .softCardBorder() は必須（v1.3 の切り出し時に一度脱落し、最上部の一番目立たせたいカードだけ枠線なしになった）。

実装メモ

  • UserDefaults 経由でタイマー永続化（24時間境界）
  • scenePhase 監視でバックグラウンド時の経過時間補正 / 学習日変更時に todayKey を更新して @Query を再構築
  • Live Activity と連動（startActivity / updateActivity / endActivity）
  • フォーカス科目モード: settings?.focusSubjectModeEnabled + settings?.focusSubjectID で制御。FocusSubjectPickerSheet で変更
  • dashboardCard は todaySessions / weekSessions / monthSessions を3つの独立 @Query で取得（パフォーマンス改善）
  • goalsRow は activeGoals（isClosedでフィルタ）から日/週/月の StudyGoal を取得
  • 共有ボタンに .accessibilityLabel("学習記録を共有") を付与（HIG準拠）
  • 完了セッション数 completedSessionCount（AppStorage）をインクリメントし、閾値でレビューリクエスト（requestReview）
  • effectiveDailyGoalMinutes: 日次StudyGoal優先→設定の dailyGoalMinutes にフォールバック（計測中リング・達成演出・カード表示で統一）
  • 科目一覧の「…」メニューに「手動で記録」・「編集」・「削除」を集約（主ボタンを「計測」のみに絞る）
  • v1.3 試験日カウントダウンを DashboardCard から ExamCountdownCard として切り出し、subjectListView の最上部（開始CTAより前）へ配置
  • v1.3 試験日設定シート＋学習計画シート＋提案アラートの一連の導線は ExamPlanFlow（ViewModifier）に切り出す。HomeView の body に直接書くと型推論が限界を超えてビルドが通らない。View を200行以下に保つ規約にも沿う
  • v1.3 提案アラートは sheet(onDismiss:) で提示する。ExamDateSetupSheet の onSaved は dismiss の前に呼ばれるため、受け側は didSaveExamDate フラグを立てるだけにする。dismiss 後に直接 alert を出すと、シートが閉じるアニメーション中の提示になり UIKit の "already presenting" で黙って捨てられる余地が残る（シミュレーターでは通ってしまう）
  • v1.3 ExamCountdownCard.isTappable は「examDate == nil または 残り0日以下」。未設定のみで判定しない
  • v1.3 DashboardCard.hasContent（streakDays > 0 || motivation が非空）が false なら EmptyView を返す
  • v1.3 UIテストで「開始CTAが押せること」と「カウントダウンが開始CTAより上にあること」を固定。学習開始は毎日いちばん使う操作のため、順序変更で押し下げても壊れないことを保証する
