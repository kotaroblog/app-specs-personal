作品カード

「これまでに置いた量」を数字で振り返るカード。ステージでは着手前・完成・作者の写真も並ぶ。設置の集計（PlacementTally）を含む

機能ID: VG-FEAT-WORKCARD

概要

ワールドに積み上げた投資量（量と時間）を1枚で見せる振り返り画面。建築特化への転換（2026-09-16）における設計の核心「達成感の源泉は危険を越えることではなく、不可逆な投資が目に見えること」をそのまま UI にした機能である。カード自体は何も集計しない（WorldRecord の列を読むだけで、4つ目の権威を作らない）。

関連画面

  • ゲームプレイ画面（メニュー → 作品カード）
  • ワールド選択画面（累計設置数バッジ・ステージの一覧のカード）
  • ステージと記念写真（写真を撮る側）

開き方: メニューの「作品カード」。ステージで「完成にする」の写真を撮り終えたときは自動で開く。

表示内容

項目内容データ元
ワールド名見出しとして表示WorldRecord.name
お題（ステージのみ）「お題: 岬の先に、灯台を建てる」WorldRecord.stageID → StageCatalog
写真3枚（ステージのみ）「着手前」「完成」「作者」を横に並べる（下記）stageBeforePhoto / stageAfterPhoto / stageAuthorPhoto
これまでに置いたブロック累計設置数（大きな数字）PlacementTally.total
制作日数「制作N日目」。初回設置日を1日目とするWorldRecord.firstPlacedAt
よく使った材料種別ごとの設置数の上位3種（色チップ＋名前＋個数）PlacementTally.byBlock
直近の設置数直近14日の日別設置数を棒グラフ表示（最大値で正規化、高さ40pt）。データがある日だけ棒を出すPlacementTally.byDay
  • まだ何も置いていない場合は制作日数・内訳・棒グラフを出さない（累計0のみ）
  • ワールド選択画面の各行には累計設置数バッジ（cube アイコン＋「N個」）を表示し、入らなくても積み上げが見える
  • VoiceOver 向けに「これまでに置いたブロック N個、制作M日目」を1要素にまとめて読み上げる

ステージの写真（2026-09-27 CF13・2026-09-28 CF22）

決まった角度から撮った「着手前／完成」を同じ枠で並べ、積み上げた投資を一目で分かるようにする。写真の撮り方はステージと記念写真を参照。

枠ラベル写真が無いとき
着手前着手前カメラのアイコン。読み上げは「〇〇の写真はまだありません」（ある場合は「〇〇の写真」）
完成完成（未完成の間は「完成（まだ）」）
作者作者（完成を宣言した瞬間のプレイヤーの画面。三人称なら自分のキャラも写る）
  • 枠は 16:9 を先に決めてから写真で埋める（scaledToFill・角丸8）。写真に枠を合わせると、着手前と完成で枠の大きさが揃わなかった（2026-09-27 にシミュレーターで確認）
  • ステージ以外のワールド（stageID が nil、または定義に無い id）では写真の節を出さない
  • 記念写真（左上のカメラのボタン）は「写真」アプリへ保存するだけで、作品カードには入らない

ステージの一覧のカード（ワールド選択）

ワールド選択画面の右側（幅290pt）の「ステージ」の欄に、ステージ1つにつき1枚のカードを出す（StageCard）。ステージのワールドは左の「自分のワールド」の一覧には出さない。

項目内容
サムネイル76×50pt・角丸8。完成の写真があればそれ、無ければ着手前の写真。どちらも無ければ空と砂のグラデーションに旗のアイコン
名前・お題「岬の灯台」と、お題1行（1行で省略）
進み具合まだ始めていない「まだ始めていません」／制作中「制作中 ・ 置いたブロック N」（WorldRecord.placedBlockCount）／完成「完成 ・ 日付」（黄色）
タップそのステージへ入る（無ければ作る）
長押しワールドがあるときだけ「最初からやり直す」。確認のあと、建てた物と写真ごと削除する
読み上げ「ステージ 岬の灯台。岬の先に、灯台を建てる。（進み具合）」を1要素・ボタンとして読む

集計ルール（PlacementTally）

sequenceDiagram participant U as User participant Scene as GameSceneView（renderスレッド） participant Tally as PlacementTally（値型ミラー） participant Input as GameInput participant Store as WorldRecord U->>Scene: ブロックを設置 Scene->>Tally: apply(block:delta:+1, day: epochDay, now:) Tally-->>Scene: total / byBlock / byDay / firstPlacedAt を更新 Scene->>Input: メインスレッドへ tally をミラー Input-->>U: 目標6の進捗・作品カードへ反映 Scene->>Store: 定期保存で placedBlockCount 等へ書き戻し
ルール内容
加算プレイヤーが設置したときに +1。クリエイティブでも数える
減算1手アンドゥで設置を取り消したときのみ -1。通常の破壊では減らない（「これまでに置いた」量なので壊しても消えない）
アンドゥの日付「取り消した日」ではなく元の操作をした日の枠から引く。日をまたいでアンドゥしても sum(byDay) == total を保つため
不変条件sum(byBlock.values) == total かつ sum(byDay.values) == total。これを守るため更新経路は apply(block:delta:day:now:) の1つに限定する（countPlacedBlock / undoLastEdit の2箇所だけが呼ぶ）
権威権威は byBlock（内訳）。WorldRecord.placedBlockCount は目標6が毎フレーム読むための非正規化キャッシュ
初回設置日delta > 0 のとき firstPlacedAt が nil なら現在時刻を記録する（以後変えない）
保持期間日別は直近730日（約2年）分までを保存し、それより古い日は保存時に切り捨てる

外部連携

連携先用途備考
目標ガイド（VG-FEAT-OBJECTIVES）目標6「自由に建てる」の進捗tally.total と objectiveBuildTarget=100 を比較する
建築支援操作（VG-FEAT-BUILD-ASSIST）1手アンドゥによる減算設置の取り消しのみが tally を減らす
WorldRecord（SwiftData）累計・内訳・日別・初回設置日の永続化詳細はデータモデル

エラー処理

発生条件対応
旧セーブで total と内訳の合計が食い違う復元専用イニシャライザは total を独立して受け取り、復元時点の値をそのまま信用する（一致チェックはしない）
日別データの epochDay が UInt16 の範囲外その日はエンコード対象から除外する
累計が 65535 を超える直列化時に 65535 でクランプする（内訳・日別とも UInt16）

既知の課題

ID内容状態
CF-011着手前の写真が、読み込み途中の地形で撮られることがある（初回の生成が8秒を超えると準備完了が保険で先に立つため。一度撮ると撮り直さない）。コードで確認・実機では未確認未対応
CF-012作品カード（最大3枚）と一覧のステージのカードが、描き直すたびに写真を UIImage(data:) で読み込み直している（性能だけの問題）。直すなら読み込んだ画像を覚えておく未対応

実装メモ

  • PlacementTally は SceneKit 非依存の純粋値型で、シミュレーターなしで単体テストできる（PlacementTallyTests）
  • epochDay は 2026-01-01 00:00:00 UTC 起点の経過日数。タイムゾーン変更・サマータイムで日付境界が動かないよう UTC 固定にしている
  • カードは GameInput.tally（メインスレッドのミラー）と WorldRecord を読むだけで、自前の集計を持たない
  • 写真の節も WorldRecord の写真の列と StageCatalog を読むだけで、カード側では撮らない・保存しない
  • カード本体は ScrollView + AdaptiveMaxHeight(standard: 320) でラップし、最大文字サイズでも全項目へ到達できる
