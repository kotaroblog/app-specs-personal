建築支援操作

設置プレビュー（ゴースト）・置ける条件・足場積み・段差・階段/ハーフ・2マスのベッド・ランタン・柵と塀・スポイト・1手アンドゥ・編集モード・視点パッドの3分岐・ホットバー構成

機能ID: VG-FEAT-BUILD-ASSIST

概要

建築では1手ごとの位置合わせが作業のほぼ全てになる。そのため「置く前に結果を見せる」「見えているブロックを指して選ぶ」「置き間違いを1手戻す」の3つを揃え、右親指1本で採掘・設置・視点を捌けるようにジェスチャーを整理した。いずれも建築特化への転換（2026-09-16〜09-17）で追加した操作である。

2026-09-24〜10-02 に、形の違う建材（階段・ハーフ・柵・塀・ランタン・2マスのベッド・船）と、それを積むための操作（足場積み・半段の自動ステップアップ・編集モード）を足した。置ける／置けないの判定はすべて設置プレビューと実際の設置で同じ関数を使う。

設置プレビュー（ゴースト）

項目仕様
表示「いま置いたらどこに出るか」を半透明の形で先に見せる。深度バッファの読み書きをせず常に手前へ描画する（renderingOrder 5。枠線ハイライトと同じ扱い）
形立方体は一辺0.98。ハーフは高さ0.49（collisionHeight 0.5 × 0.98）。階段は実物と同じ二段形状をプレイヤーの向きで回して出す。ベッドは頭側まで伸ばした長さ1.98の箱。船は幅1.3・長さ2.96・高さ0.5の低い箱を置く向きで出す
色置ける場所は選択中ブロックの色（不透明度0.42）、置けない場所は赤（不透明度0.30）
赤になる条件体と重なる（足場積みできる真下は除く）／頭上がふさがって足場積みできない／世界の高さ（0〜63）の外／置き先が空気・水以外／ベッドの頭側が置けない／ランタンに床も天井も無い／種・小麦を土・草・耕地の上面の空いたマス以外へ向けた／船が海面でない・3マス続く海が無い・近くにほかの船がある
非表示条件選択中が設置不可アイテム／サバイバルで所持数0／使える物（作業台・石切台・かまど・チェスト・ベッド）を狙っている（タップが「使う」になるため）／編集モードで何も持ち上げていない
編集モード中持ち上げ中の物があれば、その物の置き先を持ち上げたときの向きで出す（ベッドだけはいまの向き）
判定の共通化置ける／置けないの判定は実際の設置処理と同じ判定（selfOverlap・bedHeadPlacement・LanternPlacement・BoatRules）を使い、プレビューと結果が食い違わないようにする

枠線ハイライトだけでは「どのブロックを狙っているか」しか分からず、置いた結果がどの面に出るかは指で隠れて読めない。押す前に結果と可否が分かることで、積み直しの手戻りを減らす。種の影は、若芽の横を狙ったとき植えられない場所へ普通の色で出ていたため、植え付けの条件も見るようにした（CF29）。

置ける条件と届く距離

条件仕様 / 断るときの表示
届く距離壊す・置く・使うとも目線からサバイバル4.5・クリエイティブ5ブロック（2026-09-27。以前は両方6で「届かないはずの所まで壊せる」と指摘された。Minecraft Java 版と同じ値）
世界の高さ置き先の y が 0〜63 の外なら置かない。「これより上には置けません」／「これより下には置けません」。以前は範囲外が空気扱いになり、何も置かれないまま在庫と設置数だけ減っていた（2026-09-26 修正）
置き先空気か水のマスだけ。作物・植物のマスへの重ね置きは「そこには置けません」
使える物を狙ったとき手持ちの確認より先に判定し、置かずに使う（在庫切れの建材を選んでいても作業台・チェストを開ける。CF-002）
植物（花・背の高い草・キノコ）草か土の上面だけ。「草か土の上に置けます」
種・小麦土・草・耕地の上面だけ。土・草は耕地にしてから植える。「種は土か草の上に植えられます」
船海面だけ。水の中を狙っていたら上の水面へ上げ、向こう向き（だめなら横向き）で前後のマスも水であること。「船は海の上に置けます」「船を浮かべるには、3マス続く海が要ります」「近くにほかの船があります」

足場積み（真下へ置くと1段登る）

2026-09-26 追加。目線は足元+1.62 なので、地面に立ったまま壁を積むと2段目の上面（+3）が目線より上になり、2段より高く積む手段が無かった。本家のように「ジャンプしながら足元へ置く」をスマホで同時押しするのは難しいため、「真下へ置いたら、自分を持ち上げてから置く」を1操作にした。ブロックは消費するので「量」の摩擦は残る。

条件（pillarLiftFeetY）値
狙う面上面（法線が +Y）
狙った点照準の当たった点が足の幅（体の半幅0.3）の内側。体の中心の列では判定しない（スポーン地点が列の角ちょうどで、真下を向いても隣の列に当たるため）
持ち上げ量0より大きく1.5以下（ハーフの上に立って立方体を置く 0.5+1.0 まで）。足元は「置き先の y ＋ 置く物の最も高い面」
置く物通り抜けられない物だけ（松明を足元へ置いても体は持ち上がらない）。ベッドは頭側まで体と重なりうるので足場積みしない
頭上持ち上げた位置に立てなければ「頭の上がふさがっていて登れません」

段差・階段・ハーフブロック

項目仕様
半段の自動ステップアップ地上で歩いて0.5（stepHeight）までの段差は自動で上がる（2026-09-24）。接地中かつ下降中でないときだけ。斜め移動でX・Zの両軸から1フレームに計1m上がらないよう、X で上がったフレームは Z で上げない。浅瀬は1段（1.0）まで、泳いでいるときは0.5〜1.7を0.25刻みで試してよじ登る
ハーフブロック石・木・石レンガ・砂岩・針葉樹・氷の6種。下半分（高さ0.5）を埋め、当たり・照準・プレビューとも高さ0.5
階段の向き石・木・石レンガ・砂岩・針葉樹・氷の6種。プレイヤーの向き（yaw を90度単位に丸めた値）で置き、上段が向こう側（奥）に来る。向きはチャンクに保存する
階段の当たり「全面の土台（高さ0.5）＋向きに応じた奥半分の上段（0.5〜1.0）」の2箱。歩いて半段ずつ上がれる。照準も同じ形で当たる

2マスのベッド（CF11）

項目仕様
置き方狙ったマスに足側、プレイヤーの向きの先の隣に頭側（枕）を自動で置く（2026-09-26）
置けない条件頭側が空気・水でない／世界の高さの外／頭側のチャンクが未読み込み →「ベッドは2マス使います。向こう側が空いていません」。どちらかのマスが体と重なる →「自分の位置には置けません」
壊すどちらを壊しても両方消え、ベッド1個が戻る。頭側を触っても寝る・スポーン地点の設定になる
保存両方のマスへ同じ保存値（下位2ビット＝向き、3ビット目0x04＝2マスの印）を書く。保存形式は据え置き。印の無い1マスのベッド（それより前に置いたもの）はそのまま残り、従来の形で描く
取り消し・回す相方を持つので1手アンドゥの対象外（置いた・壊した直後に1つ前の操作が戻る不具合を 09-27 に修正）。編集モードでも回せない（持ち上げて置き直す）

ランタン

項目仕様
置き方床に置くか天井から吊るす（壁には付けない。2026-09-27）。下面を狙ったら吊るす（上が支えなら）。それ以外は下が支えなら床置き、下が無く上が支えなら吊るす
支え通り抜けられないブロック（blocksMovement）。水は支えにならない。どちらも無ければ「ランタンは床に置くか、天井から吊るしてください」
保存吊るしているかを保存値の 0x04 に書く
置き直し狙った面が無い置き直し（アンドゥ・編集モード）では周りの支えから床置きか吊るしかを決める。持ち上げたランタンも支えの無い宙には置けない

柵と塀

項目仕様
種類木の柵・石の塀・針葉樹の柵（同じ「細い柱」の形で、貼るタイルだけ違う）
つながり北・東・南・西の4方向だけ見て、同じ種類の柵・塀か、すき間なく埋まった立方体（葉を除く）なら横木を伸ばす。木の柵と石の塀はつながない。上下にはつながない
描き直し隣のブロックが変わったときと、隣のチャンクを読み込んだとき（チャンク境目の柵がつながらない問題の対策）に描き直す
当たり見た目は細いが、当たりはセル全体（高さ1.0の箱）

スポイト

項目仕様
起動独立したスポイトボタン（eyedropper・44pt）。操作クラスタ（置く・壊す・ジャンプ）の真上に揃える（2026-09-23 変更。横向きはジャンプのさらに上で、ボタンの大きさ設定の倍率に合わせて高さを上げる）。左利き配置時は左寄せ
編集モード中回せる物（階段・1マスの家具）を狙っている間は、同じ位置が「回す」ボタンに替わる
動作照準先のブロックをそのまま選択中ブロックに取り込む。軽い触覚フィードバックと「○○を選んだ」トースト
拒否1設置できないブロック（水・溶岩・成熟小麦など）は「それは選べません」
拒否2サバイバルで所持数0のときは「○○は持っていません」（選べてもゴーストが出ず「選んだのに何も起きない」状態になるため、理由を言ってから選択しない）

クリエイティブでは設置しても在庫が減らず所持数が増えないため、所持数で絞る所持品シートだけでは地形素材（草・砂・雪・木・葉 等）を選べない期間があった。「見えているものを指して選ぶ」が、画面を増やさずにこの穴を塞ぐ最短経路になっている（所持品シートのクリエイティブ全ブロック表示と併用）。

ボタンをホットバー内でも操作クラスタ内でもなく独立した位置にしているのは、ホットバーに入れると可視幅370ptのうち52ptを食って固定枠が1つ減り、操作クラスタに足すと5つ目のボタンとして誤爆源になるため。

1手アンドゥ

項目仕様
深さ1手のみ（履歴を積まない。履歴化は保存形式とメモリに波及するため）
対象直前の「設置」または「破壊」。実行すると履歴は空になる
対象外チェスト・かまど・ベッドなど付随状態（中身／履歴フラグ／相方のマス）を持つものの設置。編集モードの持ち上げ・置き換え・回すは履歴を消す
別ノードの物松明は placeTorch、ランタンは placeLantern（吊るすかは周りの支えから決める）、階段・柵・作業台などは placeFurniture を経由して戻す（setBlock だけだとノードが登録されず見えなくなる）。壊した時点の向き（rotationY）を履歴に退避し、階段は元の向きで戻す（2026-09-24）
在庫設置の取り消しでは材料を1個返し、破壊の取り消しでは材料を1個消費する（クリエイティブでは増減しない）
集計設置の取り消しのみ PlacementTally を -1。日付は「元々設置した日」から引く
ボタン活性戻せる操作がある間だけ有効（GameInput.canUndo）。位置は「壊す」の左

戻せない条件と文言

条件表示
履歴なし／置いたものが既に掘られている／掘った跡が既に埋まっている「戻せる操作がありません」
破壊を取り消したいが材料が足りない「○○が足りず戻せない」
対象チャンクがアンロード済み（離れすぎている）「その場所から離れすぎていて戻せません」。書き込めたことを確認してから在庫を減らすため、材料だけ消える不具合は起きない

編集モード（置き換え・持ち上げ・回す。CF17）

2026-09-27 追加。置いたブロックを直すには壊して置き直すしかなく、チェストは中身を、階段は向きを失っていた。編集モードの切り替えボタンでオンにすると、ボタンの意味が替わる（置くボタンは紫になる）。

操作通常編集モード
赤（長押し）壊す持ち上げる: 向き・チェストの中身ごと持つ
緑置く何も持っていなければ長押しで置き換え（狙ったブロックを選択中の建材へ差し替え、元のブロックは所持品へ戻る）。持ち上げ中はここに置く（置ける条件は通常の設置と同じ。置けなければ持ったまま）
スポイトの位置スポイト回せる物を狙っている間は回す（90度ずつ。ベッドは不可）
  • オフにしたとき・保存の直前に、持ち上げ中の物は所持品へ戻す
  • 切り替えたら、押している途中の壊す・持ち上げ・置き換えを止める（ボタンの意味が変わるため）
  • 持ち上げ・置き換えを終えた直後は、押し続けている間の断る知らせを出さない（CF-014）。編集モードでは羊の毛刈りをしない（CF-015）

視点パッドの3分岐操作

画面右58%の視点パッド上の1本指ジェスチャーを、状態機械で「視点ドラッグ」「押し続けて壊す」「タップで置く・使う」に判別する。SwiftUI にも SceneKit にも依存しない純粋ロジックで、シミュレーターなしで単体テストできる（LookPadGestureTests）。

stateDiagram-v2 [*] --> idle idle --> pending: 指が触れた（移動量は溜めるだけ） pending --> looking: 12pt（moveSlop）を超えて移動 pending --> breaking: 0.22秒（holdDelay）押し続け pending --> idle: それ以前に離した → タップ（置く・使う） looking --> idle: 指を離す（採掘へは移らない） breaking --> idle: 指を離す → 採掘終了
閾値値根拠
moveSlop12ptUILongPressGestureRecognizer の allowableMovement（10pt）をわずかに上回る。親指の転がりを拾わず、HIG の最小タップ領域44ptよりは十分小さい
holdDelay0.22秒意図的なスワイプは50〜80msで動き始めるため220msの静止は「押し続け」と断定できる。離散操作の遅延知覚（250ms）とシステムの touch and hold（0.5秒）のいずれとも衝突しない
  • 判定保留中の移動量は視点へ反映せず内部に溜める。タップではカメラが1ミリも動かないため、チェスト・かまど・ベッドを狙ってタップするのが確実に成立する
  • ドラッグに確定した瞬間に溜めた移動量をまとめて反映するので、先頭に死に領域ができず1:1の追従感を保つ
  • 採掘に確定した後も移動は視点へ反映し、狙いながら掘れる
  • いったん視点ドラッグに確定したジェスチャーは、途中で指を止めても採掘へは移らない（暴発防止）

ホットバー（5枠）

項目仕様
固定枠石 / 板材 / 石レンガ / ガラス / 松明 の5枠
追加枠固定枠外を選んでいる間だけ、区切り線の右に選択中ブロックの枠を出す（タップで所持品シートを開く）
所持品ボタン右端に常設（44pt）
枠数の根拠390pt 端末では可視幅370pt。1枠44pt＋間隔6＋所持品44 で5枠=294pt、追加枠（区切り5＋間隔12＋枠44＝61）込みで355pt に収まる。6枠にすると405ptで溢れ横スクロールが常態化する（旧8枠は追加枠なしでも444ptで既に溢れていた）
選定方針「スポイトで拾えないもの」を優先。地形素材は世界に転がっていてスポイトで拾えるため固定枠に置かない。🔴 M1（2026-10末）で実際に建てて決め直す

外部連携

連携先用途備考
作品カード（VG-FEAT-WORKCARD）設置・アンドゥの集計反映設置 +1／設置の取り消し -1
クリエイティブモード（VG-FEAT-CREATIVE）在庫チェックの回避・全ブロック選択ゴースト・スポイト・アンドゥとも在庫条件を外す
採掘演出（VG-FEAT-MINING）押し続け判定からの採掘開始・終了ひび割れ・破片パーティクルは採掘演出側
セッション統計（内部計測）スポイト回数・アンドゥ回数・所持品シートを開いた回数などワールドには保存せず、退出時に Logger へ1行出力するのみ（ユーザー向け機能ではない）

エラー処理

発生条件対応
アンドゥ対象のチャンクが未読み込み書き込み結果を検証し、失敗したら在庫を減らさずトーストで通知する
選択中ブロックが設置不可・在庫切れゴーストを出さない（押しても何も起きない状態を見た目で先に伝える）
VoiceOver で長押しができない「壊す」ボタンは1回目で採掘開始・2回目で停止するトグル方式に切り替わる

実装メモ

  • ゴースト・ハイライトは SCNNode を使い回し、毎フレームのマテリアル差し替えを避けるため直近の選択ブロックを記憶して差分時のみ更新する
  • アンドゥ履歴（LastEdit）は enum で placed(x,y,z,block,day) / broke(x,y,z,block,day) の2ケースのみ保持する
  • スポイト・アンドゥの要求は GameInput の requestXxx / consumeXxx パターンでレンダースレッドへ渡す
  • 視点パッドの状態機械 LookPadGestureMachine は Equatable な値型で、Effect（beginBreaking / endBreaking / use）と lookDelta を返すだけに徹する
  • アンドゥ履歴の破壊ケースは broke(x,y,z,block,rotationY,day) で、別ノードの物の向きを持つ
  • 足場積みの条件 pillarLiftFeetY、ベッドの向きと相方 BedPlacement、柵のつながり FenceConnection、ランタンの置き方 LanternPlacement、届く距離 Reach は GameRules.swift の純粋ロジックで、単体テストで固定している
  • 体との重なりは SelfOverlap（clear / pillar / noHeadroom / body）に集約し、プレビューと設置の両方から呼ぶ
