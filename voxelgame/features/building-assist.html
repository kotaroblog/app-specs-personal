建築支援操作

設置プレビュー（ゴースト）・スポイト・1手アンドゥ・視点パッドの3分岐・ホットバー構成

機能ID: VG-FEAT-BUILD-ASSIST

概要

建築では1手ごとの位置合わせが作業のほぼ全てになる。そのため「置く前に結果を見せる」「見えているブロックを指して選ぶ」「置き間違いを1手戻す」の3つを揃え、右親指1本で採掘・設置・視点を捌けるようにジェスチャーを整理した。いずれも建築特化への転換（2026-09-16〜09-17）で追加した操作である。

設置プレビュー（ゴースト）

項目仕様
表示「いま置いたらどこに出るか」を一辺0.98の半透明立方体で先に見せる。深度バッファの読み書きをせず常に手前へ描画する（枠線ハイライトと同じ扱い）
色置ける場所は選択中ブロックの色、置けない場所は赤
非表示条件選択中が設置不可アイテム／サバイバルで所持数0／チェスト・かまど・ベッドを狙っている（タップが「開く」になるため）
判定の共通化置ける／置けないの判定は実際の設置処理と同じ判定を使い、プレビューと結果が食い違わないようにする

枠線ハイライトだけでは「どのブロックを狙っているか」しか分からず、置いた結果がどの面に出るかは指で隠れて読めない。押す前に結果と可否が分かることで、積み直しの手戻りを減らす。

スポイト

項目仕様
起動ホットバー直下の独立したスポイトボタン（eyedropper）。左利き配置時は左寄せ
動作照準先のブロックをそのまま選択中ブロックに取り込む。軽い触覚フィードバックと「○○を選んだ」トースト
拒否1設置できないブロック（水・溶岩・成熟小麦など）は「それは選べません」
拒否2サバイバルで所持数0のときは「○○は持っていません」（選べてもゴーストが出ず「選んだのに何も起きない」状態になるため、理由を言ってから選択しない）

クリエイティブでは設置しても在庫が減らず所持数が増えないため、所持数で絞る所持品シートだけでは地形素材（草・砂・雪・木・葉 等）を選べない期間があった。「見えているものを指して選ぶ」が、画面を増やさずにこの穴を塞ぐ最短経路になっている（所持品シートのクリエイティブ全ブロック表示と併用）。

ボタン配置をホットバー内でも操作クラスタ内でもなく独立行にしているのは、ホットバーに入れると可視幅370ptのうち52ptを食って固定枠が1つ減り、操作クラスタに足すと5つ目のボタンとして誤爆源になるため。

1手アンドゥ

項目仕様
深さ1手のみ（履歴を積まない。履歴化は保存形式とメモリに波及するため）
対象直前の「設置」または「破壊」。実行すると履歴は空になる
対象外チェスト・かまど・ベッドなど付随状態（中身／履歴フラグ）を持つもの
松明光源ノードを伴うため removeTorch / placeTorch を経由して戻す（setBlock だけだとノードが孤立する・光源が復元されない）
在庫設置の取り消しでは材料を1個返し、破壊の取り消しでは材料を1個消費する（クリエイティブでは増減しない）
集計設置の取り消しのみ PlacementTally を -1。日付は「元々設置した日」から引く
ボタン活性戻せる操作がある間だけ有効（GameInput.canUndo）。位置は「壊す」の左

戻せない条件と文言

条件表示
履歴なし／置いたものが既に掘られている／掘った跡が既に埋まっている「戻せる操作がありません」
破壊を取り消したいが材料が足りない「○○が足りず戻せない」
対象チャンクがアンロード済み（離れすぎている）「その場所から離れすぎていて戻せません」。書き込めたことを確認してから在庫を減らすため、材料だけ消える不具合は起きない

視点パッドの3分岐操作

画面右58%の視点パッド上の1本指ジェスチャーを、状態機械で「視点ドラッグ」「押し続けて壊す」「タップで置く・使う」に判別する。SwiftUI にも SceneKit にも依存しない純粋ロジックで、シミュレーターなしで単体テストできる（LookPadGestureTests）。

stateDiagram-v2 [*] --> idle idle --> pending: 指が触れた（移動量は溜めるだけ） pending --> looking: 12pt（moveSlop）を超えて移動 pending --> breaking: 0.22秒（holdDelay）押し続け pending --> idle: それ以前に離した → タップ（置く・使う） looking --> idle: 指を離す（採掘へは移らない） breaking --> idle: 指を離す → 採掘終了
閾値値根拠
moveSlop12ptUILongPressGestureRecognizer の allowableMovement（10pt）をわずかに上回る。親指の転がりを拾わず、HIG の最小タップ領域44ptよりは十分小さい
holdDelay0.22秒意図的なスワイプは50〜80msで動き始めるため220msの静止は「押し続け」と断定できる。離散操作の遅延知覚（250ms）とシステムの touch and hold（0.5秒）のいずれとも衝突しない
  • 判定保留中の移動量は視点へ反映せず内部に溜める。タップではカメラが1ミリも動かないため、チェスト・かまど・ベッドを狙ってタップするのが確実に成立する
  • ドラッグに確定した瞬間に溜めた移動量をまとめて反映するので、先頭に死に領域ができず1:1の追従感を保つ
  • 採掘に確定した後も移動は視点へ反映し、狙いながら掘れる
  • いったん視点ドラッグに確定したジェスチャーは、途中で指を止めても採掘へは移らない（暴発防止）

ホットバー（5枠）

項目仕様
固定枠石 / 板材 / 石レンガ / ガラス / 松明 の5枠
追加枠固定枠外を選んでいる間だけ、区切り線の右に選択中ブロックの枠を出す（タップで所持品シートを開く）
所持品ボタン右端に常設（44pt）
枠数の根拠390pt 端末では可視幅370pt。1枠44pt＋間隔6＋所持品44 で5枠=294pt、追加枠（区切り5＋間隔12＋枠44＝61）込みで355pt に収まる。6枠にすると405ptで溢れ横スクロールが常態化する（旧8枠は追加枠なしでも444ptで既に溢れていた）
選定方針「スポイトで拾えないもの」を優先。地形素材は世界に転がっていてスポイトで拾えるため固定枠に置かない。🔴 M1（2026-10末）で実際に建てて決め直す

外部連携

連携先用途備考
作品カード（VG-FEAT-WORKCARD）設置・アンドゥの集計反映設置 +1／設置の取り消し -1
クリエイティブモード（VG-FEAT-CREATIVE）在庫チェックの回避・全ブロック選択ゴースト・スポイト・アンドゥとも在庫条件を外す
採掘演出（VG-FEAT-MINING）押し続け判定からの採掘開始・終了ひび割れ・破片パーティクルは採掘演出側
セッション統計（内部計測）スポイト回数・アンドゥ回数・所持品シートを開いた回数などワールドには保存せず、退出時に Logger へ1行出力するのみ（ユーザー向け機能ではない）

エラー処理

発生条件対応
アンドゥ対象のチャンクが未読み込み書き込み結果を検証し、失敗したら在庫を減らさずトーストで通知する
選択中ブロックが設置不可・在庫切れゴーストを出さない（押しても何も起きない状態を見た目で先に伝える）
VoiceOver で長押しができない「壊す」ボタンは1回目で採掘開始・2回目で停止するトグル方式に切り替わる

実装メモ

  • ゴースト・ハイライトは SCNNode を使い回し、毎フレームのマテリアル差し替えを避けるため直近の選択ブロックを記憶して差分時のみ更新する
  • アンドゥ履歴（LastEdit）は enum で placed(x,y,z,block,day) / broke(x,y,z,block,day) の2ケースのみ保持する
  • スポイト・アンドゥの要求は GameInput の requestXxx / consumeXxx パターンでレンダースレッドへ渡す
  • 視点パッドの状態機械 LookPadGestureMachine は Equatable な値型で、Effect（beginBreaking / endBreaking / use）と lookDelta を返すだけに徹する
