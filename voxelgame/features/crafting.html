クラフト

加工の種類と設備・時間制の加工ジョブ・道具・全レシピ（建材・染料）・かまど精錬・採掘速度テーブルの定義

機能ID: VG-FEAT-CRAFTING

概要

クラフトは設備ごとの加工として動く。レシピは自分の工程（手作業・組み立て・石材加工）を持ち、工程ごとに決まった設備（手元・作業台・石切台）でしか始められない。精錬はかまどで行う。どの加工も素材を開始時に消費し、決まった秒数のあとで完成品が所持品へ入る「加工ジョブ」で、画面を閉じても時間が来れば自動で完成し、ワールドの保存・復元をまたいで続く。

レシピは2系統。道具レシピはアイテム化せず「解放フラグ（Set<Tool> への追加）」を得る方式で、耐久値・重複所持の概念がない。アイテムレシピは素材からブロック・アイテムを作る（itemRecipes の末尾に染料のレシピ dyeRecipes を連結）。2026-09-16 の建築特化への転換で戦闘用（剣）と食料のレシピを削除し、以後は見た目を作り分けるための建材（形違い・素材違い・色違い）を増やしている。

クラフト画面の表示

  • 見出しは「（設備名）でクラフト」。上部の切り替えで「この設備」（既定）／「すべて」を選べ、「すべて」ではほかの設備のレシピも並ぶ
  • ほかの設備のレシピの行には、作成ボタンの代わりに「（設備名）で作る／置いた（設備名）を狙って［使う］」を出す（手作業の画面にも同じ趣旨の案内文を常設。2026-09-27、CF-002：作業台を置いても作り方が分からなかったため）
  • アイテムレシピの行には、工程名・「所要時間 X.X秒 / 完成数 N」・加工ロス（ある場合）・副産物（ある場合）・素材ごとの「所持数/必要数」（足りれば緑、足りなければ赤）を出す
  • 加工中は先頭にカード（「加工中：レシピ名」「道具作成中：レシピ名」）を出し、進捗バーと「完成まで X.X秒」を 0.1 秒ごとに更新する
  • ボタンは「加工開始」（道具は「作成開始」／解放済みは「作成済」）。別のジョブが動いている間は「加工中」で押せない

まとめて作る・ジャンル・使い道（2026-10-04〜、CF50）

本人（10-04）「200とか300とか要る場合に一個ずつクラフトするのは大変。×5ずつとか何個まで選択して」「クラフトできる順に、ジャンル別に並べて」「流木の板・係留柱・磨き石などは何に使うのか分かるか」→ 案A・並べ方・使い道。画面は CraftingSheet.swift、決まりは CraftingCatalog.swift。

項目仕様
作る数上部の切り替えで ×1・×5・×10・作れるだけ（CraftQuantity。最初から使える）。実際の回数は材料で作れる回数（いちばん足りない材料で決まる。craftableTimes）で頭打ち。ボタンは「×N 加工」。材料・完成数・副産物・時間がすべて回数倍の1件の加工になる（例: 板材 ×5＝木5 → 板材20・2.5秒）。今の加工と同じく実時間で進み、保存の形は変えていない。ジョブ名は「板材（5回分）」
かまど同じ切り替え（smeltQuantity）。鉱石と燃料の少ない方の回数まで（smeltableTimes）
ジャンル見出しで 素材・建材・家具・設備・乗り物・色・道具 に分ける（RecipeGenre。作った物で決まる）。各ジャンルの中で、この設備でいま作れる物を上へ（同じなら元の並び）
作れる物だけ切り替えボタンで、この設備でいま作れる物だけに絞る。無ければ「いまの材料で作れる物はありません」
使い道各行（かまどの行も）に1行（usageNote。例: 板材＝家の壁・床に。家具や道具の材料／係留柱＝桟橋の飾り）。道具の行には道具の効果。所持品の画面の上にも選んでいる物の使い道を出し、花・草・キノコを拾ったときの知らせにも添える（CF51）
完成の知らせ完成品の名前と数（「板材 ×20が完成しました」）

処理フロー（加工ジョブ）

sequenceDiagram participant U as User participant Sheet as CraftingSheet / FurnaceSheet participant Input as GameInput participant Loop as レンダーループ participant Store as WorldRecord U->>Sheet: 加工開始（設備・素材・空きを確認） Sheet->>Input: startCrafting / startSmelting / startToolCrafting Input->>Input: 素材（と燃料）を即時消費し CraftingJob を作る loop 0.5秒ごと（ポーズ中も止めない） Loop->>Input: consumeDueJobFlag（完成予定時刻を過ぎたか） end Loop->>Input: メインスレッドで flushDueJobs Input->>Input: 完成品（と副産物）を所持品へ追加／道具を解放 Input-->>U: 効果音とトースト「（名前） ×N が完成しました」 Input->>Store: 保存時に未完成のジョブを JSON で保存 Store-->>Input: ワールドを開くとき復元し、期限が過ぎていれば完成させる

加工ジョブのルール

  • 同時に動かせるジョブは1つだけ。アイテム加工と精錬は同じ枠（craftingJob）を使い、道具作成（toolCraftingJob）とも排他
  • 素材・燃料は開始時に消費し、完成品は完成時に追加する（途中の取り消しは無い）
  • 進み方は開始時刻からの実時間。クラフト画面を閉じても、メニューなどでポーズ中でも止まらず、時間が来れば自動で完成する（レンダーループが 0.5 秒ごとに期限だけを確かめ、完成処理はメインスレッドで1回だけ行う）
  • 未完成のジョブはワールドの保存時に WorldRecord.craftingJobData / toolCraftingJobData へ保存し、次に開いたときに復元する。ワールドを離れていた時間も経過に数えるため、期限を過ぎていれば開いた時点で完成する
  • 副産物のキーが無い古い保存データも読める（副産物なしとして扱う）
  • 精錬中はワールドのかまどが火の入った見た目になる。ガラスの精錬が完成すると目標ガイドの「ガラスを作る」を達成にする

加工ロスと副産物

  • 加工ロスは「切り出しで回収できずに失われる素材の量」を画面に示す表示用の値。素材の消費量・完成数はレシピの入力・出力のとおりで、ロス分を別に差し引く計算は無い
  • 副産物は完成時に完成品と一緒に所持品へ入る。現在は石材の階段3種が出す石片 ×1 のみ。石片は置けないアイテムで、現時点で石片を使うレシピは無い
  • 階段は「入力3 → 出力1・加工ロス1」、ハーフは「入力3 → 出力6」。素材を変えても形の値段は揃える（石・石レンガ・砂岩・氷で同じ）
  • 氷の階段は加工ロス1だが副産物なし（氷の削りくずは溶けるため）。木・針葉樹の形違いは作業台で作り、削りくずの出口が無いので副産物を付けない

ビジネスルール

  • 道具は「アイテム」ではなく Set<Tool> への解放フラグ。耐久値・重複所持は無い。解放済みの道具は「作成済」になり作れない
  • 素手と木のツルハシはクラフト不要で最初から解放済み（unlockedTools の初期値）
  • レシピは決まった設備でしか始められない（「すべて」表示で見えても、別の設備のレシピは開始できない）
  • クリエイティブモードでもクラフト・精錬には素材が要る（所持数チェックは回避されない）。クリエイティブでは所持品シートから全ブロックを選べるため、建てるだけならクラフトは不要
  • 採掘ティアは「不可」ではなく時間短縮のみのため、低ティアの道具でも根気があれば高階層の鉱石まで掘れる（ダイヤ鉱石は石のツルハシで12秒/個）
  • 新しい資材は必ず建物に残る物（建材・飾り）に行き着かせる。金ブロック（金インゴットの出口）・砂岩（砂の出口）・ランタン（鉄インゴットの使い道）はこの方針で足した

実装メモ

  • レシピはコード内の配列（toolRecipes / itemRecipes＋dyeRecipes / smeltingRecipes、GameDomain.swift）で、データファイル分離はしていない。染料の色・植物の対応は Dyes.swift
  • 工程（CraftingProcess）が設備と所要時間を持つ。レシピ側は工程だけを指定する
  • ジョブは CraftingJob（アイテム・精錬）と ToolCraftingJob（道具）。完成予定時刻をロック付きのミラーに写し、レンダースレッドは @Published を読まずに期限だけを判定する
  • クラフト画面を開いている間は画面側の 0.1 秒タイマーでも完成を拾う（レンダーループと二重になっても、先に取った側だけが完成させる）
  • 破壊されたブロックのアイテムドロップは breakBlock 内で加算する（松明・チェスト・農作物・植物は個別のドロップロジック）
