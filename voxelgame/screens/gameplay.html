ゲームプレイ画面

SceneKit を使った 3D ボクセルワールドのメインプレイ画面。操作・HUD・各種モーダルを含む

画面ID: VG-GAME-01

目的・役割

ゲームの中核となる画面。SceneKit のレンダリングレイヤー（SCNView）の上に SwiftUI の HUD・操作ボタンレイヤーをオーバーレイする構成をとる。2026-09-16 の建築特化への転換で、この画面の主題は「生き延びる」から「素材を集めて建てる」へ変わった。既定視点は一人称で、メニューから三人称へ切り替えられる（三人称のときだけカメラ距離を選べる）。サバイバルとクリエイティブの2モードは引き続き切り替え可能だが、サバイバル側から体力・空腹・死亡は無くなっている。

画面の向きは横向き専用（2026-09-19〜）。Info.plist の対応向きは iPhone・iPad とも LandscapeLeft / LandscapeRight のみ。左手で移動・右手で視点という操作系では縦だと親指の可動域が上下に潰れ、建築では「広い範囲を見ながら置く」ため視野の広さでも横が有利、という判断による。

UI 構成

画面の配置（横向き）

上段（メニュー類・右上の情報）は上端に、下段（ジョイスティック・素材バー・操作ボタン群）は下端にそれぞれ独立して固定する。縦に積む構成だと、横向き（縦 約390pt）で操作ボタンが画面外へ押し出されて移動できなくなったため（09-19 実測）。

🔴 右上の列（天気・方角と高さ・お手本の進み具合・目印・パフォーマンス表示）は上段の行に重ねる（行の高さを変えない・列はどれも表示だけなので触っても下へ通す。2026-10-07、CF-035）。行の中に置いていたので、列が伸びると上段の行ごと高くなり、ツールバーと下段の操作ボタン・素材バーが画面の外へ押し出された（本人が実機で発見。build 38 でパフォーマンス表示を7行にしたとき）。列が長いと右下の操作ボタン（スポイト・ジャンプ）の下に文字が隠れることはある（ボタンは押せる。ISSUES CF-036）。

位置要素説明
左下ジョイスティック直径110pt（×ボタンの大きさ）。前へいっぱいまで倒し続けると走る（2026-10-03〜、CF37。下記）。走っている間は外の輪とつまみが黄色
下中央素材バー（ホットバー）ジョイスティックと操作ボタン群の間。幅は最大390pt。空きが220pt未満の狭い横画面では一時的に折りたたむ（選択中の素材の色＋上向きの山形だけの小ボタン。押すとそのセッション中だけ開き、回転・再表示でまた畳む。設定値は書き換えない）。ふだんの画面でも手動で畳める（既定は開。状態は UserDefaults に保存）
右下操作ボタン群204pt 四方（×ボタンの大きさ）の枠に、壊す・ジャンプ・置く・戻すを相対配置する（下表）
右下・ジャンプの上スポイト操作ボタン群の側に揃え、下端から 10＋160×ボタンの大きさ pt の高さに置く（小 約151／標準 170／大 約189）。ジャンプはボタンの大きさに合わせて下端から拡大されるため、高さも同じ倍率で上げる（固定の170だと「大」でジャンプに11pt食い込んだ）
左下・右下の全体左右の幅下段は最大幅760pt・左右余白16pt・下余白10pt で中央寄せ（広い画面で端へ離れない）
  • 左利き配置（設定）: ジョイスティックと操作ボタン群・スポイトの左右を入れ替え、視点パッドも画面左58%へ移る。操作ヒントの「右側」「左下」の文言も入れ替わる
  • 操作ボタンの大きさ（設定）: 小 ×0.88／標準 ×1.0／大 ×1.12。ジョイスティックと操作ボタン群を下端の角を基準に拡大縮小する
  • 走る（2026-10-03〜、CF37・本人「ダッシュで移動できるモードが欲しい。マップが大きい」）: スティックを前へ（前の成分が7割以上）いっぱいまで（97%以上）倒したまま 0.35 秒で走る。速さ 1.5 倍（歩き 6→9 m/s・船 8→12 m/s・クリエイティブの飛行も）。8割を切るか横・後ろへ倒すと歩きに戻る（建てている最中にうっかり走らないように）。泳いでいる間・リフトでは走らない。走っている間は画角を 6 度広げ、スティックを黄色にする（VoiceOver は「走っています」）。ボタンは増やさない（CF-023）
  • 縦の寸法クラスが regular のとき（＝iPad）の配置: 素材バー → スポイトの行 → ジョイスティックと操作ボタン群、の順に下から縦に積む。ボタンの大きさは画面幅に収まる倍率 max(0.8, (幅−8)÷314) を上限に縮める。iPhone の横向き（縦が compact）では上記の横配置を使う

操作ボタン群（右下）

「壊す」を基準点（右下の角）に、ほかのボタンを相対配置する。値は標準の大きさのとき（右端・下端からの距離）。

ボタン大きさ・位置説明
壊す80pt・右下の角赤い円。長押し中、照準ブロックをツール採掘時間に応じて破壊する（採掘演出）。編集モードでは「持ち上げる」（手の絵）になる。VoiceOver 有効時は開始/停止のトグル方式
ジャンプ60pt・右10／下92（壊すの真上）絵は上向きの山形2つ（SF Symbols chevron.up.2）＋「ジャンプ」の文字（本人 10-02 選択）。地は暗い半透明（黒42%、押下中55%）と白い縁（白い半透明の地だと雪山・空・砂浜の明るい景色に溶けて絵が見えなかった）。水中では押し続けるあいだ浮き上がり続ける。クリエイティブでは「上下」になり、同じ円の上下ドラッグで上昇・降下する（死点6pt。上向き・下向き・上下の矢印で向きを示す）。VoiceOver には「上昇」「降下」の個別アクションを用意する
降りるジャンプと同じ位置船に乗っているあいだだけ、ジャンプの代わりに出る（歩く人の絵＋「降りる」・青緑の円。識別子 disembarkButton）
置く60pt・右116／下100（壊すの左上）照準面に選択中ブロックを設置する。狙っている物と状態で表示と動作が替わる（次節）。識別子は常に placeButton
戻す（アンドゥ）52pt・右116／下4（壊すの左）直前の設置/破壊を1手だけ取り消す。戻せる操作がある間だけ青で活性、無いときは灰色で無効

ボタンの間隔: 置くとジャンプは28pt 以上離し、スポイトはジャンプに重ねない（本人 build 23「置くボタンとジャンプのボタンが近い」への対応。置くを左へ寄せ、スポイトをジャンプの上へ移した）。UI テストで縦・横、右利き・左利き、標準・大の組み合わせについて、操作ボタン群・素材バー・スポイトが交差しないことと合わせて確かめている。

置くボタンの表示の切り替え

上の行ほど優先する。押したときの分岐（GameSceneView）と表示は同じ定義（BlockUse）を共有し、「使う」と出ているのに押すと置いてしまう、といった食い違いを起こさない。

状況絵・文字色読み上げ
編集モード・何も持ち上げていない回る矢印＋「置き換え」（長押し）紫置き換え
編集モード・持ち上げ中しまう矢印＋「ここに置く」紫持ち上げた○○をここに置く
ハサミを持ち、まだ刈っていない羊を狙っているハサミ＋「毛を刈る」オレンジ羊の毛を刈る
作業台・石切台・かまど・チェスト・ベッドを狙っているタップする手＋「使う」オレンジ作業台を使う 等
船を狙っている帆船＋「乗る」オレンジ船に乗る
リフトの乗り場を狙っている上下の矢印＋「乗る」オレンジリフトに乗る
上記以外立方体（文字なし）緑ブロックを置く

羊は「ハサミを持っていて未刈り」のときだけ置く操作を毛刈りにする（以前は羊を狙えば常に横取りし、羊の向こうの地面へ置けなかった）。編集モード中は毛刈りと羊の案内を出さない。

十字の下の案内

照準の 36pt 下に、黒い半透明のカプセルで出す（編集モードは紫）。上の行ほど優先。

状況文言
編集モード「編集中 ─ 長押しで［置き換え］［持ち上げる］」／持ち上げ中は「持ち上げ中：○○ ─ 置く場所を狙って［ここに置く］」
羊を狙っている刈れる:「羊 ─ ［毛を刈る］で羊毛3つ」／ハサミなし:「羊 ─ ハサミを持つと毛を刈れます」／刈った後:「羊 ─ 毛は次の夜明けに生えます」
使える物・乗り物を狙っている「〈名前〉 ─ ［使う／乗る］で〈効果〉」。効果は 作業台・石切台＝開いてクラフト／チェスト＝開いて出し入れ／かまど＝開いて精錬／ベッド＝スポーン地点にする（夜は眠る）／船＝海を渡る／リフト＝崖の上と下を行き来する

手と持ち物（一人称・三人称）

  • 一人称（2026-09-26〜、CF10）: 画面右下に腕と持ち物を出し、置く・壊すで振る／歩くと揺れる／持ち替えると下から持ち上げる。普段は選択中の建材を持ち、壊している間と置けない（在庫切れ・置けない物）ときだけ道具に持ち替える（道具と建材を別々に選ぶ作りのため）。右下は操作ボタン群が占めるので、手先は画面上の正規化座標 (0.36, −0.30)・奥行き0.42m に置き、腕がボタンの裏から伸びて見える配置にする。地形より手前に描く（壁際で手が埋もれない）。カメラの子ノードとして組む
  • 三人称（build 24〜）: 一人称の手と同じ物（選んだブロック・ツルハシ・ハサミ）を自キャラの右手に持たせ、壊している間は振り続け、置く・使う・持ち上げるときは1回振る（本人 build 23「三人称で壊す動作がない」への対応）。三人称では従来の2Dの採掘アイコン（照準横で振る）も出す
  • 写真を撮っている間は一人称の手を隠す

使用するデータモデル

所持品・解放ツール・進行フラグ・設置の集計（PlacementTally）とUI状態（GameInput）の詳細はデータモデルを参照。船に乗っているかは WorldRecord.isRidingBoat に保存し、乗ったままアプリが落ちても次に入ったときに船を所持品へ戻す。操作設定（左利き配置 voxel_leftHandedControls・操作ボタンサイズ voxel_controlSize・目標の展開 voxel_objectiveExpanded など）は UserDefaults に保存する。

実装メモ

  • SCNView を UIViewRepresentable でラップし、SwiftUI の ZStack 上に HUD をオーバーレイする構成をとる
  • ゲームループは Coordinator（SCNSceneRendererDelegate）の renderer(_:updateAtTime:) で毎フレーム実行する
  • 入力は GameInput（NSLock保護のrequestXxx/consumeXxxパターン）でUIスレッドとレンダースレッドを仲介する
  • シート表示中は GameInput の isPaused ミラー経由でレンダーループを早期 return させる
  • 横向きか否かは verticalSizeClass == .compact で判定し、landscapeBottomHUD／portraitBottomHUD を切り替える。下段は Spacer で押し下げる（frame(maxHeight:) や overlay(alignment: .bottom) では実機で下端に寄らなかった）
  • 置くボタンのラベルは照準で変わるため、UI テストは固定の識別子 placeButton で探す。ジャンプ・乗る・使うの絵がその OS で描ける SF Symbols であることを単体テストで確かめる
  • 届く距離は Reach.survival = 4.5／Reach.creative = 5（GameRules）、1日の長さは DayCycle.standardLengthMinutes = 20・daylightFraction = 0.65
  • ホットバーのブロックアイコンは TextureAtlas（起動時コード生成の1枚絵）から切り出して表示する
  • ホットバーの横スクロール位置は保存し、追加枠から別ブロックを選び直したときに古い追加枠へ戻らないよう補正する
  • セッション統計（所持品シートを開いた回数・スポイト/アンドゥ回数・夜間の設置数など）はワールドに保存せず、退出時に Logger へ1行出力するだけの内部計測である（ユーザー向けの表示は無い）
