データモデル

SwiftData @Model の構造とゲーム内データ設計

概要

永続化は100% SwiftData（デフォルトの SQLite ストア）で完結しており、独自のバイナリファイル I/O は行わない。モデルは WorldRecord・ChunkRecord・ChestRecord の3つで、いずれも worldID（UUID）でワールドごとに分離する。ゲームロジック自体は SceneKit のレンダースレッド上で動くランタイムクラス（Player・Mob 等）が保持し、変化があったときだけ SwiftData モデルへ書き戻す。

2026-09-16 の建築特化への転換で、体力・満腹度に関する列が消え、代わりに「これまでに置いた量」を記録する列が加わった。保存したい対象が「生き延びた状態」から「積み上げた投資」へ移ったためである。

WorldRecord（SwiftData @Model）

ワールドのメタ情報・進行状態をまとめて保持する唯一のモデル。プレイヤーの位置・時刻・天候は保存対象外で、毎回スポーン地点から再開する。

Block（UInt8 enum）

rawValue が UInt8 として blocksData / inventoryData に直接書き込まれる。最大 rawValue は 37（金ブロック）。建築特化への転換で削除した食料アイテムの rawValue（16〜18・31・33）は欠番のまま残す（他ブロックの値をずらさないため。旧セーブに残っていてもデコード時に air へ倒れる）。アトラス列数は将来の拡張余地を見て40列確保している。

ブロックは isSolid / blocksMovement / rendersAsBlock / isRaycastTarget / occludesNeighborFaces に加え、isPlaceable（プレイヤーが設置できるか）を持つ。isPlaceable は設置プレビュー（ゴースト）・設置処理・スポイト・クリエイティブの所持品一覧が共通で参照する単一のゲートで、水・溶岩・成熟小麦は除外される。

PlacementTally（設置の集計・ランタイム値型）

struct PlacementTally: Equatable {
    private(set) var total: Int                 // 累計設置数（キャッシュ）
    private(set) var byBlock: [Block: Int]      // 種別ごとの設置累計（権威）
    private(set) var byDay: [Int: Int]          // epochDay → 設置数
    private(set) var firstPlacedAt: Date?       // 初回設置日時

    mutating func apply(block: Block, delta: Int, day: Int, now: Date)
}
  • 更新経路は apply(block:delta:day:now:) の1本だけ。これにより sum(byBlock) == total と sum(byDay) == total の不変条件を守る
  • delta は +1（設置）または -1（1手アンドゥでの取り消し）のみ。通常の破壊では減らない
  • day は 2026-01-01 00:00:00 UTC 起点の経過日数（epochDay）。タイムゾーン変更・サマータイムで日付境界が動かないよう UTC 固定
  • アンドゥでは「取り消した日」ではなく「元の操作をした日」の枠から引く
  • SceneKit 非依存の純粋値型で単体テスト可能（PlacementTallyTests）。詳細は作品カード

SessionStats（セッション統計・保存対象外）

ワールド入場〜退出の1セッション分の操作ログ。ワールドデータには保存せず、退出時に Logger へ1行ダンプするためだけに存在する揮発性の値。所持品シートを開いた回数・スポイト回数・アンドゥ回数・種別ごとの選択回数・夜間の秒数と設置数を持つ。狙いは「ホットバーが足りない」「操作が誤爆しやすい」を体感でなく数字で判定できるようにすること（2026-09-19 の実機検証用）。

Player（ランタイムクラス・SwiftData対象外）

final class Player {
    var position: SIMD3<Float> = SIMD3(8, 62, 8)  // 足元基準
    var yaw: Float = 0
    var pitch: Float = -0.3
    var velocityY: Float = 0
    var grounded: Bool = false
    var fly: Bool = false             // クリエイティブのフライ
    private(set) var isInWater: Bool = false
    var isThirdPerson: Bool           // 毎フレーム GameInput から同期（既定は一人称）

    // 定数
    let moveSpeed: Float = 6          // m/s
    let gravity: Float = -24          // m/s²
    let jumpSpeed: Float = 9          // m/s
    let eyeHeight: Float = 1.62
    let halfW: Float = 0.3            // AABB半幅
    let halfH: Float = 0.9            // AABB半高さ（全高1.8）
}
  • hp は廃止（体力・ダメージ・死亡の仕組みごと削除）
  • 視点モードの権威は GameInput.isThirdPerson（既定 false ＝ 一人称）で、レンダーループが毎フレーム Player へ同期する
  • クリエイティブの昇降は 6 m/s で、Y を 0〜63（Chunk.sizeY-1）にクランプする。落下死が無くなったため、下限が無いと世界の下へ抜けて詰むのを防ぐ目的がある
  • 位置・時刻・天候・動物は WorldRecord に保存されない（毎回スポーン地点・正午・晴れから再開）

GameInput（UI状態、ObservableObject）

SwiftUI 側から参照される @Published の集合。レンダースレッドとの橋渡しは「値が変化したときだけ DispatchQueue.main.async でミラー反映する」規約で統一されている。主なカテゴリ:

UI表示制御showCrafting, showSettings, showChest, showInventory, showFurnace, showMenu, showWorkCard, toastMessage, goalBannerTitle / goalBannerHint

インベントリ / チェストのシリアライズ形式

個数を UInt8（最大255）でクランプしていた旧形式から、上限を撤廃した新形式に移行済み。先頭バイトで新旧を判別する。

形式構造個数上限
旧形式[rawValue: UInt8, count: UInt8] の2バイトペアの並び255
新形式先頭に 0xFF、以降 [rawValue: UInt8, countLo: UInt8, countHi: UInt8] の3バイト組（UInt16 リトルエンディアン）65535

0xFF は Block の最大 rawValue（37）と衝突しないため、先頭バイトだけで安全に新旧を判別できる。デコードは常に両形式に対応し、エンコードは常に新形式で書く。種別ごとの設置累計（placedByBlockData）も同じ形式を再利用する。

日別設置数（dailyPlacedData）の形式

項目内容
マジックバイト0xFE（インベントリの 0xFF と衝突しない）
レコード[epochDayLo, epochDayHi, countLo, countHi] の4バイト固定長（いずれも UInt16 リトルエンディアン）
epochDay2026-01-01 起点の経過日数（UInt16 で約179年分をカバー）
保持期間直近730日（約2年）分まで。730日で 730×4＝2920 バイト
クランプcount は 65535 まで。0 件の日は書き出さない

スキーマ版管理・マイグレーション方針

現状は VoxelSchemaV1（1.0.0）のみで移行ステージは無く、軽量マイグレーションに任せている。軽量マイグレーションが効くのは「デフォルト値つきプロパティの追加・削除」など情報を失わない変更に限られるため、各 @Model の全プロパティにデフォルト値を置く。ボクセルゲームではワールドが積み上げた成果そのもので、1回の全損が致命傷になる。
  • 列の追加だけで済むならデフォルト値つきで足すだけでよい（V1 のまま）。実績: placedBlockCount・placedByBlockData・dailyPlacedData・firstPlacedAt は全てデフォルト値つきで追加した
  • 型変更・リネーム・データ加工が必要なら、先に現行の型定義をコピーして V1 内へ固定し、新定義を V2 として作る（V1 が現行型を参照したまま書き換えると移行の起点が失われる）
  • 新しい Block を追加する場合は既存 rawValue を変更せず末尾に追加する。削除した Block の rawValue は欠番として再利用しない
  • 永続ストアの生成に失敗した場合はメモリ内ストアで起動する（失敗は Logger に残す）。ここで停止するとアプリが二度と開けず、ワールドの吸い出し手段まで失われるため「起動はする／このセッションの保存はされない」側に倒している
