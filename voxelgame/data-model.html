データモデル

SwiftData @Model の構造とゲーム内データ設計

概要

永続化は100% SwiftData（デフォルトの SQLite ストア）で完結しており、独自のファイル I/O は行わない。モデルは WorldRecord・ChunkRecord・ChestRecord の3つ（VoxelSchemaV1.models）で、いずれも worldID（UUID）でワールドごとに分離する。ゲームロジック自体は SceneKit のレンダースレッド上で動くランタイムクラス（Player・Chunk 等）が保持し、変化があったときだけ SwiftData モデルへ書き戻す。

2026-09-16 の建築特化への転換で、体力・満腹度に関する列が消え、代わりに「これまでに置いた量」を記録する列が加わった。その後、ステージ（舞台とお題）・世界の種類（群島／島／無限）・船・群島の改訂番号の列を、すべて既定値つきの追加として足している（スキーマは V1 のまま。後述）。

ステージの写真3枚だけは @Attribute(.externalStorage) で、SwiftData が行の外の別ファイルに置く。WorldRecord は定期保存で何度も書き直すため、行の中に写真があると保存のたびに写真ごと書き直すことになるからである。

WorldRecord（SwiftData @Model）

ワールドのメタ情報・進行状態をまとめて保持するモデル。プレイヤーの位置・向き・時刻・天候・船の位置は保存対象外で、毎回スポーン地点から再開する。

09-17 以降に足した列はすべて既定値つきの追加（craftingJobData・toolCraftingJobData・stageID・stageCompletedAt・写真3枚・worldKindRaw・isRidingBoat・archipelagoRevision）。SwiftData の軽量マイグレーションは「既存レコードに新しい列の値を埋められること」が条件で、既定値の無い非 Optional が1つでもあると次に列を足した時点で移行が失敗し、ストアごと開けなくなる（＝全ワールド消失）。そのためスキーマは VoxelSchemaV1 のまま、移行ステージを持たない。
廃止された列: hp（体力）・hunger（満腹度）・hasCraftedTorch・hasCraftedGoldenApple。いずれも 2026-09-16 の建築特化への転換で、対応する仕組みごと削除した。

群島の改訂の入れ直し（ArchipelagoMigration）

保存済みのチャンクは生成し直さないため、build 23 で作った群島には build 24 で直した物（凍った滝・崖のリフト）が出ない。群島のワールドに入るとき archipelagoRevision < ArchipelagoMigration.currentRevision なら、保存済みチャンクを読み込んで次の2つを一度だけ書き込み、改訂番号を上げて保存する。

入れ直す物決まり（Rule）内容
凍った滝replacesWater水のマスだけ置き換える
崖のリフト（乗り場2つを含む）replacesTerrain地形のまま（空気・雪・石・土・草・木・葉・鉱石・水・溶岩・氷・草花）のマスだけ置き換える。プレイヤーが置いた建材は上書きしない

チャンクの保存形式（Chunk.serialized / Chunk.from(data:)）

部分バイト数内容
ブロック配列16×64×16 = 163841マス1バイトの Block.rawValue。インデックス = y × 256 + z × 16 + x
向きの追記（任意）4マジック "VXOR"（0x56 0x58 0x4F 0x52）
1版（現行 1）
2項目数（UInt16 リトルエンディアン）
3 × 項目数[位置 UInt16 LE（上のインデックス）, 保存値 UInt8] の並び。位置の昇順
  • 保存値は下位3ビット（マスク 0x07）。下位2ビットが90度単位の向き（0＝北・1＝西・2＝南・3＝東）、3ビット目（0x04）はベッドでは「2マスのベッド」の印（BedPlacement.twoCellFlag。印の無い bed は2マス化以前に置いた1マスのベッド）、ランタンでは「吊るしている」印（LanternPlacement.hangingFlag）
  • 書き出すのは「向きを保存するブロック」（Chunk.storesOrientation ＝ 階段・isRotatable・bed・bedHead・lantern）で、かつ保存値が0以外のマスだけ。該当が無ければ追記自体を付けず、16384バイトちょうどになる
  • 旧形式も読める: 追記の無いデータは向き0として読む。マジック・版が合わなければ追記を無視する。16384バイトに満たない部分は空気、知らない rawValue（欠番を含む）は空気として読む
  • 版1の形式は石の階段のころから変えていない。旧版は自分の知らない項目を読み飛ばすので、向きを保存するブロックを足しても旧版で読めなくなることはない

チャンクはブロック編集のたびに dirtyChunks へ記録され、(a) チャンクアンロード時、(b) アプリのバックグラウンド移行・「保存して出る」、(c) 定期保存、の経路で WorldStore.saveChunk（専用シリアルキュー上の ModelContext。既存レコードがあれば上書き）へ書き込まれる。バックグラウンド移行時は whenAllPendingWritesComplete で投入済みの書き込みが終わるまで実行猶予を取る。

所持品の2つの写し（GameInput）

所持品はスレッドの違う2か所で持つ。2026-10-02 に同期のしかたを直した（CF-025）。

写し実体誰が書くか
描画スレッド用の写しinvMirror（NSLock で保護）描画スレッド（掘る・置く・船を戻す等）は adjustInventory でここを増減し、itemCount でここを読む
画面用の一覧inventory（@Published、メインスレッド）SwiftUI（加工・チェスト操作・クリエイティブ等）が直接書き換える
  • 描画スレッドの増減は写しを正とし、増減のたびにメインスレッドへ「写しを一覧へ映す」（publishInventoryMirror）を投げる。映している最中は一覧の didSet を通さない（写しへ戻し書きしない）
  • 画面側の書き換えは、品ごとの差分（新 − 旧）だけを写しへ足す（applyInventoryEdit）
  • 🔴 以前は画面側の書き換えで写しを一覧ごと上書きしていた。描画スレッドの増減は一覧へ遅れて届くので、別の品の書き込みで上書きされると、まだ届いていない増減とその間の増減が失われていた
  • 保存はメインスレッドで一覧（input.inventory）を encodeInventory して inventoryData に書く
  • 初期在庫は 松明2・チェスト1・小麦3（新規ワールドのみ）

Block（UInt8 enum）

rawValue が UInt8 として blocksData・inventoryData・slotsData・placedByBlockData に直接書き込まれる。現行の最大 rawValue は 97（リフトの乗り場）。欠番 16〜18・31・33 は建築特化への転換で廃止した食べ物（鶏肉・豚肉・牛肉・パン・金のリンゴ）で、値をずらさないため再利用しない。旧セーブに残っていても読み込み時に空気として読む（所持品では読み飛ばす）。テクスチャアトラスの列は Block.atlasColumn で rawValue から切り離してあり、形違い・色違いは素材の列を借りるので列を消費しない。

PlacementTally（設置の集計・ランタイム値型）

struct PlacementTally: Equatable {
    private(set) var total: Int                 // 累計設置数（キャッシュ）
    private(set) var byBlock: [Block: Int]      // 種別ごとの設置累計（権威）
    private(set) var byDay: [Int: Int]          // epochDay → 設置数
    private(set) var firstPlacedAt: Date?       // 初回設置日時

    mutating func apply(block: Block, delta: Int, day: Int, now: Date)
}
  • 更新経路は apply(block:delta:day:now:) の1本だけ。これにより sum(byBlock) == total と sum(byDay) == total の不変条件を守る
  • delta は +1（設置）または -1（1手アンドゥでの取り消し）のみ。通常の破壊では減らない
  • day は 2026-01-01 00:00:00 UTC 起点の経過日数（epochDay）。タイムゾーン変更・サマータイムで日付境界が動かないよう UTC 固定
  • アンドゥでは「取り消した日」ではなく「元の操作をした日」の枠から引く
  • SceneKit 非依存の純粋値型で単体テスト可能（PlacementTallyTests）。詳細は作品カード

SessionStats（セッション統計・保存対象外）

ワールド入場〜退出の1セッション分の操作ログ。ワールドデータには保存せず、退出時に Logger へ1行ダンプするためだけに存在する揮発性の値。所持品シートを開いた回数・スポイト回数・アンドゥ回数・種別ごとの選択回数・夜間の秒数と設置数を持つ。狙いは「ホットバーが足りない」「操作が誤爆しやすい」を体感でなく数字で判定できるようにすること（2026-09-19 の実機検証用）。

Player（ランタイムクラス・SwiftData対象外）

所持品・チェストの直列化

所持品（inventoryData）・チェスト（slotsData）・種別ごとの設置累計（placedByBlockData）は同じ形式。個数を UInt8（最大255）でクランプしていた旧形式から、上限を撤廃した新形式に移行済み。先頭バイトで新旧を判別する。

形式構造個数上限
旧形式（読み取り専用）[rawValue: UInt8, count: UInt8] の2バイトペアの並び255
新形式先頭に 0xFF、以降 [rawValue: UInt8, countLo: UInt8, countHi: UInt8] の3バイト組（UInt16 リトルエンディアン）65535

0xFF は Block の最大 rawValue（97）と衝突しないため、先頭バイトだけで安全に新旧を判別できる。デコードは常に両形式に対応し、エンコードは常に新形式で書く。個数0の品は書き出さず、知らない rawValue（欠番）は読み飛ばす。エンコード・デコードは GameDomain.swift と WorldStore の2か所に同じ実装がある（揃えて変えること）。

加工ジョブ（craftingJobData / toolCraftingJobData）の形式

JSONEncoder 既定の JSON。ジョブが無ければ空 Data。読み込み時、期限を過ぎたジョブはその場で完成させる。

型項目
CraftingJobrecipeName（String）・output（Block の rawValue）・outputCount・station（"手作業" / "作業台" / "石切台" / "かまど"）・startedAt・duration・byproduct（{block, count}。任意。無い旧データも読める）
ToolCraftingJobrecipeName・unlocks（Tool の rawValue）・station・startedAt・duration

日別設置数（dailyPlacedData）の形式

項目内容
マジックバイト0xFE（インベントリの 0xFF と衝突しない）
レコード[epochDayLo, epochDayHi, countLo, countHi] の4バイト固定長（いずれも UInt16 リトルエンディアン）
epochDay2026-01-01 起点の経過日数（UInt16 で約179年分をカバー）
保持期間直近730日（約2年）分まで。730日で 730×4＝2920 バイト
クランプcount は 65535 まで。0 件の日は書き出さない

スキーマ版管理・マイグレーション方針

現状は VoxelSchemaV1（1.0.0）のみで移行ステージは無く、軽量マイグレーションに任せている。軽量マイグレーションが効くのは「デフォルト値つきプロパティの追加・削除」など情報を失わない変更に限られるため、各 @Model の全プロパティにデフォルト値を置く。ボクセルゲームではワールドが積み上げた成果そのもので、1回の全損が致命傷になる。
  • 列の追加だけで済むならデフォルト値つきで足すだけでよい（V1 のまま）。実績: placedBlockCount・placedByBlockData・dailyPlacedData・firstPlacedAt・craftingJobData・toolCraftingJobData・stageID・stageCompletedAt・写真3枚・worldKindRaw・isRidingBoat・archipelagoRevision は全てデフォルト値つきで追加した
  • 型変更・リネーム・データ加工が必要なら、先に現行の型定義をコピーして V1 内へ固定し、新定義を V2 として作る（V1 が現行型を参照したまま書き換えると移行の起点が失われる）
  • 新しい Block を追加する場合は既存 rawValue を変更せず末尾に追加する。削除した Block の rawValue は欠番として再利用しない
  • チャンクの中身に後から物を足す必要がある場合（群島の改訂など）は、スキーマではなく WorldRecord の改訂番号で一度だけ書き込む（ArchipelagoMigration）
  • 永続ストアの生成に失敗した場合はメモリ内ストアで起動する（失敗は Logger に残す）。ここで停止するとアプリが二度と開けず、ワールドの吸い出し手段まで失われるため「起動はする／このセッションの保存はされない」側に倒している
