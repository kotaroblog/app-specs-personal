広告機能（AppLovin MAX）

Banner + Rewarded 広告

v2.0機能ID: WD-FEAT-AD

2026-08-04 広告基盤を AdMob から AppLovin MAX へ全面移行

AdMob アカウントが「無効なトラフィック」により恒久的に無効化され、再審査請求も却下された。 新規アカウント作成も含めて AdSense / AdMob は今後一切利用できないため、AppLovin MAX へ移行した。

AppLovin の publisher アカウントは審査中のため、SDK Key と広告ユニットIDは未設定。 現時点で広告は一切配信されていない（後述の安全機構により、未設定の間は自動的に無効）。

概要

本アプリは Banner と Rewarded の2種類の広告を活用。プレミアムユーザーは非表示。 Rewarded 視聴で1回限りプレミアム機能を一時解放できる導線あり。

広告を出してよい環境の判定（再発防止の中枢）

AdMob 停止の原因は、開発中・TestFlight 検証中に本番の広告IDでインプレッションが発生していたことだった。 ネットワークを変えても同じ規約（自己クリック・他者への視聴依頼の禁止）が適用されるため、同じ事故を構造的に防ぐ。

AdEnvironment.isAdDeliveryAvailable = 「SDK Key が設定済み」かつ「App Store 配信版である」

環境広告のロード・表示
DEBUG ビルド / シミュレーター / TestFlight一切リクエストしない
App Store 配信版（SDK Key 設定済み）配信する
  • 判定は App Store レシートの種別（sandboxReceipt かどうか）で行う。ビルド構成の設定ミスでは破れない
  • AppLovin にはテスト広告IDの概念がないため、開発中は広告を出さない方式を採用した
  • SDK 初期化自体も配信可能な環境でのみ実行する

広告配信が無効な期間の挙動

  • バナーは枠ごと非表示（空白を残さない）
  • リワードはロードしない。その結果 isAdReady が false のままとなり、 「広告を見て1回無料」の導線はシェア画面側で自動的に非表示になる（UI 側の追加分岐は不要）

広告の種類と配置

種類配置無料/プレミアム
BannerContentView 下部無料のみ
Rewarded能動視聴（プレミアム機能一時解放）常時利用可

広告ユニットID の構成

AppLovin ダッシュボードで発行した値をコード側に設定する。 未設定（空）の間は広告を一切ロードしない（差し替え漏れで意図しない挙動にならないための安全弁）。

※ 実際のIDは本仕様書には記載しない（コード上で管理する）。

RewardedAdManager API

@Observable @MainActor
final class RewardedAdManager {
    var isAdReady: Bool
    private var adContinuation: CheckedContinuation<Bool, Never>?

    func loadAd()
    func showAd() async -> Bool  // true=報酬獲得
}

continuation leak 対策

Google AdMob の callback ベースAPI を CheckedContinuation でブリッジ。 重複表示・メモリリーク防止のため、callback 実行後に必ず resume + nil 化。

ビジネスルール

  • Banner はプレミアムユーザーには表示しない
  • Rewarded はプレミアム判定不要（常時表示可）
  • Rewarded 視聴で tempPremiumExpiresAt を保存し時限解放
  • 本番リリース時は本番 Ad Unit ID へ切替必須
